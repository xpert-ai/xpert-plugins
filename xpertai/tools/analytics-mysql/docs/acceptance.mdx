## Scope and ownership

This iteration adds `mysql.sql` and `doris.sql` through the analytics-mysql plugin.
The existing MySQL database plugin provides both native adapters. Provider IDs and
registrations are independent even though the two implementations share one package.
They can be separated later without changing saved Bindings.

The platform continues to own DataSource credentials, current-viewer authorization,
Dataset/Binding normalization, Artifacts and iframe isolation. The provider owns native
discovery/query interpretation. The dashboard plugin owns authoring, controls, HTML and
save-receipt checks. No new platform engine switch, renderer or credential store was added.

## Test environment

Local xpert-pro source runtime, data-xpert with normal browser SSO, and isolated MySQL 8.4
and Apache Doris 4.1.3 containers. The normal platform data-source API registered two
sources using SELECT-only principals. No browser token extraction or database auth bypass
was used. Test accounts, source IDs, private receipts and credentials are outside this package.

The fixture in `tests/fixture.sql` has nine orders. The requested metric is paid amount
minus refunds, for paid orders in July–September 2026, grouped by month and region, in CNY.
Cancelled and out-of-quarter rows must be excluded:

| --- | ---: | ---: | ---: | ---: |
| east | 1,000 | 1,500 | 1,000 | 3,500 |
| west | 800 | 900 | 500 | 2,200 |
| All | 1,800 | 2,400 | 1,500 | 5,700 |

## Agent and browser procedure

Use a single business request naming the source, Q3 net sales, region filter, manual refresh
and a ten-second refresh interval. MySQL requests a platinum-blue page with a top KPI,
left trend and right details; Doris requests a black-gold page with vertically arranged
trend/details. The Agent must discover the metric from table comments, preview real rows,
verify a non-default filter, write HTML with SandboxFile, and obtain a draft save receipt.

Check the persisted Artifact independently of the chat reply in both xpert-pro and the
data-xpert SSO Workbench:

1. All/east/west must produce 5,700 / 3,500 / 2,200 in ECharts series, KPI and detail totals.
2. With west selected, insert one temporary paid Q3 order worth 100 through the separate
   fixture administrator. Wait for the page timer: the total must become 2,300 while both
   the filter selection and an injected DOM marker remain unchanged (no iframe reload).
3. Delete that exact temporary row in a `finally` cleanup path. Manual refresh returns
   2,200. Reload/reopen the saved draft and confirm the declared default gives 5,700.
4. Deny an undeclared Binding, direct network fetch and parent DOM access inside the iframe.
   Deny an extra raw-SQL payload submitted to the server's query-binding action.

This verifies polling refresh; it does not claim database change-stream push delivery.

## Failures found and repaired

1. Creating a native MySQL connection before SQL validation allowed early rejection/close
   to race the asynchronous handshake. The driver now creates its connection lazily and
   handles connection errors through the pending query.
2. The dashboard schema rejected optional null defaults when a parameter's scalar allowlist
   contained only real regions. It now follows platform parameter semantics: `required`
   controls nullability; non-null values still obey the allowlist.
3. SandboxFile can refuse a write with a domain error while the tool transport reports
   success. Recording every attempt as an unsaved edit caused an erroneous final failure
   after a different file was successfully saved. The dashboard now compares bytes around
   the operation; no-op writes do not create pending changes, and partial/concurrent writes
   remain guarded. No tool-name or error-text inference was added.
4. Generated ECharts code replaced series with data-only objects and duplicated the SDK's
   select handling. The HTML skill now explicitly requires complete replacement series
   and `live.refresh` for timers/buttons, preserving the SDK's typed filter values.
5. A fresh model run combined parts of two listed source UUIDs and then repeatedly changed
   discovery arguments. Discovery now rejects a pair absent from its run-local authorized
   list with exact available choices and instructions to refresh/copy the IDs. It neither
   guesses a replacement source nor bypasses the host's access revalidation. That failed
   run was stopped rather than accepted as a different-source dashboard.

## Verification limits

These are local source-runtime results. Published SDK/contracts versions must expose the
Analytics APIs before an npm-only release; the existing peer range alone is insufficient.
Only MySQL and Doris's internal catalog are covered. MariaDB, RDS MySQL, StarRocks and Doris
external catalogs are not advertised. The Doris driver does not expose a read-only
transaction, so database SELECT-only privileges remain mandatory.

Browser query success alone does not prove every chart or every sentence in an Agent reply
is correct. An early Doris reply misstated the total as 6,700 despite correct query rows and
the saved page showing 5,700. The skill now requires an executed calculation or verified
aggregate for numeric prose; initial failed runs are not counted as passing acceptance.
