## Compatibility

Development dependencies pin published SDK/contracts 3.25.0, which export AnalyticsProvider,
AnalyticsQueryProvider, ActorTokenRuntimeFactoryCapability and the shared Dataset/Binding
contracts. The host must provide the corresponding runtime capabilities.

Data-xpert must expose `POST /agent-workbench/analytics/discover` and
`POST /agent-workbench/analytics/query` under the configured API base. Discovery returns
adapter-owned `definition` metadata. Query returns canonical rows, execution/audit references,
fetch time and `fromCache: false` after the normal authorization and read-only Action pipeline.

## Local verification

From the xpertai workspace:

```sh
corepack pnpm exec nx run @xpert-ai/plugin-analytics-data-xpert:test
corepack pnpm exec nx run @xpert-ai/plugin-analytics-data-xpert:typecheck
```

Tests start a disposable local HTTP fixture and use synthetic Actor Tokens. They verify:

- current actor, organization, trusted Assistant scope and token audience;
- Semantic Model/OData metadata, canonical targets, pagination and Action schemas;
- scalar filter mapping and rejection of unknown/prototype/duplicate paths;
- rows/series/entity projection, partial totals, audit receipts and fresh requests;
- unknown inputs, missing targets, cached responses and invalid configured URLs;
- refused redirects, bounded response streaming and cancellation.

Build and package before running `plugin-dev-harness`. Its lifecycle mocks verify package
loading and Nest injection, not a real identity provider or data-xpert authorization decision.
Validate `docs.json` navigation and run `mint validate` when updating documentation.

## Separate live acceptance

Install through the authenticated system-plugin workflow with tenant scope in the Default
tenant. Configure a DataSource pointing to the intended data-xpert API and its OIDC audience.
Use xpert-pro SSO, a published Assistant/resource binding and explicit viewer policy.

Verify an allowed viewer can discover and query, while a denied viewer cannot. Preview both
Semantic Model and OData (or another registered adapter) using their actual Action schemas.
Then verify one-sentence generation, filters, changed-source refresh, save/reopen and rejection
of undeclared HTML frontend queries. Local HTTP fixtures do not establish those outcomes.

## Errors

- `DATAX_PARAMETER_MAPPING_INVALID`: align parameter names with unique declared paths.
- `DATAX_PARAMETER_PATH_INVALID`: use an existing path relative to params with canonical indices.
- `DATAX_PARAMETER_PATH_NOT_SCALAR`: target a scalar value, not an object or array.
- `DATAX_URL_INVALID`: correct trusted source configuration.
- `DATAX_QUERY_HTTP_<status>`: investigate authorization or request validation in data-xpert;
  upstream error bodies and secrets are not forwarded.
- `DATAX_RESPONSE_TOO_LARGE`: reduce result size; response buffering is bounded.
