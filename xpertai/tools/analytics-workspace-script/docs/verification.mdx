## 依赖和发布边界

开发依赖固定使用已发布的 SDK/contracts 3.25.0，无需本地平台链接。
宿主需要提供对应的 Analytics、Artifacts、Workspace Files、Sandbox invocation 能力。
生产环境还需要发布兼容的 compute 镜像和不可变 digest Binding。

## 自动化检查

在 xpertai 工作区使用固定版本的 Corepack pnpm：

```sh
corepack pnpm exec nx run @xpert-ai/plugin-analytics-workspace-script:test
corepack pnpm exec nx run @xpert-ai/plugin-analytics-workspace-script:verify:dist
```

检查路径限制、Actor/Artifact ACL、输出契约、来源预检、CSV、精确数值和截断传播；
检查列表分页、版本引用、输入授权复验、每次刷新重新读取、任务取消/期限和输出校验。
执行证据必须在输出通过 Dataset 校验后创建。

`build-action.mjs` 从排序后的常规文件生成 SHA-256 树哈希，拒绝软链接和额外文件。
打包后从插件源码目录对解压的实际包再次验证：

```sh
node scripts/build-action.mjs --verify-package /absolute/path/to/extracted/package
```

同时运行仓库 `plugin-dev-harness`，验证包入口、Nest 注入和关闭流程。
该 harness 使用平台 capability mocks，不能替代实际容器执行。

## 提交审核与历史验收

本批提交审核在临时目录构建、测试和打包，不覆盖正在运行的 dist。
`acceptance.md` 保留此前真实模型、Docker 与 SSO 验收的结果和边界；
本批的本地自动化通过不表示已重跑其中的端到端场景。

重新进行真实验收时，使用对应文档中的固定夹具和部署流程，验证：

- Agent 从业务问题生成真实脚本，而非直接绕过脚本 Provider。
- 文件、PostgreSQL、本体输入按声明别名读取；筛选和刷新得到可独立核对的结果。
- 保存重开后仍引用明确版本，并重新验证输入权限。
- 网络/输入写入拒绝、取消和软链接输出拒绝由真实 Runtime Provider 保证。

变更过的夹具必须恢复；凭据、执行 ID 和截图等私有回执不进入发布包。
