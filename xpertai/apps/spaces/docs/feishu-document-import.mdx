## 本批范围

本批落地第二阶段的只读来源与文本副本导入。入口为协作空间“新建 → 从文档平台导入”。飞书新版文档（`docx`）可列出、按关键词搜索、粘贴链接预览，再导入当前项目文件夹。

这是**文本副本**：图片、附件、公式、表格结构、排版和评论不随副本保留。对话框在导入前显示实际文本及转换提示，用户确认后才保存。原文不会被修改。富文档转换、知识库目录浏览、远端引用、发布与读回、双向同步仍属后续阶段。

## 插件与平台职责

| 层 | 职责 |
| --- | --- |
| SDK | 可选 `ConnectorStrategyRuntime.documents` hook；显式 `text/plain` 快照、修订号、内容哈希和提示 |
| 平台 | `platform.connector.documents` 提供来源目录、搜索、读取；依据当前身份、已发布 Assistant、项目绑定和实时连接状态授权 |
| 飞书插件 | 在现有 `plugin-lark-cli` 增加独立文档适配模块；调用固定 OpenAPI 域名，保持授权凭据仅在服务端 |
| Spaces 插件 | 预览、目标文件夹、共享确认、请求幂等、项目 Markdown 文件及来源元数据 |
| Markdown 插件 | 继续负责 Tiptap/Yjs 编辑；不依赖飞书 SDK，不引入远端协同协议 |

平台目录从已授权的 Assistant 工作区与当前项目连接构建。浏览器传入 `bindingId` 不构成授权；平台先从实时目录中选择，再使用已有 scoped credential API 完成身份、项目、连接状态、刷新与审计检查。此交互 API 不扩大 Agent 执行中的 Connector grants。

当前连接模型只使用平台已有的 **shared** 连接。操作依据该连接授权账户的可见范围，不等于每位项目成员自己的飞书权限。管理员必须按预期团队范围配置连接；个人连接的独立授权和权限交集需要后续单独交付。未连接、不支持文档 hook 的来源不会被当作可读来源。

## 用户流程

1. 在当前文件夹选择“从文档平台导入”。
2. 选择可用来源。空查询列出云盘根目录；关键词搜索新版文档，当前接口最多取前 199 项。文件夹与知识库导航暂未接入，非根目录文档可用关键词或 `/docx/`、`/wiki/` 链接定位。知识库链接会解析到其指向的新版文档；表格、文件等其他节点类型仍不可导入。搜索和云盘根目录不保证列出个人文档库中的知识库节点，未找到时可粘贴链接。
3. 选择结果或粘贴新版文档链接，查看文本预览、原文版本和目标项目。
4. 确认将文本副本共享给项目成员。导入后的内容按项目权限长期保存，飞书撤权不会自动删除已经导入的副本。
5. 导入后在空间打开，进入同一 Workbench 中的 Markdown 编辑器。列表来源显示“外部文本副本”；更多菜单中的“查看导入来源”显示来源平台、文档 ID、版本、时间、转换提示与可用的原文链接。

空来源、加载中、失败重试和授权失效均有对应界面。搜索结果分页加载并按文档 ID 去重。控件字号和密度沿用宿主主题。

## 一致性与失败恢复

- 读取采用“元数据 → 原始文本 → 元数据”，两次修订号或标题不同则要求重新预览。
- 导入请求带预览修订号和 SHA-256，服务端重新读取；变化后拒绝导入旧预览。
- 文件名使用标题与请求 UUID；相同请求 ID 只创建同一份文件，重试不会产生重复副本。请求绑定操作者、来源、预览版本和目标。
- 使用空间锁与现有发现/移动流程串行；先保存导入意图，再进行文件发布。注册编辑器中断可重试；文件被其他主体修改时保留文件并报冲突。
- 完成的导入请求仅返回既有副本。后续远端变化不会覆盖已经协同编辑的本地内容。
- 内容保存在项目 `.md` 文件；`plugin_spaces_item.importOrigin` 保存来源元数据、哈希和幂等凭据，不保存正文、token 或签名下载地址。
- 导入先编码为字面 Markdown 文本，不将远端 HTML 或链接标记直接作为活动内容。单篇可读取文本上限为 100 KB。

飞书适配器仅接受 HTTPS 的飞书/Lark `/docx/`、`/wiki/` 地址或文档 token；输入 URL 只用于提取文档 ID，绝不直接抓取。请求使用固定 API origin，禁止重定向，有超时和响应大小限制。错误仅带固定错误标识、HTTP 状态与数字业务码，不转发 Axios headers、凭据或原始错误响应。

知识库链接通过飞书当前 `wiki/v2/spaces/node_by_token` 接口解析，使用 `wiki:node:retrieve` 权限。仅接受返回的 `obj_type=docx`，校验节点 ID，并在正文读取后复核映射；元数据保存真实文档 ID，来源链接保留去掉追踪参数的原始知识库 URL。

## 部署

1. 更新平台 plugin-sdk 与 server-ai，重启 API，使 `platform.connector.documents` 生效。
2. 构建并更新 Spaces 与 Lark CLI 插件。Lark CLI 在 monorepo 中声明 `workspace:^` 依赖，独立部署使用 `corepack pnpm pack` 生成 `.tgz`，再通过平台归档安装接口上传；直接复制源码目录给 npm 安装会报 `EUNSUPPORTEDPROTOCOL`。发布包会把 workspace 范围转换为已发布版本。
3. 在未启用开发 schema 同步的环境执行 `migrations/20261023-document-import-origin.sql`。
4. 为所需 Assistant 工作区或项目配置 shared 飞书连接，并在飞书应用与账户中授予读取/搜索文档所需权限。

新 API/SDK 应先于插件升级。仅更新插件会因宿主尚未导出新 capability 而装载失败。

## Remote View 组件规范

导入弹窗使用共享 shadcn/Radix 的 `Dialog`、`DialogHeader`、`DialogFooter`，来源选择使用 `Select`，共享确认使用 `Checkbox` 与关联的 `Label`。不使用原生 select/checkbox，也不覆盖组件的标题字号、内边距、遮罩、边框和按钮外观；这些视觉属性沿用共享组件和宿主 theme variables。插件只约束弹窗可用宽度、滚动区域和内容布局。

Spaces 与 Markdown 的远程资源只加载共享 shadcn 样式中的一次 Tailwind Preflight，插件样式仅补充 theme/utilities，避免第二次 reset 覆盖组件的默认边框规则。来源选择支持方向键、Enter 与 Escape，确认勾选支持空格键；从新建菜单打开的导入弹窗关闭后，焦点返回新建按钮。
