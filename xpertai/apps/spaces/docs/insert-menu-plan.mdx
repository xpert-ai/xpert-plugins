## 依据与边界

依据 2026-10-23 提供的四张截图分析可见菜单，不将截图中的文案视为已经验证的 ChatGPT 内部行为。尤其“助手说明”的权限、执行方式和自动更新语义，截图不足以确认。

Space 是项目上的协作能力；内容保存在项目文件工作区。Markdown 插件负责编辑，平台负责资源身份、访问校验、协作和版本，Assistant 负责生成与审阅。知识库是文档检索索引，不是正文存储。Markdown 编辑器不依赖 Spaces 服务类，也不新增左侧空间导航。

## 本期实施步骤

1. 将插入项和内容构造集中管理；顶部加号打开可滚动的分组菜单，沿用宿主字号、密度和主题。基础插入在当前顶层块之后，不覆盖已有选区；弹窗期间用稳定块 ID 重新定位，目标被协作者删除时明确失败。
2. 前后端共用 Tiptap schema。加入任务列表和受限 GFM 表格，验证任务状态、表格形状、节点属性和安全链接；不支持的 HTML、图片等仍拒绝导入，保留原文件。
3. schema 升级到 v2。平台只调用模型显式声明的升级方法；获得写权限并确认文件已物化、无外部冲突后，保留文件字节和块 ID，发布新 epoch，原子归档旧协作房间。旧客户端不能继续写入新版本；失败可恢复，不静默丢弃已接收更新。
4. 页面链接通过平台授权获取稳定宿主 URL。文档选择器限定当前项目可见资源；点击内部链接复用 `workbench.content.resolve` → `workbench.navigation.open`，不导航到外层宿主。外部链接仅允许 HTTP(S)、mailto 和文内锚点。
5. “交给 Assistant 撰写”只追加引用到已有输入框，不发送、不替换草稿。待编辑器保存成功才交接。不存在可用 Assistant 时明确报错。

## 验收标准

- 任务勾选、表格单元格、基础块和链接在保存、刷新、导出后保持语义；双客户端更新可合并。
- 开菜单和弹窗不会丢失插入位置；已有选中文本不被覆盖；目标删除、断线、只读时不误写。
- 表格增删行列可撤销，复杂结构拒绝保存，不能悄悄扁平化数据。
- v1 文档升级保留原文件字节、历史与块 ID；并发更新、旧 epoch、外部冲突受到保护。
- 本地真实浏览器验证菜单、编辑、落盘与刷新；单元测试、类型检查、构建、插件 metadata 和生命周期 harness 均通过。

## 后续实施顺序

1. 平台持久内容引用协议：项目文件、图片、页面、聊天使用显式类型和资源 ID，解析阶段校验权限；不把短期访问凭证写进 Markdown。
2. 图片与附件：上传复用 Project Files，建立资源引用节点和导出降级；处理取消上传、孤立附件、移动与回收站。
3. 数学公式已独立扩展并离线渲染；可视化后续设计沙箱和版本约束。
4. 子页面已基于独立文件和 Space 层级元数据实现；助手说明继续另行设计。

## 交付状态

2026-10-23：本期范围已完成。菜单、基础块、任务清单、表格、引用与 Assistant 交接由 Markdown 插件提供；平台增加无副作用的文档链接命令和显式模型升级接口。基础能力与视图继续分离，后续项不计入本期交付。

### 验证结果

- 51 项定向测试通过：Markdown 插件 15 项、平台文档服务 14 项、宿主链接与命令 22 项。覆盖序列化往返、并发任务/单元格更新、稳定插入锚点、非法结构拒绝、旧客户端隔离、升级恢复及链接命令副作用。
- Markdown 插件类型检查和构建、宿主 Angular 编译通过；Markdown 与 Spaces 插件 metadata 检查和生命周期 harness 通过。
- 本地真实后端完成 6 类联调：旧页面资源与原文件、双用户/双 Assistant 共用文档、并发及重试、评论与历史、越权拒绝、版本恢复后的旧 epoch 拒写。
- v1 文档升级实测：原文件哈希、块 ID 和历史保留，进入 schema v2 与新 epoch；旧客户端请求被拒绝。
- 浏览器实测任务勾选、表格增删行列与撤销、提示模板、页面选择与打开、自动保存和刷新。最终读取项目文件与文档服务校验哈希一致，保留原段落、任务状态、表格内容及页面链接。
- 页面链接在当前 ChatKit Workbench 内打开；Assistant 入口追加文档引用并聚焦输入框，没有发送消息。本次验证不包含真实模型生成质量验收。

### 已知限制

- 表格最多 200 行、30 列，仅一个表头；每格单行正文，可含行内格式，不支持合并单元格、嵌套表格或列宽保存。
- 页面选择器检索当前项目最近 100 份可见文档；全量分页、跨项目引用另行扩展。
- 只读用户不能执行 schema 升级；旧文档需要有写权限的成员先打开一次。新插件与平台升级接口必须一起部署。
- 提示和强调块是标准 Markdown 引用模板；生成交由 Assistant。公式与子页面已在 schema v3 中交付，见 [公式与子页面](math-subpages)；图片附件、文件/聊天引用与可视化仍按后续顺序推进。
