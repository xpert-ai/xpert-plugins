## 目标与边界

写作空间继续使用内置 Project type。项目文件是内容来源，Space 表保存组织与展示元数据，知识库是可重建索引。Markdown 编辑器提供文档编辑与协同，Assistant 负责通用审阅、AI 生成和定时维护。

本计划承接 ChatGPT Pages 调研。图片、附件、页面引用和快速插入优先落地；Task、Prompt、Agent instructions 等能力通过 Assistant 的已有职责实现，不在页面视图复制一套智能体运行系统。

## 第一批设计

### 引用协议与插件边界

平台契约 `ContentReferenceTarget` 显式区分 `image | file | page`，包括 `providerKey` 和 `resourceId`。持久化格式为：

```text
xpert-resource://v1/{kind}/{providerKey}/{resourceId}
```

Markdown 图片使用 `![说明](资源 URI)`，附件和页面使用 `[名称](资源 URI)`。名称和图片说明是插入时的快照，资源身份保持稳定。改名与移动后通过资源 ID 找到最新路径；被回收或撤权后显示不可用，恢复后可重新解析。引用不扩大授权。

平台提供 `platform.content.references` Runtime Capability 和可选 provider hooks。每次先校验包含引用的文档，再授权目标；Space provider 限制当前项目，复用 `SpaceFiles` 与 `SpaceDocuments`。编辑器只消费通用契约，不导入 Spaces 实现。将来其他来源可实现相同 hooks。

图片预览地址只存在浏览器内存，Yjs 和 Markdown 中不保存签名 URL 或凭证。File Gateway 在发放访问 grant 与读取文件时重新授权。预览只接受 PNG、JPEG、GIF、WebP 的文件头；SVG/HTML 不作为图片执行。附件强制下载。单文件上限 25 MB。

### 界面

- 顶部插入菜单增加图片、附件与分页页面引用。
- 图片/附件可上传或从当前项目选择；文件保存在当前文档所在物理文件夹。
- 上传成功但插入位置失效时保留文件，提示重新选择位置；文件可从空间再次引用。
- 资源选择器服务端搜索名称，25 条一页，提供加载更多、加载中、失败重试、无结果状态。
- 左上角文档切换使用同一分页检索，不再受最近 100 条限制。第一批只列出已注册到 Markdown 编辑器的页面。
- 顶层独立段落输入 `/` 搜索基本块、公式、图片、附件、页面引用；支持方向键、Enter、Escape 和中文输入。正文、代码与 URL 中的斜线不触发。
- 所有新增控件的尺寸继续继承宿主 root font size 与 density。

### 协同与兼容

Markdown 模型从 schema v3 升级到 v4，只新增资源图片节点。现有 Yjs 数据原样升级，保留文本块锚点，平台使用新 epoch 隔离旧客户端。已有普通网页和页面链接继续有效。图片是可选择/删除/移动的原子节点，说明与资源身份参与 CRDT；不提供图片裁剪和绘图。

对话框持有稳定块 ID，插入前再次定位。`/` 命令执行前重新校验段落内容，协作者改动后中止而不覆盖。外部图片 URL 和原始 HTML 继续拒绝编辑，保留原文件，避免静默丢失内容。

第一批 Markdown 下载保留 Xpert 资源 URI，依赖有权限的 Xpert 环境解析。离线资源打包导出、跨项目引用、聊天引用、图片生成与外部图片抓取不属于本批交付。

## 第二批：飞书

只读文本副本已进入交付，具体行为、边界和验收见 [飞书文档文本副本导入](./feishu-document-import)。

新增独立文档来源适配插件，复用现有连接器授权，不把飞书 SDK 或 token 放入 Spaces View。以只读接入与显式发布起步：

1. 列出/搜索用户可访问的文档和知识空间，保存来源、类型、远端 ID、URL、版本与同步时间。
2. “引用远端”保留远端作为内容来源；“导入副本”生成当前项目文件并记录出处。两种操作明确区分。
3. Assistant 可读取授权来源、归纳、形成项目内新稿。发布时显示目标和差异，先检查远端版本，写入后读回校验。
4. 知识库仅索引授权范围；远端撤权即停止检索与引用，不让服务账号授权扩大给所有项目成员。
5. 无法在本地无损表示的块保留原文链接/原格式，禁止以纯文本覆盖富文档。

远端协同继续由飞书负责；本地 Tiptap/Yjs 负责项目文件。第一版不承诺两个协同系统自动双向合并。飞书内嵌编辑器需要验证目标租户的 SDK、授权与嵌入条件，不能仅凭 iframe 推定可用。真实验收依赖测试租户应用配置和授权文档。

## 第三批：其他平台

WPS 优先定位 Office 编辑器插件：通过文件、权限和保存回调编辑项目里的 docx/xlsx/pptx，保留 Project 为内容来源。已有 WPS 知识检索连接器不等于 Office 编辑集成。

语雀可作为下一种文档来源接入，复用飞书阶段提炼的读取、导入、发布与版本接口。腾讯文档、钉钉文档先验证目标版本开放接口和租户授权，不提前承诺嵌入编辑或完整双向同步。

## 验收与证据

自动验证包括：身份 URI 与 Markdown 往返、非法图片与协议拒绝、v3 升级、图片与正文并发合并、`/` 输入保护、源文档与目标授权。

真实验证应包括：上传→插入→协同→项目文件落盘→重新读取；分页无重复；改名/移动/回收/恢复；项目外成员、只读成员与撤权后的 grant 失效；浏览器菜单、预览、下载和中文插入。

### 2026-10-23 第一批验收记录

- **插件自动测试**：Markdown 24 项、Spaces 24 项通过；两者 TypeScript 检查、构建、元数据校验和插件生命周期检查通过。生命周期检查仅证明装载与导出契约，不代替业务联调。
- **平台测试**：资源授权服务 2 项通过；文件访问网关 34 项通过。网关套件遇到仓库现有 `agent-execution.service.ts:12` 的 TypeScript TS2589 深层实例化诊断，第二次执行仅忽略该诊断；未修改仓库测试配置，也不声称完整平台类型检查通过。
- **真实 API**：`markdown-editor/tests/references.live.mjs` 的 7 个场景通过：上传、游标分页、预览与下载原始字节、双用户/双 Assistant 的资源与正文并发写入、移动/改名/回收/恢复、非法图片与只读/项目外访问拒绝、已发放 grant 在成员撤权后失效。项目文件实际内容与保存哈希一致。
- **真实 WebSocket**：`markdown-editor/tests/collaboration.live.mjs` 的 7 个场景通过：双用户与双 Assistant 同房间、同位置并发、光标、任务与公式、断线恢复、项目外账号拒绝、最终文件一致。
- **浏览器已确认**：ChatKit 内的媒体插入菜单、图片和附件选择插入、页面列表 25 条后加载剩余条目、中文检索、`/二级` 转标题、页面引用在当前 Workbench 打开、左上角切回文档。浏览器生成的标题、正文与引用再次从真实项目文件读回，SHA-256 一致。图片预览及附件下载请求返回成功。
- **尚未确认的系统交互**：浏览器自动化未捕获上传文件选择器和下载完成事件；系统处于锁定状态，无法通过原生文件选择/保存窗口补测。真实 multipart 上传、下载响应及原始字节已验证，但不将其记为浏览器选择文件到保存下载的完整闭环。后续需解锁系统后补测这两步。

真实撤权测试发现并修复了平台 Cookie 文件访问路径遗漏实时授权的问题：现在发放 grant 和读取文件都重新检查当前用户、项目与资源；删除用户、项目撤权、资源移动或回收后旧授权不能继续读取。兼容当前 SDK ALS 与旧 View 服务 CLS 请求上下文，并增加回归测试。


飞书、WPS、语雀等后续阶段尚未接入真实租户，本次没有对外部文档执行发布或同步。
