# HTML dashboard runtime

When the user requests a custom HTML/JavaScript page, free layout, or a specific visual style, use HTML mode. Before writing JavaScript, read [html-lifecycle.md](html-lifecycle.md) for the runnable lifecycle pattern. Keep its SDK initialization, subscriptions, typed filter fan-out and refresh behavior while changing the layout freely. Build the smallest complete page first; avoid extra aggregate Bindings when complete rows already support every panel:
1. Discover and preview the real data exactly as for a standard dashboard. Reuse the returned previewId and binding.id; the latter is the identifier passed to the page SDK. No hard-coded business rows or stale snapshots in HTML.
Prefer ONE complete Dataset per page when its rows already support the requested KPIs, trends, breakdown and details. Compute display aggregates from those complete rows in frontend JS. The standard chart renderer's separate-aggregate-binding requirement does not apply to custom HTML. If multiple datasets are truly necessary, every bindingId passed to query, subscribe or bindSelect MUST have its previewId included in dashboard_create_html. An upstream preview that is omitted from the saved previewIds is NOT available to the page and returns DOCUMENT_BINDING_DENIED. Never query an auxiliary totals binding without saving it, and propagate shared filters to every binding used in a dependent total.
2. Write a complete single-file HTML/CSS/JavaScript document using sandbox_write_file({file_path,content}); use sandbox_edit_file or sandbox_multi_edit_file for existing files. Use inline styles/scripts, SVG, Canvas and DOM for any layout. External scripts, fonts, images, imports, fetch, XMLHttpRequest, WebSocket, iframes, forms and eval are unavailable. No credentials, API URLs or backend queries in page code. Call dashboard_libraries to discover packaged dependencies. ECharts and Three.js are supported without CDN: pass libraries:["echarts"] or ["three"] (or both) to dashboard_create_html; the host injects window.echarts/window.THREE before your page code. Use the documented bundled versions. Never paste library source, load a CDN, use React/JSX or assume other globals. ECharts can use SVG or Canvas: initialize a sized container once, setOption on each Dataset update and resize with ResizeObserver. When filters can remove a series/category, replace the old series: use chart.setOption(option, {notMerge:true}) or replaceMerge:["series"]. The default merge keeps stale series even when the new Dataset has fewer regions. Verify all → one region → another region → all against both totals and plotted series. Three.js core supports WebGLRenderer with WebGL2; catch unavailable GPU contexts, show a meaningful fallback, dispose resources, and do not request external textures/models/addons/workers. Libraries only render data: all queries still use the page SDK. Dependency bytes, versions and SHA-256 are frozen with the Artifact; preflight runs the identical snapshot.
3. The injected SDK is window.xpertLiveArtifact. await live.ready() returns {bindingIds,defaults,theme,locale}. live.query(bindingId, {controlId:value}) returns the canonical Dataset {fields,rows,grain,completeness,freshness,provenance}. Field values use output.fields[].id; decimal/int64 stay exact strings. Use Number only for safe plotting; show exact monetary values. Treat received text as untrusted: use textContent, not innerHTML interpolation.
4. Register live.subscribe(bindingId, dataset => render(dataset)) BEFORE the first query. Call live.query on initial load and filter changes; subscription callbacks redraw both normal results and toolbar refresh results. live.refresh(bindingId) repeats the latest controls. Catch errors and show an error state. Null means all only when the declared parameter allows it. Every control ID/type/default/allowedValues must match the preview and the controls argument to save.
For a dimension selector controlling ONE binding (such as region), use the SDK helper before the initial query: live.bindSelect(document.getElementById('regionFilter'), {bindingId, controlId:'region', fieldId:'region', allLabel:'全部区域'}). Replace IDs with the exact preview IDs. It populates unique values from received Dataset rows, preserves options across filtering, and calls the declared query on change. Do not add another change listener or manually rewrite its options/values: its option values are JSON encoded to preserve types. Keep a visible associated label. Handle the bubbling xpert-query-error event to display an error. Its optional allValue defaults to null; pass the actual declared all sentinel if different. Do not use it for fixed query parameters such as forecast days, page size or granularity: these values are not Dataset rows.
Native data selects must declare `data-dashboard-control="<exact controlId>"`. A purely visual selector (for example chart style) uses `data-dashboard-presentation` instead; never mark a business filter as presentation-only. The plugin uses this explicit declaration to verify that changing a data select actually queries its Binding. Filtering cached rows without querying does not count. Existing pages continue to open; add the markers when saving an edited page. Custom controls still need scenario-specific interaction checks.
Saving preflight rejects `DOCUMENT_SHARED_CONTROL_NOT_PROPAGATED` when a native select changes a shared control on only some affected bindings, after a bounded wait for asynchronous panel handlers. Use different control IDs for intentionally independent panel filters.
For a shared dimension filter across MULTIPLE bindings, `bindSelect` only queries its one configured binding; it does NOT broadcast even if every Binding uses the same controlId. Instead, own a custom select and ONE change listener; do not also attach bindSelect. Populate distinct options from the full default datasets, preserve them during filtering, encode values with JSON.stringify and decode with JSON.parse. Keep one typed controls object, and query EVERY affected declared binding with those controls on initial load and every change. Do not silently keep a panel at its previous filter. Display per-panel failures and update the refresh timestamp only after results arrive. A minimal lifecycle is:
```js
const live = window.xpertLiveArtifact;
const ids = [csvBindingId, jsonBindingId, xlsxBindingId]; // Exact IDs from saved previews.
const select = document.getElementById('regionFilter');
const controls = {region: null}; // Must match all three declared parameters.
const known = new Set();
function option(value, label) {
  const key = JSON.stringify(value);
  if (known.has(key)) return;
  known.add(key);
  select.add(new Option(label, key));
}
option(null, '全部');
for (const id of ids) live.subscribe(id, dataset => {
  for (const row of dataset.rows) if (row.region !== null) option(row.region, String(row.region));
  select.value = JSON.stringify(controls.region);
  render(id, dataset);
});
async function queryAll() {
  await Promise.all(ids.map(id => live.query(id, {...controls}).catch(error => showError(id, error))));
}
select.addEventListener('change', () => {controls.region = JSON.parse(select.value); void queryAll();});
await live.ready();
await queryAll();
document.getElementById('refresh').addEventListener('click', () => {
  for (const id of ids) live.refresh(id).catch(error => showError(id, error));
});
```
Implement render/showError for every panel. Verify all → one region → another region → all against each binding's KPI, plotted series and details; inspecting only the first binding is insufficient.
For a fixed enum, render options from the Binding parameter's declared allowedValues, select the declared default, and call live.query with the correctly typed value on change. For example, a number parameter forecast_days with allowedValues:[3,7,14] needs options 3/7/14 and Number(select.value), not dates from a date field. Do not add an "All" option unless the parameter explicitly permits that value. This select owns its change listener; do not also attach bindSelect. Saving preflight exercises native selects and rejects values outside the Binding contract. It does not prove filtered business results; verify those separately. For other custom controls, review the full initial-query → options → selection → query → render path before save.
5. Include a visible title, metric units, accessible labeled filter controls, last refresh time, loading/error/empty/partial states, real detail rows and a responsive visual chart. Respect all grain dimensions; do not mislabel subsets as totals. Do not overwrite window.xpertLiveArtifact. Put code in an async function rather than top-level await in a classic script.
6. Call dashboard_create_html with {title,path,previewIds,controls,libraries}; it reads that exact Workspace file and saves those bytes together with the verified bindings as a persistent working draft. Do not call dashboard_create for an HTML request. Before saving, an isolated browser runs the exact HTML against the real default preview datasets. DASHBOARD_HTML_PREFLIGHT_FAILED means nothing was saved: fix the indicated runtime error or missing binding in the Workspace file, then retry dashboard_create_html in this same run. Do not claim completion after failed validation. Report only the successful draft receipt's Artifact ID and draftRevision. Formal publication requires human confirmation in Workbench; merely writing HTML is not completion.
Example data lifecycle (replace binding and field IDs with actual preview evidence): const live=window.xpertLiveArtifact; live.bindSelect(document.getElementById('regionFilter'),{bindingId,controlId:'region',fieldId:'region',allLabel:'全部区域'}); live.subscribe(bindingId,render); await live.ready(); await live.query(bindingId,{region:null}); The host refresh button calls the same subscription without reloading the document.

For both page refresh buttons and timers, call `live.refresh(bindingId)` after the initial query. Do not read `select.value` and resend it: bindSelect owns its typed controls, including JSON-encoded null. Render once through subscribe instead of rendering again in query.then.

`live.refresh()` without a Binding ID is invalid. Refresh several panels with `Promise.all(bindingIds.map(id => live.refresh(id)))`, handling errors per panel. Preflight clicks a bounded set of native buttons and also dispatches toolbar refresh; runtime errors block saving. It does not infer button intent or prove that every custom interaction updates the correct business result.

For ECharts `notMerge`, supply the complete chart option, including axes and series. For `replaceMerge: ["series"]`, supply the complete current series list. Include stable id, name, type and data on each series; do not rely on data-only objects inheriting their type. `notMerge` rebuilds the series, while `replaceMerge` preserves matching IDs and creates new series for unmatched IDs. A successful data query does not prove a visible chart: verify populated series, KPI and detail rows against the Dataset.

For panels that share a metric and filters, derive KPI, trend and detail from the same returned Dataset. Do not let a second unfiltered total subscription overwrite the same KPI on refresh. A deliberately global comparison must use its own clearly labeled element. Populate enabled data selects with usable choices; use the documented bindSelect helper or create options from verified values. Empty data selects must be disabled until choices are available.
