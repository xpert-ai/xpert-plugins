# BPC

作为 BPC 任务入口，复用模型专用子技能完成工作。Live Dashboard 插件同时提供看板制作技能和两个 BPC 分析子技能。固定的语义模型定义属于子技能；数据连接、模型实例、权限、组织成员和实际金额来自当前环境。

## 父子分工

| 层次 | 负责内容 |
| --- | --- |
| 本父技能 | 理解任务、确认模型、选择并加载子技能、协调验证与交付 |
| 模型子技能 | 固定字段及业务含义、维度角色、成员规则、查询模板、指标公式和适用范围 |
| 运行时绑定 | 当前授权来源、模型实例、Cube、底层技术字段/成员唯一名和当前可用数据 |

同一个模型合同可复用于不同组织。字段相同且业务含义、粒度、符号、版本和期间规则一致时，共用同一个子技能；数据不同不需要复制技能。名称相同但口径不同的模型，必须先确认差异。

## 执行流程

1. **确定任务和范围。** 区分解释/分析、查询、修改现有看板和新建看板。只执行用户授权的动作；复用当前已选模型和看板，收集缺少的业务条件。
2. **定位模型实例。** 通过当前授权工具核实用户选定的模型及版本。使用平台实际返回的 resource、source、target 等身份，不在技能中固定公司、服务器、租户或模型实例 ID。
3. **选择子技能。** 阅读 [模型路由](references/model-routing.md)。先确认用户要做单月预算执行还是年度财务规划，再核对选定模型或已授权绑定是否支持该口径。同一模型实例可以支持两种分析。若用户只说“预算”且上下文无法区分，先问清所需分析。
4. **加载并交接上下文。** 在当前技能目录中查找子技能名称，使用实际返回路径读取其完整 `SKILL.md`（Xpert 中为 `read_skill_file`），再按需读取引用。交接任务、授权范围、选定模型实例/版本、筛选条件、已有看板标识及待确认项。技能加载不等于启动子 Agent。
5. **执行模型规则。** 按子技能核实语义合同和运行时映射，构造有界查询、核对结果并计算指标。合同不兼容时说明具体差异，不静默换模型或自行猜映射。
6. **统一验证和交付。** 使用 [通用质量要求](references/quality-gates.md)。修改看板时使用当前 Live Dashboard 技能和工具合同，校验通过后保存草稿；明确保存回执、数据范围及未验证项。发布遵循用户授权和平台人工确认流程。

## 加载条件

父子技能是指令层的组合关系。插件默认看板助理模板显式声明 `live-dashboard`、`bpc`、`bpc-cost-expense` 和 `bpc-financial-planning`。已有或自定义数字专家需启用需要的技能；插件升级不会自动修改已有专家的配置，安装父技能也不会自动继承子技能。子技能未提供时，说明缺少哪个技能；只有当前环境已经允许技能发现/安装且在用户授权范围内时，才使用对应能力补齐。

仓库目录中这些技能并列，安装后不能假设仍是相邻目录。按技能目录提供的绝对路径加载，不硬编码本机或服务器路径。用户直接调用已知子技能时，可按其自包含流程执行，无需反复回到父技能。

完整关系与扩展流程见 [工作流程](references/workflow.md)。从 Live Dashboard 进入 BPC 后，只读取所需规则并继续当前流程；子技能交回看板制作步骤时，不重复执行已经完成的模型识别。

## 输出

说明所用模型和子技能、业务条件、数据/查询完整性、结果及限制。看板交付附草稿版本和入口。无法加载、查询失败、未保存和未验收各按实际状态说明，不能用一个“成功”概括所有阶段。
