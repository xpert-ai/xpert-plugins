# 模型路由与扩展

## 当前路由

| 用户指定并已确认的模型合同 | 子技能名称 | 状态 |
| --- | --- | --- |
| 成本/费用计划模型；与子技能定义的 CATEGORY、PLANYEAR、TIME 等字段及业务规则兼容 | `bpc-cost-expense` | 已提供；当前查询模板覆盖生产成本六大类、单月预算与实际 |

`bpc-cost-expense-v1` 是子技能文件内用于映射/校验的合同标识，不是平台模型实例 ID，也不是自动新增的服务端字段。只有读取并确认模型规则后，才能为本次绑定选择该标识。

其他预算、收入、投资模型尚无已交付子技能。不能因用户说“预算”就认定必须使用另一个模型：成本/费用模型本身也有预算与实际。先尊重用户指定的模型；只有模型合同不同，才需要另一个子技能。

## 选择规则

1. 优先使用用户明确指定的模型及技能。核对其当前授权实例，并加载对应子技能验证字段和业务规则。
2. 已有明确的模型实例到子技能配置时，在当前作用域核实该绑定；不将一个组织的实例 ID 写进公共路由表。
3. 仅有模糊的“做预算”等请求时，查看当前选定模型与已有显式绑定。仍有多个合理选择时，向用户说明候选业务模型并询问选择。
4. 未识别的模型不能仅因包含 ACCOUNT/TIME/CATEGORY 等字段就套用成本规则。可继续读取该模型元数据并说明缺少哪些语义，但不能声称已有可用子技能。
5. 选定后从宿主的技能目录读取 `bpc-cost-expense` 等实际技能路径。缺少时按父技能的加载条件处理，不猜工具或路径。

## 增加一个模型子技能

在 Live Dashboard 插件的 `skills/` 下新增平级目录，如未来的 `bpc-budget`。它应包含：

- `SKILL.md`：触发条件、模型范围、必要输入、工作步骤和交付。
- `agents/xpertai.yaml`：Xpert 展示信息及确实需要的工具依赖。
- 模型合同：字段、业务角色、版本/期间规则、粒度、公式及明确的不支持范围。
- 环境映射说明：从当前授权模型解析实例和物理标识，不能带客户名称、连接密钥、固定环境 ID 或真实业务金额。
- 必要的查询模板/脚本，以及合同不匹配、缺数据、错误和跨环境隔离的验证。

再在上面的路由表增加对应模型合同、子技能名称与实际支持范围，并在插件 `src/lib/templates.ts` 的 author template 技能依赖中声明该组件。验证打包产物能发现该技能、模板目标 Agent 能加载该技能。已有或自定义专家由其管理员按需启用，不自动重写。保持父技能流程不变；不要让父技能不断吸收各模型的科目和计算细节。与成本模型语义一致、仅数据源不同的实例继续用原子技能，不新增“某公司成本”技能。

## 目录与安装

```text
xpertai/apps/live-dashboard/skills/
  live-dashboard/     # 看板制作、绑定校验与草稿保存
  bpc/                # BPC 通用入口与模型路由
  bpc-cost-expense/   # 成本/费用模型专用规则
```

使用平级可发现的技能包表达逻辑父子关系。插件 manifest 的 `skills: "./skills"` 发现这些组件，package 的 `files` 包含整个 skills 目录。把子技能嵌在父技能目录内不能替代独立技能发现和模板依赖声明。运行时使用宿主技能目录返回的路径。
