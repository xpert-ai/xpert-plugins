# 模型路由与扩展

## 当前路由

| 用户需要的分析 | 需验证的模型合同 | 子技能 |
| --- | --- | --- |
| 单月生产成本预算执行、差额与执行率 | ACCOUNT 的 PARENTH2 / LEVEL01 生产成本六类。预算和实际分开取数，同月比较 | `bpc-cost-expense` |
| 一个编制年度、一个版本对指定规划年度的销售、费用与投资预算及月度分布 | ACCOUNT 的 PARENTH1 / LEVEL02 三个预算科目组。规划年度合计与基础月份可分别查询、逐组对账 | `bpc-financial-planning` |

同一模型实例可以同时满足两行合同。以用户已选模型和明确的分析用途决定应验证哪一行。例如“明年费用和投资各预算多少”走年度财务规划，“本月生产成本预算比实际多多少”走单月执行。单说“做预算”且上下文无法确定时，先询问分析用途。

从宿主的技能目录读取所选子技能的实际路径，再验证层级、成员和度量。能读到同名字段、模型名称相同或样本金额相近均不足以识别模型。合同不兼容时说明差异，子技能未启用时说明所需配置。保留已授权模型和业务范围，不自行改用其他模型。

## 增加一个模型子技能

在 Live Dashboard 插件的 `skills/` 下新增平级目录，用于新的模型合同或分析任务。它应包含：

- `SKILL.md`：触发条件、模型范围、必要输入、工作步骤和交付。
- `agents/xpertai.yaml`：Xpert 展示信息及确实需要的工具依赖。
- 模型合同：字段、业务角色、版本/期间规则、粒度、公式及明确的不支持范围。
- 环境映射说明：从当前授权模型解析实例和物理标识，不能带客户名称、连接密钥、固定环境 ID 或真实业务金额。
- 必要的查询模板/脚本，以及合同不匹配、缺数据、错误和跨环境隔离的验证。

再在上面的路由表增加对应模型合同、子技能名称与实际支持范围，并在插件 `src/lib/templates.ts` 的 author template 技能依赖中声明该组件。验证打包产物能发现该技能、模板目标 Agent 能加载该技能。已有或自定义专家由其管理员按需启用，不自动重写。保持父技能流程不变；不要让父技能不断吸收各模型的科目和计算细节。与成本模型语义一致、仅数据源不同的实例继续用原子技能，不新增“某公司成本”技能。

## 目录与安装

```text
xpertai/apps/live-dashboard/skills/
  live-dashboard/     # 看板制作、绑定校验与草稿保存
  bpc/                # BPC 通用入口与模型路由
  bpc-cost-expense/        # 生产成本单月预算与实际
  bpc-financial-planning/  # 年度销售、费用和投资预算
```

使用平级可发现的技能包表达逻辑父子关系。插件 manifest 的 `skills: "./skills"` 发现这些组件，package 的 `files` 包含整个 skills 目录。把子技能嵌在父技能目录内不能替代独立技能发现和模板依赖声明。运行时使用宿主技能目录返回的路径。
