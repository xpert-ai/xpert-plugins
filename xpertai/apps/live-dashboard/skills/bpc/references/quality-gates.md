# BPC 通用质量与交付要求

## 查询与数据

- 先明确模型、版本、期间、组织、科目及币种范围。模型字段的业务含义由子技能定义，不把所有 BPC 模型都当成同一种期间或版本规则。
- 比较使用同一业务范围和查询批次；保留两侧各自需要的版本或计划年度规则。不同预算版本分别展示，不能混加成一个预算。
- 元数据、成员列表和结果查询保持有界。复用已核实的合同，只补查新条件或漂移部分，避免反复全模型探索。
- 按稳定唯一标识关联数据，验证粒度；不能只按显示标题连接，不把父级汇总和子级再次累计。
- 保留金额原始十进制值，使用可用的精确金额能力复算，最后再换算显示单位和舍入。
- 区分成功空结果、空值、零、查询失败和结果截断。字段缺失/映射冲突不是“无数据”。不生成伪造的零行完整性信息。
- 结果完整性未知、截断、重复粒度或预期成员缺失时，不宣称全部范围完整。比较双方同时缺相同成员也不能通过覆盖校验。
- 当前查询成功与完整、业务数据完整、财务关账、业务人工验收是不同事实，分别说明。

## 看板

遵循当前环境 Live Dashboard 技能。更新已有看板先打开当前编辑副本，保留 artifact/binding/dataset 身份及并发版本控制；文件写入不能代替保存工具成功回执。

筛选切换即让当前比较失效。两侧结果记录筛选快照/批次，忽略晚到的旧请求；一侧失败时不能以该侧旧值计算新期间的差额/比率。若展示历史成功值，显式标记其原条件并排除在当前比较之外。

所有相关 KPI、图表和明细使用同一条件。确需独立参照图时清楚显示其范围。旧绑定省略不一定等于删除；确认已废弃后同步清理绑定和消费者，不隐藏其后台失败。

使用本轮真实预览建立字段合同和保存证据。筛选验证必须检查实际筛选维度或执行参数；不能用科目字段证明月份/组织筛选正确。预览上限或合同错误出现时，收束探索，不伪造 previewId、不删除校验绕过保存。

## 最少验收场景

| 场景 | 预期 |
| --- | --- |
| 默认范围与具体筛选/重置 | 请求、KPI、图表、明细同步 |
| 版本或期间切换 | 两侧各自规则正确且范围可对齐 |
| 单侧失败、乱序完成、恢复 | 不混用新旧结果；最新成功批次才恢复计算 |
| 真空结果、字段错误、截断 | 分别表达真实状态，不伪装零值或完整结果 |
| 双方同时缺成员、重复成员 | 覆盖或粒度检查失败 |
| 单位、零分母、负金额 | 按子技能的财务含义处理，不掩盖异常 |

执行适用的工具验证或隔离测试；浏览器操作遵守用户授权。报告未执行的场景，不用默认预览成功替代全流程验收。

保存后回读 artifactId、status=draft、draftRevision 和草稿入口。执行结束、文件修改卡片、打开旧看板卡片或旧正式版标签都不能证明已保存新草稿。
