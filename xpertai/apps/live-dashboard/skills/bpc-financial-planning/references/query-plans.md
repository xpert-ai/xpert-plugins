# 取数口径与查询配方

先从当前 Provider 发现 source、模型版本、resource、target、Cube、SignData 度量与返回字段。连接或成员名称因环境改变时，重新建立映射。以下业务编码和逻辑层级用于验证合同，传给工具的唯一名取自该环境实际元数据。

| 维度 | 年度和月度查询共同条件 |
| --- | --- |
| CATEGORY | 单一已确认的预算版本，比较多个版本时分列或分次查 |
| PLANYEAR | 单一编制年度，与报表规划年度分别选定 |
| TIME | 一个明确的规划年度合计成员，模型的年度层级为 PARENTH1 / LEVEL01。单独识别普通月、季度、年合计、YTD 与特殊录入成员（如 .INP） |
| RPTCURRENCY | 单一报告币种。单位换算依据源度量单位，换显示单位不换币种 |
| ENTITY | 指定组织或经确认的全部组织。合并口径、父组织或叶子集合择一，不重复汇总 |
| ACCOUNT | PARENTH1 / LEVEL02，同层三个互斥组 AC01 销售预算科目、AC08 费用科目合计、AC05 投资项目科目合计 |
| OBJECT / AUDITTRAIL 等 | 核实默认值是否包含重叠对象、不同数据来源或重复版本。需要约束时在相关查询中使用相同切片，保存证据 |

用 SignData 的原始十进制值。先核实销售预算组内叶子科目是否同为金额、是否混有数量／单价或非收入项，再确认收入符号。其他生产、采购、成本、财务或“其他”科目不计入这三个组。组间分类或层级不兼容时，暂停受影响指标并说明差异。

## 绑定配方

[合成年度查询参数](annual-params.example.json)仅展示 `data-xpert.ontology / mdx.query_cube_slice` 的原生 params 形状。示例中的唯一名、编制年和规划年都要替换成当前授权模型的精确成员。构造完整 Binding 时从当前发现或已有 Binding 获取 source/provider、action、target、output 和 parameterPaths。先验证后使用，不把原生 params 直接当成 Dashboard Binding。

| 用途 | 行粒度与范围 | 结果检查 |
| --- | --- | --- |
| 年度 KPI | ACCOUNT 分类行，TIME 筛选所选年度合计 | 预期每组一行，重复、缺行和空金额分别诊断。按成员唯一名取值 |
| 月度趋势 | 从年度查询拷贝全部切片，行轴增加 TIME **基础月层级 LEVEL01**，保留 ACCOUNT 分类轴和同一年度 TIME 切片 | 按已发现的该年度月份成员白名单逐行校验。一行对应一个月份和一个组。拒绝父层汇总、YTD、特殊录入或其他年度成员。先确认返回总量和截断状态 |
| 组织拆分（需要时） | 同一年度切片，按指定组织范围内的 ENTITY 同一层级 × ACCOUNT 展开 | 组织候选使用三个组的覆盖范围。只有组织成员互斥且符合模型合并口径时，才将分项之和与组织总额比较 |
| 跨年度规划（需要时） | 固定编制年、版本、币种、组织和科目，只比较所选规划范围内各年度合计 | 明示其独立年度范围，排除 .INP 等特殊成员，避免把多年总额用作当前年度 KPI |

具体组织选择在年度及月度同时增加同一个 ENTITY 切片。用户选择全部组织时，按 Provider 确认的方式省略可选切片，显示“全部组织”。核实有效请求参数与预期行集，不能用查询成功或控件标题证明筛选已生效。选到另一个版本、编制年、规划年、币种或组织时，验证指标绑定使用对应的新成员。已有固定图表若不跟随某控件，明确写出其独立范围。

## 逐组对账

保存两份同批次完整预览。用来自**实际请求**的模型及版本、版本成员、编制年、规划年、币种、组织和全部其他切片作为共同范围，按唯一成员名映射结果。按 AC01、AC08、AC05 分别比较年度源值与月份源值之和。年度父成员不再参与月份加总，先对带符号原值对账，最后再换单位。年度与月度任一失败、截断、字段缺失或混用以前批次时，不输出对账通过。

可把留存结果适配为本地 JSON 后运行 `python3 scripts/reconcile.py <input.json>`。以下是脚本的本地输入约定，实际 Provider 回执字段以其合同为准。可参考[合成输入样例](../scripts/test_reconcile.py)中的 `fixture()`，它以次年规划、仅 12 月有记录为例。

- `accounts` 将三个业务编码映射到本实例的科目成员唯一名。`months` 将规划年度的 12 个 `YYYY-MM` 映射到已发现的基础月份唯一名。合同采用 12 个自然月，有特殊会计期间的模型需先确认期间映射。
- `annual` 和 `monthly` 各含 `scope`、`complete` 和 `rows`。共同的 `scope` 包含 `source_version`（明确指向当前模型、Cube、度量和版本）、`batch`、`category`、`plan_year`、`report_year`（所选年度汇总成员）、`calendar_year`（该 TIME 成员对应的四位自然年份，从元数据确认，独立于编制年）、`currency`、`entity`（全部时为 null）和 `extra_slicers`（其他维度到成员的完整映射）。只有回执证明查询成功、全量未截断且字段映射正确，才设 `complete=true`。
- `rows` 每行含 `account` 和 `amount`（未舍入、带符号的十进制字符串），月度行还含 `month`。取唯一成员名，不传科目显示名、月度标题或显示金额。
- 输出每组年度原值、已返回月份合计、缺失月份和差额（年度减已返回月份之和）。相等只表示已返回月份可与年度数字对上。缺行不补零，收入定义、组织合并和年底集中录入语义需各自核实。脚本离线处理，不能独立证明输入回执真实或建立业务验收。
