本次在 xpert-pro 与 data-xpert 的本地 SSO 环境实际部署验收，使用真实模型、已授权的数据源和 Workbench。测试使用独立验收 Artifact，未覆盖原有手工看板。

## 实际对话和发布

| 场景 | 观察结果 |
| --- | --- |
| 第一轮样式修改 | 打开现有工作草稿，读取 HTML，写入页面后自动保存为 r2；仍无正式版本 |
| 同一会话继续修改 | 读取 r2，将柱形图改为折线图并修改标题，自动保存 r3；Artifact ID 不变，正式版本数仍为 0 |
| 服务重启与草稿重开 | 重新进入 SSO Workbench，恢复 r3、ECharts 页面、数据绑定和筛选 |
| 取消定稿 | 打开发布对话框后取消，正式版本数保持 0 |
| 第一次人工定稿 | 在 data-xpert Workbench 确认 r3，产生 v1；重复同一发布请求返回相同版本 |
| 已发布后继续修改 | Agent 读取当前看板并保存 r4，Workbench 自动切换到草稿预览；正式历史仍只有 v1 |
| 第二次人工定稿 | 在 xpert-pro 界面检查旧版和 r4，再确认发布 v2；两边重开均显示同一 v2，v1 定义保持不变 |

模型的完成回复报告实际草稿修订号，并说明尚未发布。另一个真实失败用例中，模型把文件路径错误地传成 `.html`；没有拿到保存回执，执行被明确判定失败，未生成虚假的正式版本。随后增加了已打开页面写入时的自动保存，以及可定位的路径错误提示，重新完成上述成功流程。

## 数据与边界

ECharts 看板使用独立的 PostgreSQL 业务 fixture：全部净销售额 5700、华东 3500、华西 2200。实际切换区域与刷新验证正确。临时将华西七月数据增加 100，刷新观察到对应图表值由 800 变为 900；保留筛选和当前文档，随后恢复来源并再次验证。

data-xpert 本体、Workspace Python 和 Workspace JavaScript 来源分别验证了草稿保存、继续修改、重开、Binding 保留以及重新查询；每份查询均返回 6 行，重复刷新产生不同执行 ID。这部分验证来源兼容性，不替代各来源历史业务语义验收。

并发请求修改同一草稿时，一个提交成功、另一个返回冲突；正式版本数不变。过期修订查询、过期修订发布、缺少人工确认字段的发布、替换原始查询载荷均被拒绝。HTML 内的未声明 Binding、父页面访问和直接网络请求被拒绝。

## 后续流程调整（2026-10-17）

上文保留当时的验收经过。文件工具统一后的当前流程是：写入或编辑 HTML 文件后，Agent 显式调用 `dashboard_create_html` / `dashboard_update` 自动保存草稿，并取得对应文件字节的成功回执；文件写入本身不触发 Artifact 保存。人工发布仍是独立步骤。本次分批代码审查没有重新部署或重复 SSO 验收。
