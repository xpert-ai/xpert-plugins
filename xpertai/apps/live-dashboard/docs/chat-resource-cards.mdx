## 使用方式

Agent 成功执行 `dashboard_create`、`dashboard_create_html`、`dashboard_update` 或 `dashboard_open` 后，消息列表自动显示一张资源卡片，包含看板名称、图标、草稿修订号或正式版本号及“打开”按钮。

点击“打开”进入现有 Workbench 实时看板视图并选中对应 Artifact。消息内不运行看板，不复制 HTML、SQL、Dataset 行数据或凭据。标准图表与 HTML/JS 看板共用同一种卡片。

- 草稿卡片是该轮保存状态的快照，点击后读取当前保存内容。
- 显式读取历史 `versionId` 时，卡片固定打开该正式版本。
- 同一条回复多次处理同一个 Artifact，平台更新同一张卡片；其他回复保留各自快照。
- 重开对话恢复已保存卡片。加载消息本身不会自动打开看板。
- 卡片不授予新的访问权限。点击后仍须通过当前主机、用户和 Artifact 的权限检查。

## 职责与协议

平台负责 `emitResourceCard`、消息/执行绑定、持久化、去重、通用卡片渲染和导航。插件只生成 `live_dashboard / live-dashboard` 资源引用及看板展示快照；不新增消息 API、卡片 Provider 或专用聊天渲染器。

Agent 主机使用 `workbench.view`；Project 主机使用 `assistant.project` 和平台 Project ID。目标 View 为 `live-dashboard__live-dashboard`，`selectionId` 为 Artifact ID，历史版本使用 `parameters.versionId`。

View 用同一个类型校验器解析 `initialQuery` 和后端查询，拒绝不合法 ID、相互冲突的目标及没有 Artifact 的版本参数。重复 `init` 不重复加载，不丢弃本地编辑。手动选择、保存和工具完成后的导航通过公开 `workbench.navigation.open` 同步，避免后续卡片点击仍指向旧选择。

工具只在授权读取或持久化成功后发出卡片。`resourceCard.status` 为 `emitted` 或 `unavailable`，独立于业务保存回执；展示失败不重试创建或回滚已保存内容。Agent 使用安装的 `live-dashboard` 技能，不需要另外调用 `present_files` 或构造链接。

## 验证范围

插件测试覆盖标准/HTML 创建、打开、修改的真实工具回调；失败操作不发卡片；稳定身份、Project 路由、历史版本及拒绝越权/非法目标。生产前端包的 Workbench 测试覆盖卡片切换目标、历史版本、重复初始化保留编辑，并回归筛选、刷新、保存重开与团队分享。

资源卡片默认在 ChatKit 自己的 Workbench 中打开插件 View，复用现有 `workbench.navigation.open`、View 注册及历史恢复能力，无需新增导航模式选项。ChatKit 解析当前授权会话的卡片与可用 View，传递 `selectionId` 和 `parameters`；插件通过 `initialQuery` 读取指定看板。平台继续负责 View 和 Artifact API 的权限检查，跨 Project 等导航仍使用既有平台协议。
