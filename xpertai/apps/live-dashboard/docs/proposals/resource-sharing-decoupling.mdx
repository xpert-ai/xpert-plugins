## 状态与决策

2026-11-08：首次记录为 Proposal，暂缓实施。随后确认实施第 2 项的现有 Provider 复用方案；第 1、3 项仍暂缓。

当前平台已负责授权、身份、审计和分析限制，ChatKit 消费侧没有 Live Dashboard 专属分支，可以继续使用现有方案。本提案记录复用边界的后续改进，第 2 项按下述边界调整接口；未改变数据库或既有授权。其他建议不代表已经实现。

本次单独调整分享弹窗宽度：宽视口最多使用 `42rem`，窄视口保留两侧留白，长表单维持纵向滚动。该布局调整不改变授权行为。

## 当前职责

| 层次 | 职责 |
| --- | --- |
| Xpert Platform | Artifact 固定版本授权、目标群与项目、有效期、接受与撤销、访问复查、审计、查询预算和通用分析策略 |
| Cloud / Bosi 宿主 | 验证 View 声明与作用域，使用宿主登录身份执行受限管理命令，不向远程页面暴露凭据 |
| ChatKit | 通过 SDK 展示共享资源、确认分析范围、接受授权和打开资源 |
| Live Dashboard | 分享入口、看板发布与依赖检查、版本包解析、从 manifest 提取数据集和参数、把请求映射到固定 Binding |
| Analytics Provider | 数据源的分享资格、实际查询、发起成员的上游访问权限 |

当前 `ShareDialog` 包含群聊授权和分享链接两个页签。群聊表单由 `src/remote/group-grant-panel.tsx` 和 `src/remote/group-analysis-policy.tsx` 实现；看板分析适配位于 `src/lib/artifact-type.provider.ts` 的可选 `analytics` 扩展；`src/lib/dashboard-artifact.ts` 供展示和分析共用固定版本解析。

三档权限、字段白名单、固定行范围、明细开关和返回条数属于平台的通用分析策略。具体有哪些数据集、字段、筛选参数，以及如何读取看板正式版本，属于 Live Dashboard domain。

## 待实施建议

### 1. 抽取通用授权表单

当前群聊授权和分析范围编辑主要是通用交互，但组件仍依赖 Live Dashboard 的远程 bridge 和文案对象。后续有其他资源接入时，提取为平台共享资源 UI 模块，避免各插件复制表单。

- Live Dashboard 保留工具栏入口、分享弹窗外壳、看板发布检查与分享链接的领域说明。
- 通用组件通过类型明确的 API 接口、资源版本、数据集描述和本地化文案工作，不导入插件 bridge、看板服务或数据源服务。
- Cloud / Bosi 保留各自的宿主适配；组件不持有登录令牌，不自行构造更宽的作用域。
- 服务端继续执行全部授权校验；前端筛选和禁用状态不构成安全边界。
- 共享 UI 模块应支持其他资源插件消费，ChatKit 继续承担群内资源的消费侧交互。

组件命名和包归属在有明确复用方时确定；不因本提案预先新增 SDK Capability 或宿主内部服务出口。

### 2. 分离分析接口与展示接口（已调整，待本批审核）

原实现通过 `IArtifactPresentationProvider.analysis` 提供无界面分析。当前优先复用已有扩展点，没有新增独立 `IArtifactAnalysisProvider`、Decorator 或 Registry。

- `IArtifactTypeProvider.analytics.resolveBindings` 只从平台提供的固定版本内容解析数据集 Binding。
- 可选 `normalizeControls` 保留看板控件默认值、允许值、类型检查和选定 Binding 的参数映射；不查询数据。
- `ArtifactVersionContext` 是展示与分析共用的中立版本上下文。平台共用内容读取、身份和完整性检查，不通过展示 Registry 调度分析。
- 平台生成安全的数据集描述，编排源端分享资格检查、群聊同意范围、预算和审计。实际只读查询复用 `AnalyticsQueryProvider.execute`。
- 数据源分享资格由 `AnalyticsQueryProvider.authorizeGroupSharing` 判断。群聊执行与资格检查的宿主编排保持内部方法，不新增插件 Capability 方法。
- `IArtifactPresentationProvider` 只保留展示入口、展示数据与界面交互。Live Dashboard 的发布包解析由展示与 Artifact Type 共用。

此次接口仍在未发布的功能批次内，直接调整所有本地消费者；保留既有 grant/reference ID、固定版本、Actor 身份、数据库和授权范围。旧的只读授权不会自动获得分析权限。当前群聊授权仍要求类型声明 authenticated presentation，尚未扩展为完全无展示资源的授权模型。

仅在后续出现独立注册、独立生命周期或同一资源多种分析实现的具体需求时，再评估独立 Provider。

### 3. 由数据源返回可授权状态和原因

当前描述只有 `canShare`，界面使用同时提到 Data Xpert 管理员和项目文件管理权限的提示。通用表单不应维护各数据源的权限规则。

后续由对应 Provider 返回结构化的可用状态与稳定原因码，平台校验并向 UI 提供安全的诊断信息。界面使用本地化消息展示原因；诊断不包含凭据、私有查询、未授权表结构或原始异常堆栈。实际提交时仍重新校验，不能把预检查结果当作持久授权。

本次已移除宿主内部编排方法在 SDK 中的专属 Live Dashboard 注释；后续诊断契约继续保持领域中立。

## 保持不变的约束

- 创作项目与群聊使用项目保持独立，群聊引用固定发布版本。
- 源端显式授权，群主独立接受分析范围，旧的只读授权不自动升级。
- 实际查询使用发起提问成员的数据源权限，结果的受众是接收群聊。
- 平台执行数据集、字段、固定行范围、明细、返回条数和执行预算限制。
- 查询前后及答案发布前复查权限；撤销不能抹除已经合法披露的历史内容。
- ChatKit 和通用平台授权代码不根据 `live-dashboard` 或库存数据集名称分支。
- 新的内部复用优先采用宿主内明确依赖或类型化 CQRS；只有具体外部插件需求才引入新的 Runtime Capability。

## 后续实施与验收

1. 选择一个有实际需求的第二种资源，确认公共表单和分析接口需要覆盖的能力。
2. 先提取 UI 与宿主适配边界，保留现有服务端授权协议，验证群主确认、过期、撤销和版本切换。
3. 验证本次 Provider 组合可以在未注册 renderer 时执行受控分析；完全无展示资源的群聊授权模型另行评估。
4. 接入 Provider 原因码，验证缺少资格、不支持分享及上游不可用时的反馈。
5. 验证 OS、Cloud、ChatKit/Bosi 和 Pro 行为一致；插件生命周期、打包内容和实际安装版本均通过验证后再发布。

验收应证明另一种资源可以复用表单而不引入 Live Dashboard 依赖，已有授权没有扩大，且数据源凭据和领域查询结构没有进入通用 UI。
