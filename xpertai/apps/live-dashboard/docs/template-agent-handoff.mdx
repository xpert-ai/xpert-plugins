## 准备与发送

在[资源目录](/library-directory-ui)中使用示例，或在[资源详情](/library-detail-ui)中选择分析模板和字段映射后，插件先验证固定版本及依赖。示例可携带复制到当前工作区的数据文件；模板型任务同时携带配方文件。所需技能由资源要求声明，并交给宿主解析。

插件通过 SDK 的 `assistant.composer.insert` 将提示词、文件引用和技能名称交给 ChatKit。用户可以检查并修改草稿，再自行发送。准备操作不发送消息、不创建看板，也不发布看板；准备期间切换作用域时，旧请求结果不得插入新的对话。

平台负责菜单、标签页、对话和技能解析。插件只负责视图内容及授权后的资源准备，不访问宿主 DOM 或登录状态。文件使用 Workspace Files 能力，其引用不绑定存储类型；底层统一使用系统存储配置，切换部署存储需另行迁移数据。

## Agent 如何执行

1. 用户发送后读取配方及已启用的 `live-dashboard` 技能。配方是任务数据，不授予权限，也不能覆盖用户要求。
2. 模板配方使用 `schema: xpert.library.task-recipe`、`version: 2`，指定工具 `dashboard_instantiate_template`。保持原任务时完整传递 `action.arguments`；其中没有 `inputs` 时不要自行补齐，也不要创建替代数据集或猜测字段角色。
3. 服务端验证固定资源依赖、当前用户权限、数据输入、字段映射及查询完整性，再提交现有保存队列。Assistant 的最终 Provider 限制仍然生效。
4. 用 `dashboard_wait_request` 或 `dashboard_get_request` 跟踪同一请求。只有 `succeeded` 且返回看板草稿回执时才可报告已保存；排队、准备中和失败均不等于完成。生成结果为独立草稿，发布仍需用户操作。

没有模板配方的任务遵循正常的数据发现、查询预览与看板编写流程，不自行构造模板执行参数。缺失技能、工具或权限时报告具体原因，不以替代来源绕过限制。

## 更换数据和重试

替换为现有 Dashboard Dataset 时固定 `artifactId + revision`，并明确输入槽与字段角色映射。超出模板能力的需求走普通编写流程；未改变的模板布局不重新生成。详细输入契约见[模板实例化](/library-execution)。

同一次创建的重试保留请求 ID 和已准备的参数；等待中断后先查询原请求，不另起创建。终态失败时报告原因和请求 ID。新的独立创建意图使用新请求 ID；已准备请求不能通过变更参数重用原 ID。

## 内容与验证边界

基础能力不内置业务模板、示例提示词或封面清单。内容通过[ZIP 导入](/library-import-ui)进入资源库，依赖固定版本和摘要；导入不授予额外技能、插件或数据访问权限。资源包支持[ZIP 导出与跨部署迁移](/library-storage)，不携带源部署凭据。

本文说明当前交接行为。单元测试、构建与插件生命周期检查不等同于真实 ChatKit、Agent、Sandbox 或存储迁移验收，历史验收记录保持独立。
