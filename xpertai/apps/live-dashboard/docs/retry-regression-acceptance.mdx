## 范围与环境

本轮于 2026-10-18 至 19 日在本地 xpert-pro 源码环境执行，复用现有 Assistant、模型、
WorkspaceFiles 和声明式 `file.table` 数据源。输入为独立合成的 CSV、JSON、XLSX 七笔销售数据。
所有生成、修复及持续修改均通过真实 Chat 发送，脚本不改写 Agent 生成的 HTML。

源码基线为 xpert `a7ff08645`、xpert-pro `0a76dabebd`、插件 `4da9a261`，加本轮工作区改动。
平台能力同步至 xpert-pro；插件通过平台本地部署命令安装，按回执重启 API，并核对安装技能的字节。
部署后严格环境检查为 ready。此处是本地应用回归，不是发布包或 SDK npm 兼容性认证。

## 实现分层

| 所属 | 改动 |
| --- | --- |
| 平台 SDK | 根据已发现的 Provider JSON Schema 检查 payload 结构；不改参数、不补默认值、不替代授权或 Provider 校验 |
| 平台文件工具 | 准确说明顺序编辑不回滚，报告已应用数量和失败序号，错误时给出重读当前文件的恢复步骤 |
| 看板插件 | 预览提前返回待执行筛选测试；打开副本明确已存在并提供保存参数；Agent 更新显式提交标题，改名和页面一次保存 |
| 插件技能及回归脚本 | 指导局部修复，按实际工具回执与持久化内容验收，保留失败与恢复记录 |

没有将看板字段或业务 oracle 放入平台，没有放宽创建工具的覆盖限制、草稿 CAS、
Provider 权限、声明式 Binding 或 HTML 沙箱边界。

## 真实模型与业务结果

| 来源 | 初次保存 / 业务修复 | 第一次修改 | 第二次修改 | 接受的页面检查 |
| --- | --- | --- | --- | --- |
| CSV | r3 页面筛选失败；Chat 修复至 r4 | r5 | r6 | 24 / 24 |
| JSON | r1 | r2 | r3 | 24 / 24 |
| XLSX | r1 | r3 | r4 | 24 / 24 |

最终回归序列共 10 个模型轮次，包含 CSV 的额外业务修复；9 个接受的页面轮次通过 72 个交互检查。
其中 7 个接受轮次没有工具错误，2 个经工具错误恢复；连同原始 CSV 失败轮次，总计 4 次工具错误、14 次保存调用。
最新“显式标题与页面一起保存”约束部署后的 6 轮修复或修改，均为零工具错误、一次保存。
XLSX 首轮修改和生成阶段发生在此前的迭代构建，整组结果不是单一不变构建的首次成功率。

每个接受的页面轮次执行八个检查：初始数据、华东筛选、更新源文件后的宿主刷新、
页面刷新、华西筛选、恢复源文件后全部区域、关闭后资源卡片重开、整页刷新恢复。
检查同时核对 KPI、逐行明细、逐月图表和区域系列，以及每个已声明 Binding 的成功查询。

独立口径为总额 5700、华东 3500、华西 2200。源文件首笔金额分别增加 100、200、300，
刷新后华东为 3600、3700、3800。工具栏刷新保留筛选和页面实例。
持续修改保持相同 Artifact、草稿、Binding、控件和依赖版本；保存 HTML 摘要与回执匹配。
新标题和新增说明反映在页面及保存元数据中。没有创建正式版本。

## 失败与恢复不能被隐藏

- 最终回归序列的首次 CSV 页面在筛选华东后仍保留华西零值系列，虽然 KPI 和明细正确，页面验收仍判失败。
  通过 Chat 在原草稿修复，再执行完整检查。修复是额外一轮，不算首次生成通过；原失败证据仍保留。
- 本轮较早的诊断尝试发现了 XLSX 契约摘要抄写错误后的重复预览，以及 CSV 编辑失败后的部分写入和错误正式基准参数。
  这些尝试保留状态及中止记录，用于推动结构错误反馈、顺序编辑恢复和 JSON null 说明；不计为接受的闭环。
- 诊断期间还出现浏览器导航超时、关闭流式 Chat 浏览器延迟和旧版检查器等待过长。
  回归流程增加了发送后恢复观察、避免重复发送和有界检查；保留这类执行器失败，不将其混作模型业务成功。
- 较早生成及编辑仍有文件已存在、字段选择错误和字符串 `None` 等可恢复工具错误。
  本次减少重试的结论来自有限真实样本，不承诺任何模型都能零错误或一次生成正确。

权限回归最初遗漏了组织初始化自动添加的默认工作区成员资格，撤销单独分享后仍可读，
该失败记录得到保留。修正测试前提后才验证撤销全部相关授权。早期清理还遇到软删除用户保留临时角色引用；
仅对本轮两个已软删除测试用户执行定向本地残留清理，未修改业务账户。
复跑流程在软删除前停用测试用户并切换到已有非管理员清理角色，最终通过公共接口完成清理。

上一轮固定基线的九个模型轮次记录了 10 次工具错误、18 次保存调用。本轮在诊断中迭代了代码，
不能将两批不同模型输出当作受控性能实验，也不能把最后几轮的成功率外推到所有生成请求。

## 权限和查询边界

- 三种格式使用同一非管理员 JWT：授权时查询 201，撤销 `DATA_SOURCE_VIEW` 后查询与发现均为 403，恢复后为 201。
- 先移除测试用户在默认工作区的继承成员资格，再撤销 Assistant 显式分享，三种文件查询均为 403；恢复后为 201。
- 最终页面共有 6 个已保存 Binding，对每个执行 9 种覆盖尝试，合计 54 次均被拒绝：文件路径、文件目录、Reader、URL、Provider、完整 Binding、payload、未知控件、未知 Binding。
- 三个最终页面均观察到直接网络请求被 CSP 的 `connect-src` 拒绝。
- 最终权限回归通过公共接口清理分享、工作区测试成员、临时权限和临时角色，并停用及软删除测试用户。

前端还检查未知 Binding、未知控件、父页面 DOM 访问和直接网络请求。
独立边界脚本使用可访问的本地健康接口，并观察浏览器 `connect-src` 违规事件，
不会把不存在域名的请求失败当作沙箱隔离证明。

源文件在每轮结束时恢复原始字节，最终重新下载并核对初始 SHA-256。
临时权限实体由专用回归流程创建和清理，不改业务账户、连接认证或外部 SSO 策略。
此项不代表重新验收外部身份提供方撤销，也没有扩展其他数据源验收矩阵。
