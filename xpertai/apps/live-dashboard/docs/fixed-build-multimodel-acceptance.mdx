## 范围

本轮在本地 xpert-pro 源码环境执行 CSV、JSON、XLSX 的真实 Chat 生成、同一草稿连续修改、
区域筛选、源文件更新刷新、资源卡片重开和整页恢复。只使用独立合成数据与现有模型连接，
不发布看板正式版本，不执行 SDK npm 或正式发布包认证，也不建立新的外部 SSO 撤销结论。

平台基线为 xpert `6df7d17f0`、xpert-pro `17d05673d`，插件为 `7f83906b` 加本轮工作区修改。
平台及文件适配器没有新增业务代码；页面约束、HTML 预检、技能和验收流程由看板插件维护。
WorkspaceFiles、Dataset/Binding、Artifacts、权限与文档隔离仍由平台提供。

## 固定构建与模型证明

诊断构建 A、B 的结果独立保留。最终构建 C 经构建、测试、本地插件部署、API 重启、
严格环境检查及四个已安装技能文件的字节核对后，才记录不可覆盖的构建清单。
清单覆盖平台版本与运行代码差异、SDK/contracts 产物、插件运行源码、技能、Sandbox Action 和 dist。
每轮生成前后及最终汇总再次比较摘要；代码或产物变化必须另建基线。
文档和回归检查器可以补充，但不能修改被测运行代码后沿用旧的成功结论。

模型选择必须在 Chat 输入框明确完成，并由每轮根执行记录的主模型 ID、名称、连接和参数快照核对。
只有模型选择器标签或 API 偏好不够。两组接受基线使用同一已配置通义连接的 Qwen 3.6 Plus 与
Qwen 3.5 Plus；参数均为 temperature 0.1、max_tokens 16384、enable_thinking true、
thinking_budget 4096、maxRetries 1。工具重试统计来自实际工具回执，不代表供应商内部重试次数。

## 本轮修复

- 打开编辑副本明确标记 `hasUnsavedChanges: false`，不再暗示查看回执后必须原样保存。
- 新看板应选择未使用的 Workspace 路径；文件同名不代表可以改写历史 Artifact。
- 同一筛选口径的 KPI、趋势和明细应从同一个完整 Dataset 渲染，避免未筛选总额订阅覆盖 KPI。
- HTML 预检拒绝可见、启用、已声明为数据筛选却没有可用选项的 select；禁用控件和纯展示控件仍可合法存在。
- 验收确认初次生成确实调用创建工具，不能把历史 Artifact 的更新算作新生成。
- 查询证据必须在 UI 操作之后发起，并携带相应的筛选值，不能拿初始加载的迟到响应证明筛选成功。
- 明细表的合计行独立核对，避免双计，也不能静默忽略合计错误。

以上约束没有放宽文件覆盖、草稿 CAS、数据源授权或 Binding 查询边界。生成指引不能代替独立业务验收。

宿主刷新保留页面实例。源文件最终 SHA-256 与初始值一致。

全部持续修改保持同一 Artifact 和草稿、递增 revision、不变的 Binding、控件及依赖锁，
并核对保存回执中的 HTML 摘要。正式版本数量均为零。

原始与期望标题差异完整保留，不将其表述为逐字节相同。

## 权限、边界与恢复

- 两组各使用一个临时非管理员，覆盖三种格式，共六组同 JWT 撤销场景。
  授权时查询为 201；撤销 `DATA_SOURCE_VIEW` 后查询及发现为 403；恢复后为 201。
  撤销临时用户的 Assistant 分享和独立工作区授权后，文件查询为 403，恢复授权后再验证可读。
- 最终七个已保存 Binding 各执行九种覆盖尝试，63 次全部拒绝：路径、文件目录、Reader、URL、
  Provider、完整 Binding、payload、未知控件和未知 Binding。
- 六个最终页面对可访问的本地健康接口发起直接 fetch，均观察到 `connect-src` 违规和请求拒绝。
  页面交互检查还覆盖未知 Binding、未知控件及父页面 DOM 访问。
- 临时分享、用户、权限和角色通过公共接口完成清理。测试结束后恢复 Assistant 原来的模型允许范围
  与默认选择，核对 graph 和 draft 未变。保留验收草稿、诊断样本和截图。
- 最后再次核对固定构建清单与严格环境 ready 状态。没有提交或推送代码。

## 自动检查与剩余限制

匹配平台源码的 SDK 构建通过；平台参数校验与文件恢复 10 项、文件中间件 10 项、
PermissionGuard 22 项通过。插件 68 项测试（包含 5 项回归证据反例检查）、真实 Chromium 预检 36 项、
元数据核对、远程 bundle 与 Action/图库摘要检查、plugin-dev-harness 生命周期通过。
本轮修改的 MDX 与导航 JSON 校验通过。

仍观察到模型参数结构错误、错误字段、文件同名、非唯一编辑文本和字符串形式的空版本值，
均按实际错误记录并恢复；不是零重试保证。Qwen 3.6 JSON 第二次修改还发生一次
`DOCUMENT_BUTTON_INTERACTION_FAILED`，相同 HTML 和保存参数在只读检查后重试通过。
保留为已恢复的瞬态预检失败，尚不能从单次样本确认原因或认定已消除。
浏览器验收另有三次卡片等待超时，均发生在发送提示之前；保留失败日志，确认卡片存在后
将等待上限调整为 60 秒并复跑，没有重复发送模型请求。

这是两个 Qwen 版本、每种格式一次新建和两次连续修改的小样本基线。
业务修复请求和 CSV 的额外视觉修复说明均单独记录，不能据此推断某模型整体优于另一模型，
也没有完成跨供应商、DeepSeek、并发压力、长时间运行或正式发布兼容性验证。

## 保留的诊断记录

构建 A 暴露了旧文件碰撞后修改历史测试 Artifact、部分文件编辑失败和无变化重复保存。
构建 B 暴露了启用但没有选项的区域筛选，以及刷新时未筛选查询覆盖筛选后 KPI。
这些样本用于推动修复，不计作构建 C 的成功样本。B 中存在与源文件变更重叠的生成及构建变化，
因此不能拿它建立固定构建成功率。

构建 C 的模型配置诊断中，API 偏好已切换但 ChatKit 实际提交默认 Qwen；执行记录识别后取消三次诊断，
验收脚本改为每轮从可见模型菜单明确选择。随后实际 DeepSeek V3.2 请求均返回供应商
`404 Model not exist`，没有进入工具调用。它是当前连接的可用性失败，不是看板业务或工具恢复成功。
失败记录保留，第二组可运行基线改用现有连接中的 Qwen 3.5 Plus。

见 `tests/acceptance/README.md`。每个模型使用独立私有输出目录与唯一标题，同一构建清单不可覆盖。

原始工具状态、保存回执、执行模型快照、DOM、截图、源文件备份和错误均保存在仓库外。

权限实体清理和每个接受页面的完整八步交互，`read-only` 诊断不能替代源文件更新验收。
