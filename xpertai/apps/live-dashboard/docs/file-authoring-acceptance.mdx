运行环境为本地 xpert-pro 与 data-xpert SSO，使用已配置的真实 Qwen 模型和默认 Docker 沙箱。代码改动同步到 xpert-pro；插件完成构建、部署及进程重启后再执行验收。凭据、会话信息、原始回执和截图仅保留在本地验收记录中。

## 发现与处理

- 可选中间件未启用会导致文件工具不在 Agent 的运行工具集中。部署指引明确将此流程依赖的中间件设为 `required`，并使用实际机器标识 `skillsMiddleware`。
- 默认沙箱 Provider 在获取沙箱时才确定。平台现按实际 Provider 重新解析工作区映射，使通用文件工具与插件 WorkspaceFiles 使用一致路径；不绕过路径和 Volume 授权。
- 初次模型生成省略了筛选默认值。Agent 创建接口现要求显式 `defaultValue`，包含表示全部的 `null`；页面预检返回明确的初始筛选不匹配原因。旧存储格式保持兼容。
- 首个生成页面在过滤后仍保留 ECharts 旧系列。真实交互验收发现后，通过同一 Artifact 的后续编辑修复；技能已补充系列替换规则及完整筛选验证步骤。
- 上游 SQL 预览曾误拒绝合法的带括号 WHERE 表达式，模型调整等价写法后通过。该既有 SQL 校验行为未在本次改动中调整。

验收分别证明了真实脚本注册、基于已注册 Dataset 的一句话生成，以及后续修改和两端交互。最初的 PostgreSQL → Python → HTML 单轮尝试未完整通过，因此本记录不将它计为端到端单轮成功，也不将提示词指导视为任意生成页面的正确性保证。

## 2026-10-17 补验：完整单轮与两端闭环

在上述修复已部署、技能已安装的环境中，新开会话，直接要求从 PostgreSQL 原始销售订单出发，经 Python 按月份和区域计算第三季度净销售额，生成浅色蓝金 ECharts HTML 看板，包含区域筛选和刷新。没有向 Agent 提供预制脚本、HTML、已注册 Dataset 或预期金额，也没有在生成过程中补充纠正指令。

单轮执行成功，19 次工具调用全部成功：5 次实际技能/参考资料读取，完成业务发现、原始数据预览、Python 文件写入、新 Dataset 注册、脚本结果预览、筛选测试、HTML 文件写入和草稿保存。最终 Binding 为 `workspace_script.query`，代码通过声明的上游 PostgreSQL Binding 实时读取订单并使用 Decimal 聚合，没有嵌入静态业务数据。保存回执的 SHA-256 与后端实际保存的 HTML 一致。

| 补验项目 | 实际结果 |
| --- | --- |
| 独立金额核算 | 直接查询测试源得到六行月度/区域汇总，总额 5,700 元，华东 3,500 元，华西 2,200 元；与 Agent 预览、页面 KPI 和 ECharts 系列一致。 |
| 初次生成即可筛选 | 两端分别切换全部、华东、华西并刷新，图表只包含当前区域系列；首次生成使用 `notMerge: true`，没有旧系列残留。 |

| 从 data-xpert 继续修改 | 在 SSO 页面要求修改当前看板名称及墨绿色强调色。Agent 通过 `dashboard_open` → `sandbox_read_file` → `sandbox_multi_edit_file` → `dashboard_update` 保存页面和标题，最终为草稿修订 3。7 次工具调用全部成功。 |

这次补验已覆盖首轮未完成的 PostgreSQL → Python → HTML 单轮流程。发布步骤由浏览器验收操作显式点击确认，Agent 本身只保存草稿。以上结论对应本次真实执行，不表示任意模型、数据源或页面均可免验收。
