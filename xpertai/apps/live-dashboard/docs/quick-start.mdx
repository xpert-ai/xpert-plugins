## 初始化应用

在 Explore 中选择实时看板应用，按平台引导配置主模型并初始化。应用使用 `live-dashboard-assistant` 制作模板，创建专用的私有配置工作空间并发布助理。默认不创建知识库，不要求嵌入模型。

制作模板依赖 Live Dashboard、Analytics Files 插件及 `live-dashboard` 技能，启用 SandboxFile 和 Sandbox。平台会检查依赖与模型就绪状态；浏览器 Sandbox 不可用时，HTML 看板预检不能完成。看板巡检模板仍是单独的可选模板，不在首次制作引导中安装。

进入 ChatKit 后选择或创建实时看板项目。项目选择与 Live Dashboard 视图保持双向同步，文件和看板均归属当前项目。初始化应用不授予项目、文件、数据库或本体资源的额外访问权限。

## 从样例制作

### 在哪里预览

- **先看效果图**：打开 Explore → 实时看板 → 应用详情。首图为应用封面，随后展示 Trend Workspace、Profit Atlas、Customer Brief 三种进阶风格的原型预览；这三张图对应 Superstore 企业分析的设计方向。
- **体验筛选和刷新**：进入实时看板助理，选择或创建项目，在开场提示或空白看板页点击对应的“体验样例”。助理生成并保存草稿后，打开结果卡片即可操作筛选、查看明细和刷新数据。
- **再次打开已有样例**：在 Live Dashboard 顶部的项目／看板级联选择器中，选择制作时使用的项目及对应看板，并进入工作草稿。无需重新生成。

详情页图片是静态预览；可交互看板在所选项目内生成。HTML 样例依赖平台提供的数据 Binding 和文档 SDK，不能通过直接双击 `dashboard.html` 获得相同运行效果。

### 选择样例

助理开场提示和空白看板页提供以下入口；级联选择器中的“新建看板”也会进入同一空白页。

| 样例 | 形式 | 学习内容 |
| --- | --- | --- |
| 区域销售 · 入门 | 标准图表 | 区域筛选、柱状图、明细表 |
| 销售总览 · 入门 | HTML / ECharts | 销售额、订单数、日趋势、区域对比 |
| 生产质量 · 入门 | HTML / ECharts | 产量、加权良品率、不良品与产线筛选 |

| Superstore 企业分析 · 进阶 | 三种 HTML / ECharts 风格 | 经营总览、商品盈利、客户与退货；需已授权的 Data Xpert 发布模型 |

三个入门样例优先显示。聊天开场仅显示上述简短业务名称，点击后仍发送完整制作指令，包括配方、数据要求、筛选验收、保存草稿和不发布约束；编辑开场提示时可分别维护显示名称和完整指令。

“体验样例”向当前项目的助理发送明确的演示制作请求。助理按需读取技能中的配方，复制标注为演示数据的 CSV 或 JSON，通过 Analytics Files 注册和预览真实文件查询，然后沿用现有创建工具保存草稿。它不是直接导入一个带旧数据源 ID 的 Artifact。

三个入门配方位于 `skills/live-dashboard/examples/<key>/`，含预览图、业务说明、源码、字段定义、查询要求、CSV/JSON 和预期结果。数据为人为构造，预览不代表用户业务数据。

样例版本更新不会覆盖用户已经创建的文件或看板。相同路径存在不同内容时应使用新文件名。修改已有看板继续使用精确 Artifact 与草稿修订校验。

## 使用真实数据

选择“使用我的数据”，由助理检查当前项目已授权的文件、数据库或 Data Xpert 本体资源。先确认指标口径、粒度、单位和字段映射，再预览、绑定和制作。缺少字段、权限不足或查询失败时不得以演示数据补齐。

演示页只有在所有绑定及可见数值均已替换为验证过的真实来源后才能移除演示标识。生产良品率按良品数合计除以产量合计计算；零分母显示无值。金额样例使用整元，适配小数或高精度货币时需要相应的精确计算策略。

## 验证和发布

制作完成后核对当前项目、默认结果、两个筛选项、恢复全部及工具栏刷新。图表、指标与明细须一致；空结果、不完整结果和查询失败应清晰显示，不能将旧值当作当前结果。

保存回执表示草稿已经持久化。正式发布继续由项目管理者在现有 Workbench 流程中确认。

## 维护样例

样例目录由 `examples/catalog.json` 管理。新增配方须提供独立 key、版本、完整源码、预览、字段与指标说明、演示文件和预期结果。示例按业务语义匹配；生产质量不能用销售数据或改名后的销售看板替代。

HTML 源码按可读行组织，避免文件工具截断长行。业务查询、筛选和明细使用同一完整 Dataset，数据访问继续通过声明式 Binding；浏览器不直接访问数据库。演示数据刷新意味着重新读取项目文件，并非自动推送更新。

运行 `corepack pnpm test` 检查模板、依赖、入口与原有权限和保存流程。构建 Analytics Files 后，在 Live Dashboard 包目录运行 `node tests/example-browser.mjs <platform-root>`，通过实际文件查询实现、文档 SDK 和 Chromium 验证数据、图表、筛选、刷新、空结果、异常和窄屏；`--screenshots` 更新配方预览。该受控测试不能替代部署后的助理与界面验收。

制作模板为读取配方、准备数据源和筛选检查预留有限执行预算；模型调用上限为 64，图执行步数上限为 300。其他未配置的 LiveDashboard 中间件仍采用 24 次模型调用上限，保存回执、预览和 HTML 预检要求不变。成功保存后结束制作，不为确认同一次保存而再次打开和更新未改动的看板。
