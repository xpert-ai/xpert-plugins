# 简历初筛工作台 v5 · 操作说明（面向使用者）

> 适用版本：分支 `feat/resume-screen-workbench` 至 commit `0e68be1`（2026-09-30 收口）。
> 面向岗位招聘操作者，解释日常使用的每一处行为口径；实现细节见 `docs/spec/resume-screen-v5-rework-spec.md`。

## 一、简历文件的存储位置（运维须知）

- 配置项 `fileStorageDir`（插件配置），环境变量 `RESUME_SCREEN_FILE_STORAGE_DIR` 可覆盖；两者都空时用默认目录 `data/resume-screen`（相对进程工作目录解析），空白值回退默认并在日志给中文 warn。
- 上传的简历原始字节按内容哈希落盘（单段内容寻址文件名），**同一份文件无论上传多少次磁盘上只有一份**。
- 变更该目录后，历史文件仍在旧目录中——预览与解析重试依赖原路径，移动目录会导致历史行「有记录无文件」，需自行迁移文件。
- 数据库只存哈希与元数据（`fileHash`/`fileMime`/`fileSize`/`filePath`），不存文件本体。

## 二、上传规则与五态

- 支持格式 `.docx` / `.pdf`，单文件 ≤ 10MB，单次批量上限 10 份（配置项 `maxResumesPerBatch`，1–20 可调，环境变量 `RESUME_SCREEN_MAX_RESUMES_PER_BATCH`）；匹配分达标线默认 60 分（`scoreThreshold`）。
- 上传弹窗中每一行呈现五种状态：

| 状态 | 含义 |
| --- | --- |
| 排队中 | 已选择、尚未发出请求 |
| 上传中 | 请求在途 |
| 已创建 | 服务端已建档并进入解析队列 |
| 跳过(重复) | 同一职位下**文件内容完全相同**（SHA-256 按内容判定，改名无效）的文件不再重复建档；重复判定按职位隔离，换一个职位上传同一文件会正常建档 |
| 失败 | 请求失败或被拒（格式/大小/读取错误），行内给出可执行指引，可点击重新上传 |

- 上传完成后列表行先进「解析中」，AI 解析回填评分后转「待审」。解析完成通常在一分钟内；若模型调用持续失败，单份简历 90s×4 次重试后落失败态并附 `parse_error` 等可执行指引（行内「重试」入口可用）。

## 三、解析滞留与兜底（sweep）

- 单份解析超过 **10 分钟** 仍是「解析中」，后台兜底任务（sweep）会接管重投，无需人工干预；UI 的超时提示与该阈值同源（10 分钟）。
- 兜底重投不消耗模型的评分次数（attempt 语义见实现文档）；若反复滞留，优先检查模型服务可用性。

## 四、预览：docx 与 pdf 的差异

- 列表/抽屉的「预览简历」按钮打开预览弹窗（docx 与 pdf 共用，宽 1100px 上限、随容器自适应）：
  - **docx**：服务端转 HTML 并经白名单消毒后展示（富文本版式，正文限 72ch 阅读列宽）。
  - **pdf**：弹窗内 canvas **直接渲染**（pdf.js），页面宽度自适应弹窗、可滚动、多页纵排；不再跳转新标签页。
- 旧数据（未保留原始文件的存量行，`hasFile=false`）：预览按钮置灰，悬停说明「旧数据未保留原始文件，请重新上传简历后预览」；这类行的「重试解析」同样不可用（无原始字节可解析）。**补救方式：对同一候选人重新上传一次简历文件**，此后预览与重试恢复。

## 五、乱码历史行的修复说明

- v5 之前经 multipart 上传的文件名存在「双重编码」乱码（如 `æå-ç®ä»¿.pdf`）。T1/T2 已完成两笔修复：
  1. 上传通道按平台同口径解码 UTF-8 文件名，**新上传不再产生乱码**；
  2. 存量乱码行已用幂等脚本回填（`scripts/backfill-v5.sql`，可重复执行，已正确的行不会被改写）。
- 若仍见到个别乱码来源显示，属不可逆损坏的历史行（原始字节未留存），以重新上传该文件为最终修复手段。

## 六、日常操作速查

- **筛选/排序**：工具条状态下拉（待审/推进/待定/淘汰等）+ 排序下拉（匹配分升降序）；页脚「已显示 n / 共 N」随筛选同步。
- **处置**：抽屉底部动作条按状态呈现（推进/待定/淘汰，淘汰需二次确认且可撤回为待审）；「编辑」按钮仅在**待审**态出现，可人工修正抽取字段与匹配分，保存触发乐观锁，他人已更新时会弹出冲突对话框（「查看最新」保留草稿刷新 /「放弃修改」丢弃）。
- **键盘**：列表 ↑/↓ 切换候选人、Enter 打开抽屉、Esc 关闭浮层；输入框内方向键不劫持。
- **刷新**：头部刷新按钮手动拉取增量；列表心跳轮询解析中状态的回填。
