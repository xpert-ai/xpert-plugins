# 面试演示操作

## 提前准备

启动 Docker Desktop、WSL 和 Xpert；确认 localhost:4200 可用、插件 loaded、已发布助手连接中间件。检查模型连接和额度，不在屏幕共享中打开凭据窗口。准备浏览器、代码编辑器、GitHub PR；会议软件用于屏幕共享，录屏仅作可选备用。无需额外启动原股票系统。

## 八到十分钟流程

1. 一分钟：说明研究人员原来在实验输出中追踪证据的困难，以及本应用固定输入、阶段记录、人工确认的范围。
2. 四分钟：在研究工作台填写任务标题和目标，粘贴 examples/historical-2026-10-30.json，创建任务，点击“引用到聊天研究”并发送。展示 shadow_get_task、shadow_begin、四维检索、财务查证和阶段保存。等待真实模型结果，不用规则或测试结果代替。
3. 一分钟：审阅结论及证据，允许弃选。点击确认，刷新页面或重新进入，展示已确认状态及四阶段结果。
4. 一分钟：展示缺失财务或非法输入提示，及真实递归故障截图。说明中断后五分钟租约到期可恢复为失败，再按原快照重试；集成测试还验证了受控工具失败和输入指纹保持。
5. 两分钟：打开 middleware.ts、domain/research.ts、task.store.ts、view.provider.ts，解释工具与人工权限、状态机、并发修订和同一业务服务；再展示测试结果、Git 提交和 PR。

研究请求示例：请研究引用的历史任务，基于已有证据完成基本面、技术、风控和决策，证据不足时弃选，不推断快照没有的历史趋势。

## 回答边界

财务未知表示快照没提供，不评价公司好坏。五只演示数据是预先限制的样本，不证明全市场筛选。技术面只有单时点报价，没有历史量能或均线时不能声称缩量、放量或趋势已验证。现有真实输出中的过度解释应主动指出，不包装为准确率。

模型慢时展示已完成的真实任务，同时现场发起小任务；清楚区分历史结果和当前运行。递归错误、凭据协议不匹配和 Workbench 入口问题可作为 AI 协作定位案例。
