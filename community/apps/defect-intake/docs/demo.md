# 五分钟演示：智能工单补全助手

演示前确认本机 Xpert API、数据库、Redis 与模型连接可用，打开已发布助手的“智能工单补全”页签。所有示例均标注为虚构，不声称连接真实业务日志。

## 0:00–0:40：痛点与边界

测试或技术支持收到零散反馈时，需要反复追问并手工整理，容易遗漏事实或把猜测写成结论。此应用使用 Xpert 的身份、助手工具、工作台、托管队列和模型运行时，把反馈整理为可人工核对的缺陷报告。重点是信息补全，不承诺自动诊断、分派或修复。

## 0:40–2:10：稀疏反馈到具体追问

新建反馈：“【虚构演示】订单列表点击导出后一直转圈，没有下载文件。”点击“AI 整理”，展示排队和分析状态。成功后查看已提取事实，展开一项“查看 AI 来源”，说明引用来自用户材料，仍需人工核对其含义。

让观众看到未知环境等字段留空，追问与当前问题相关、最多三条。实际问题由真实模型生成，不预先承诺固定措辞。可以选用已经成功分析的同类虚构记录，避免把演示时间全部消耗在等待中，但要明确这是预先生成的结果。

## 2:10–3:15：回答保存、再次整理与人工保护

在追问下填写对应已知信息，未知项继续留空。例如：测试环境、Windows 11、Chrome 124；相同条件下连续三次出现；仅确认本人账号受影响。点击顶部“保存草稿”，看到“已保存”后再点击“重新整理”。

人工修改标题或实际结果，保存后重新分析，核对人工字段保留及“人工修改”提示。打开“此前补充的回答”查看历史回答；完整刷新后重新选择记录，展示持久化结果。

## 3:15–4:15：聊天发起与失败重试

对已保存且带唯一标记的虚构反馈，在聊天中请求“查找、读取详情并启动整理”。展开工具轨迹核对查找、读取、分析工具。排队回执只表示已经启动，切回工作台检查真正的结果。

若有已保留的失败虚构记录，展示明确失败提示与原草稿，再在同一记录点击“重试分析”。不为演示而破坏共享模型配置，不把模拟宿主故障注入说成真实提供商故障。模型校验失败或超时应如实展示。

## 4:15–5:00：确认与工程证据

人工核对后点击“确认报告”，展示确认快照；后续编辑草稿时快照保持不变。确认表示人已核对，不表示问题已修复或研发已经受理。

说明 15 项测试、真实模型分析、普通用户正向操作及双向越权拒绝均有独立证据。双用户验收使用正常平台分享，不靠给普通用户管理员权限实现。展示 README 的安装、模型配置与验证命令，指出仍未覆盖的跨租户及故障注入范围。
