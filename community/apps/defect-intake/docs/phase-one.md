# 第一阶段实现与验证

2026-11-03，已完成本机 Xpert 中的反馈录入、人工编辑、保存与恢复闭环。本阶段不把 AI 整理算作已完成。

## 实现

- 独立插件 `@community/apps-defect-intake`，版本 0.1.0，`system` 层级，artifact namespace 为 `defect_intake`。
- PostgreSQL 实体表为 SDK helper 生成的 `plugin_defect_intake_record`。每次列表、读取、保存及确认都使用可信上下文的 tenant、organization 和当前用户；业务输入不接受身份字段。
- 原始反馈保持提交时的内容，拒绝纯空白及超长输入。新的报告字段全部为空，不自动生成事实。
- 原始反馈、用户补充、人工报告、业务状态、版本、确认快照及时间持久化。编辑已确认报告会保存为新草稿，旧确认快照保持独立。
- 创建使用作用域内唯一 requestId 去重；保存以 revision 做原子条件更新；确认同一版本的重试返回已有结果。失败返回有限的业务错误码，不返回 SQL、堆栈或其他范围的数据。
- 正式 React 远程组件使用共享 shadcn UI、Tailwind、i18n 及宿主主题。列表与详情在宽窗口分列，窄窗口可收起列表。保存与确认位于顶部，避免被平台浮动聊天栏遮挡。
- 助手模板直接连接领域、Todo、Context Compression 三个中间件。领域中间件第一阶段仅激活视图，尚无 AI 业务写入工具，确认始终在工作台执行。

## 模型连接与模板契约

DeepSeek 官方连接已通过平台校验并保存到本地组织，助手绑定用户提供的 `deepseek-flash`。原先配置接口的 HTTP 400 被定位为缺少当前平台要求的具名连接创建参数，已按实际接口修正。早期直接生成预检的 HTTP 503 是当时结果，不将其与连接配置错误混为一谈。

DSL 技能的快照哈希与当前宿主部分文件不同。本模板只使用已核对的公开 DTO 与字段，通过已发布公共类型约束生成，并完成了当前平台的实际安装与发布验证；未用旧快照代替当前宿主。可复用 workflow entity 不含安装后的数据库 id。

## 后续阶段

下一阶段实现真实 AI 事实提取、来源引用、针对性追问、补充后再分析，以及任务失败和重试。还需要模型生成的业务验收、两个真实用户间的完整隔离验收及最终截图/PR 材料；本阶段的身份字段拒绝测试不替代多用户隔离验收。

Context Compression 的长上下文触发、分析任务取消/过期回写、外部系统集成、浏览器矩阵及 Mintlify 完整站点构建均不在本次通过范围。文档导航 JSON 与所列文件存在性已单独检查。
