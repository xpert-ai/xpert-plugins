# AI 开发协作记录

使用 Codex 辅助理解题目、核对官方示例、梳理产品范围和准备本机开发环境。模型名称以实际会话配置为准，此处不推测未显示的模型标识。

## 从问题收集确定产品边界

最初讨论缺陷报告补全时，候选人指出没有真实生产数据，不能假设可以查询日志并判断故障原因。因此将第一版明确限定为缺陷受理与澄清：已有事实来自用户原文与补充，AI 提出追问，人工核对后保存报告。生产系统诊断不属于第一版范围。

演示案例覆盖信息稀少、信息充分和观察与猜测混合三个场景。检查重点不是让输出看起来完整，而是确认未知内容没有被编造、已提供内容没有被重复追问、用户修改能够保留。

## 选择平台内可验证的交付方式

阅读官方 `xpert-platform-local-environment`、`xpert-agentic-app-developer` 和 `xpert-plugin-development` 技能，并核对平台与插件仓库的 `AGENTS.md`。选择 source-hybrid 环境，平台和插件源码分开存放，在插件独立功能分支开发。构建、插件加载、Assistant 可用和完整业务验收分别记录，不能互相替代。

## 用实际证据排查环境问题

首次 GitHub 访问超时，终端内 GitHub 登录检查也没有成功。随后检查系统代理，在本次联网命令中显式使用已有本机代理后，两个官方仓库下载成功，GitHub 登录也验证通过。这个过程表明应先区分网络失败与凭证失败，不能仅凭受限环境中的失败结果要求用户重新登录。

Docker Desktop 经 Homebrew 下载校验后，安装时因系统命令链接需要管理员权限而失败。保留官方安装包，直接复制应用并验证签名，随后检查 Docker 服务和 Compose。没有读取或索取管理员密码，也没有修改全局 Git 代理配置。

## 验证记录

产品规格和演示数据已建立；JSON 语法检查与 Git 差异空白检查已执行。

本地平台已通过官方环境检查：API 健康、Cloud UI 可达、源码进程归属一致、插件源码目录已在允许范围内、NsJail 带认证 RPC 健康。首次管理员登录和默认组织已通过 API 验证，浏览器已确认登录页可用。NsJail 内实际业务命令尚未验收。

Node 24 下 `isolated-vm 5.0.4` 编译失败，改用从 Node.js 官方下载并校验的 Node 22.23.4 后，平台依赖、服务端和插件 SDK 构建通过。沙箱构建的网络问题通过本次构建代理及已解析的基础镜像摘要处理；平台维护源代码没有手工修改，启动构建生成的两个 timeline 资源变化另行记录。

初始环境阶段，模型密钥与模型列表检查通过，直接生成测试返回 HTTP 503，平台提供商配置返回 HTTP 400。当时仅建立产品说明和演示数据，没有宣称业务验收已通过。

## 第一阶段实现与复核

用户同意继续第一阶段后，AI 实现了独立系统插件、持久化服务、领域中间件、工作台和助手模板。人机分工保持为 AI 整理已有事实、用户补充与核对；本阶段先提供人工闭环，尚未开放模型写入与分析按钮。

对照当前平台源码发现，模型连接创建要求提供具名连接参数。补充后官方 DeepSeek 连接通过平台校验并保存，随后专用助手通过模板安装、组织内发布和视图发现。初始 HTTP 400 与 HTTP 503 是不同环节的结果，按实际接口错误分别处理。

测试中复核了原文空白保留、重复创建去重、原子 revision 更新和确认重试语义。模拟宿主与真实平台分别记录证据，不能将宿主内存状态当作 PostgreSQL 持久化。真实平台运行接口验收后，再通过浏览器新建、人工编辑、重启 API、完整刷新、重新打开与确认快照查看验证。

窄窗口检查发现宿主浮动聊天栏会遮住底部操作，因此将保存、确认移至顶部。测试完成后检查构建资产新鲜度、5 项契约测试、实际插件生命周期、元数据和密钥扫描。具体结果及尚未覆盖的多用户隔离、AI 生成和重试范围见 [第一阶段记录](phase-one.md)。

## 第二阶段实现与真实模型复核

用户同意加入 AI 自动整理、针对性追问和失败重试后，AI 在领域服务中实现输入快照、独立分析 attempt、平台托管队列与模型运行时、严格结果校验以及版本检查。模型只能提出建议，人工确认继续由用户执行。对人工清空、旧结果晚到、分析期间未保存编辑与回答关联分别检查，避免将“保留用户内容”仅停留在提示词中。

真实模型联调发现宿主发布的模型选项可能为 null，修复配置 schema 并增加回归测试。更新助手时，自动审批拒绝了修改组织默认主模型，因为可能影响其他助手；随后采用专用助手的规范导出与现有实例导入接口完成绑定及发布，未修改共享默认配置。

两轮真实 DeepSeek 分析脚本通过后，再在真实浏览器对同一失败记录点击重试、回答三项追问、保存、重新分析并完整刷新。最终报告包含回答事实，人工标题和实际结果保留，追问转向未知项。模拟宿主另外验证分析期间未保存编辑及故障注入，文档将其与真实平台证据分开。发现窄窗口下来源区和报告重叠后修正布局。详细验证与未覆盖范围见 [第二阶段记录](phase-two.md)。

## 凭证与提交检查

用户要求确认后续上传代码不会包含密钥。凭证保留在本地私有配置中，使用者提供的密钥目录位于两个代码仓库之外，配置文件受到 Git 忽略规则保护。对两个仓库可提交的工作文件、Git 暂存内容和本地已有提交进行实际密钥值扫描，未发现命中。扫描只输出文件路径和结果，不输出匹配行或密钥；推送前需按最终差异再次执行。
