# 合同关键条款审查台 — 产品说明

> Xpert Agentic App 插件 · `@xpert-ai/plugin-contract-review`
> 选题：合同关键条款审查台　作者：BANG404　日期：2026-09-17

## 1. 目标用户

中小企业的一线销售与商务。他们没有专职法务、或法务排不上队，自己拿到的合同往往只有十几分钟可以看。

## 2. 业务问题

造成损失的通常不是合同"看不完"，而是四类条款**看漏**：

| 条款类型 | 具体看什么 | 漏掉的后果 |
| --- | --- | --- |
| 付款条件 | 预付比例、账期、验收即付款 | 垫资、现金流断裂 |
| 交付 | 交期、延期责任、交付标准 | 违约在先还不自知 |
| 质保 | 期限、范围、响应时限 | 售后成本失控 |
| 违约责任 | 违约金比例、责任上限 | 敞口无上限 |

这些条款散落在几千字里、格式各异，人工核对全凭经验。漏一条就可能是一个未知的风险敞口。

## 3. 产品判断：为什么是"审查台"而不是"抽取工具"

抽取只是第一步。合同审查的业务本质是**责任归属**——结论必须由人确认，AI 不能替人担责。

所以本应用的核心指标不是抽取准确率，而是**把 AI 的建议变成可追溯的人工结论**：

- AI 只产出「建议 + 原文依据 + 风险等级 + 理由」，**不产出最终结论**；
- 每一条都必须由人工 **确认 / 修改 / 驳回**，未处理的条目不进入结论；
- 每条都留痕：**AI 原判 vs 人工终判**，以及人工备注。

这也是本应用不会被误当成"套壳抽取"的地方：如果把确认环节删掉，产品就不成立——因为那样产出的结论没有人对它负责。

## 4. 核心流程（输入 → 处理 → 结果确认 → 落库）

```
① 输入        粘贴合同正文 + 文件名
       ↓
② 处理        AI 抽取四类关键条款，每条给出
              {条款类型, 原文摘录, 抽取结论, 风险等级, 风险理由}
       ↓
③ 人工确认    逐条 确认 / 修改 / 驳回 + 备注
              顶部实时显示「已确认 x / 待处理 y」
       ↓
④ 落库        保存审查结论；列表可查、可恢复
       ↑
⑤ 失败重试    模型调用失败 → 审查单进入「抽取失败」
              输入不丢，可原地重试
```

## 5. AI 的具体作用（不含糊）

AI 负责**从非结构化合同文本中定位并结构化四类条款，并给出风险判断与原文依据**——这是人工做起来最慢、最容易漏的一步。

人负责**判断与担责**。

两者职责在界面上是分开的：AI 的输出永远显示在「AI 建议」区，人工的结论显示在「审查结论」区，两者的差异在保存后仍然可见。

## 6. 范围取舍（明确不做的）

| 不做 | 理由 |
| --- | --- |
| ❌ 全文问答 / 聊天式合同助手 | 那是聊天机器人，不是业务应用；评分标准也明确排除纯问答 |
| ❌ PDF / Word 解析 | 粘贴文本已足以验证核心流程；文件解析是接入层的事，会显著膨胀范围 |
| ❌ 多用户权限、审批流 | 超出 2–6 小时建议范围，且不是核心流程的必要条件 |
| ❌ 合同模板比对、条款库、历史版本 diff | 属于"功能更多"，评分标准明确说明不因此加分 |

## 7. 可验证的成功标准

1. 粘贴一份真实合同 → 得到四类条款的结构化建议，每条可点开看到原文依据；
2. 未处理的条款不计入结论，界面能看出还差几条；
3. 刷新页面后审查结论仍在（结果保存与恢复）；
4. 模型调用失败时输入不丢，可重试并成功（失败重试）。
