# 产品说明与范围

整理日期：2026-09-14；当前实现：Dockyard 插件 0.3.0。本文描述实际保留功能，不把旧方案或待议迁移写成已完成。

## 用户、问题与价值

目标用户是需要同时查看、编辑多份文本或代码的开发者。原方式是在工作台和聊天之间复制内容，容易漏掉来源与行范围，也容易把整个文件发出去。Dockyard 提供可调整的多面板工作台；新增右键操作把选区或整份文本带来源地放入 ChatKit，减少手工复制。

AI 的作用是解释引用内容或提出修改建议。当前不自动执行代码、不直接保存模型修改，不再提供 AI 布局或任务表单。

## 当前核心流程

1. 打开或编辑文本文件。
2. 在选区或 Explorer 文件上右键，选择“帮我改”或“解释一下”。
3. ChatKit 输入框出现文本引用，用户补充具体问题后发送。
4. 模型在聊天里解释或给出修改建议。
5. 用户若要采用建议，需要手动编辑文件，再点击 Save buffer / Ctrl+S 保存。
6. 重新进入工作台读取已保存正文；聊天结果由平台会话机制管理。

第 1–4 步已有自动测试、DOM 测试及实际接口/模型证据。第 5–6 步作为一条“AI 结果被采用后保存恢复”的完整用户路线，尚未在最终版本完成界面验收，不能视为已交付闭环。文件数据库读写测试通过不等于这条完整路线通过。

## 功能取舍

| 范围 | 当前状态 |
| --- | --- |
| 原 Dockyard 编辑器、面板、主题、预设与布局操作 | 已复用并适配；完整浏览器一致性验收未完成 |
| 选区与文件右键的两项 AI 操作 | 已实现；当前均为文本引用 |
| 数据保存 | 正文、布局、便签仍存插件数据库，按范围隔离 |
| AI 布局预览/应用、AI 协作表单、任务与文档生成流程 | 用户要求删除，0.3.0 不包含 |
| 工作区文件存储与真实附件引用 | 未实施；本轮停止开发，仅整理材料 |

## 关键页面原型与操作结构

```text
Dockyard 工作台                         ChatKit
┌ Explorer ─────┬ 文本编辑器 ───────┐   ┌ 引用卡 ──────────────┐
│ 右键文件      │ 选中文字后右键    │ → │ 操作、文件名、正文来源 │
│ • 帮我改      │ • 帮我改          │   │ 用户补充问题 → 发送   │
│ • 解释一下    │ • 解释一下        │   │ 模型回答 / 修改建议   │
└───────────────┴───────────────────┘   └──────────────────────┘
```

这是根据当前交互整理的结构示意，不是运行截图，也不是新一轮界面设计。旧高保真原型采用已删除的 AI 布局面板，只能作为历史取舍材料，不能当作当前版本原型或验收证据。

## 与题目要求的关系

题目明确要求业务应用而非仅聊天问答。当前具有可操作工作台和业务文件保存，但 AI 处理结果主要在聊天中，人工确认保存的闭环证据不足。是否接受“人工编辑采用建议”的流程需要明确，不能仅因为工作台能够运行就宣称全部满足面试要求。
