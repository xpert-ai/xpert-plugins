# AI 开发协作与候选人复盘

工具为 Codex；本会话使用 GPT-6 系列代理。早期每次开发调用的精确模型版本没有完整证据，不补写。应用运行模型是测试平台中配置的 deepseek-flash，和开发工具模型不是同一概念。

## 代表性选择

| 场景 | AI 的建议/行为 | 候选人与用户的选择及收获 |
| --- | --- | --- |
| 理解选题 | 最初错误引入需求评审场景 | 用户要求与 Dockyard 功能一致，撤回无依据的业务假设；先核对公开示例再设计 |
| 设计 AI 入口 | 先做布局助手，又增加较复杂的内容协作表单 | 用户认为不实用，最后缩到选区和文件右键两项操作；交互步骤少比功能多更重要 |
| “加载中”不结束 | 一度出现初始化未运行 | 从最终生成 HTML 查到字符串替换解释特殊字符，改为替换回调并加内嵌脚本语法检查；源码构建通过不足以证明最终页面可运行 |
| 引用成功但实际未添加 | 初始测试只有 mock，没有覆盖未挂载控制器 | CR 用实际 ChatKit 控制器复现静默空操作，增加 element 检查及回归；测试应覆盖真实依赖的失败行为 |
| 文件存储范围判断 | 初步断言只改插件即可完整迁移 | 后续核查发现公开写入接口拒绝空文件，修正结论；用户暂停迁移，不用填充空格或伪造附件掩盖能力差异 |

## 还需要改进的判断

开发范围多次扩大、文档跟随旧方案增长，超过题目聚焦 2–6 小时小闭环的建议。现在按当前功能和明确证据整理，承认旧流程删除后“AI 结果确认保存”的验收缺口，优先补最短业务闭环而非继续增加能力。是否继续开发由用户确认，本轮仅整理材料。

具体过程记录保留在本项目，提交材料只摘录以上有代表性的决策，不需要公开完整对话、个人目录或账号信息。
