## 范围和证据

本轮在本地 Xpert Pro 与 data-xpert SSO Workbench 中部署并运行当前源码，
使用已配置的模型，通过真实 ChatKit 输入自然语言请求。
Provider 覆盖 PostgreSQL、本体查询和 Workspace 脚本；脚本分别验证 Python 读取 CSV、
JavaScript 读取声明的 PostgreSQL Binding。
私有执行记录、包部署回执和浏览器截图保留在验收环境，不提交凭据或环境身份信息。

## 业务 oracle

指标为 2026 年第三季度已支付订单的实付金额减退款，单位为人民币元，按月、区域聚合。
固定预期如下；它们来自验收订单定义，不从被测查询响应反推。

| 月份 | 华东 | 华西 |
| --- | ---: | ---: |
| 2026-07 | 1,000 | 800 |
| 2026-08 | 1,500 | 900 |
| 2026-09 | 1,000 | 500 |
| 合计 | 3,500 | 2,200 |

刷新测试临时修改一条订单的实付金额，期望对应月份增加 100，再恢复原值。
CSV 生成复验额外加入上一年度同月订单与同月同区域订单，
随后把当月 1,000 拆成 900 与 100 两笔，检查页面汇总仍为 1,000，结束后恢复原始文件。
Python Dataset 合法地保留订单明细，HTML 将完整明细汇总为趋势图；验收同时核对了明细和展示汇总，
不要求所有数据源都预先返回同一种聚合粒度。

## 修复的实际问题

- **只有默认查询通过，筛选实际无效。** 第一轮 Python 脚本没有使用区域参数。
  新增 `dashboard_test_filter`，对可空的同名维度控件要求真实非空筛选证据。
  修复后的真实模型运行再次触发错误时，工具拒绝保存，Agent 自行重写脚本、重新注册和验证。
  此门槛用于模型质量控制，不替代 Analytics 权限验证，也不推断任意范围或搜索语义。
- **当前选择没有进入工具上下文。** data-xpert 原先只写入 request state。
  通用 Workbench 桥现在同时提供 request context，保留原 state 行为；SSO 身份仍由既有认证层合并。
  插件分别读取执行上下文与请求上下文中的选择，避免空执行上下文遮蔽请求。
  回归前的误选测试版本保留在测试环境；修复后必须以空参数 `dashboard_open({})` 的实际目标验证。
- **更新标题后列表仍显示旧名称。** 平台 Artifacts 增加可选的当前版本元数据批量读取，
  保持原有分页和授权作用域。插件使用当前版本标题，不另建标题存储或逐条读取内容。
- **保存后的自动纠错另建同名作品。** 同一运行中再次创建同名但不同内容的看板会被拒绝，
  要求读取已返回的 Artifact 再更新；相同内容的重试仍保持幂等，不影响明确创建不同标题的作品。
  此新增门槛通过工具级回归验证，真实持续修改另以选中作品后的更新回执验收。

## 分层和持久化

平台负责 Dataset/Binding、数据访问授权、Workspace、Sandbox、Artifacts 的不可变版本与 CAS，
以及通用文档隔离。新增的版本元数据读取和明确的文档协议类型均同步至 Xpert Pro。

Live Dashboard 插件负责看板定义、选择上下文、编辑回执、筛选验证、版本菜单与渲染接入。
数据源插件继续只负责发现和执行，未引入页面样式、看板版本或 Workbench 状态。
data-xpert 只修复通用上下文桥，不包含看板专用字段或逻辑。

历史版本保存原 HTML、控件和 Binding，打开历史版本时仍查询当前可访问的最新来源数据。
这里的刷新是用户触发的重新查询，没有新增定时轮询、CDC 或服务端推送。

## 验收结果

| 数据路径 | 页面生成 | 持续修改 | 保存身份 |
| --- | --- | --- | --- |
| PostgreSQL 直接查询 | 浅色销售分析 | 墨蓝指挥屏，v1 → v2 | Artifact ID、Binding 保持不变 |
| data-xpert 本体查询 | 深色经营驾驶舱 | 浅色财务报表，v1 → v2 | Artifact ID、Binding 保持不变 |
| Python + CSV | 暖色文件分析 | 深绿色驾驶舱，v1 → v2 | Artifact ID、脚本版本 Binding 保持不变 |
| JavaScript + PostgreSQL | 蓝白运营分析 | 黑金经营简报，当前 v3 | Artifact ID、脚本版本 Binding 保持不变 |

四次修改均在真实 Workbench 选中作品后，以不包含 ID 的自然语言提出。
成功执行的首个 `dashboard_open` 参数均为 `{}`，随后 `dashboard_update` 返回原 Artifact 的新版本。
JavaScript 案例保留了上下文回归测试阶段的 v2，因此最终为 v3。
实际界面在更新工具完成后自动打开新标题和精确版本，无需刷新宿主页面。

上述四条路径的生成版与改版均完成浏览器区域筛选、源数据变化后的刷新、原值恢复和保存重开。
刷新时保留筛选与同一个 HTML 文档实例，明细及 KPI 随真实来源金额变化；未发生页面重载。

跨版本接口检查覆盖 4 个案例、9 个版本、54 次成功查询／刷新和 54 次拒绝请求。
所有版本的全部／华东／华西结果均匹配独立 oracle，刷新产生新的执行记录；
修改前捕获的原始定义摘要不变，样式更新保留原 Binding。
传入 SQL payload、替换 Provider、替代 Binding、替换数据源均被拒绝，
未知 Binding 返回 403，未声明控件返回 400。

平台 API 重启后，四份看板均从真实 SSO 页面重新打开；版本菜单分别切到初始版本和当前版本，
每次都展示对应页面及 6 条正常业务数据。版本总数、精确版本 ID、列表标题与持久化回执一致。
所有临时 PostgreSQL 金额和 CSV 内容均已恢复；失败及重复测试作品归档保留。
