## 本地自动检查

在 community 工作区使用固定版本的 Corepack pnpm：

```sh
corepack pnpm --filter @xpert-ai/plugin-live-dashboard test
corepack pnpm --filter @xpert-ai/plugin-live-dashboard verify:dist
```

测试覆盖 Dataset 映射、图表粒度、预览回执、权限重验、筛选探测、版本并发、
不可变 HTML、查询入口拒绝替代 Binding，以及后台预检与临时数据清理。
源文件与远程 bundle 的摘要一致性通过 `verify:dist` 核对。

Action 验证拒绝额外文件、符号链接和陈旧内容。打包后从源码目录验证解压的真实包：

```sh
node scripts/build-action.mjs --verify-package /absolute/path/to/extracted/package
```

同时运行仓库的 `plugin-dev-harness`，验证实际包入口、Nest 注入和关闭流程。
能力 mocks 只用于生命周期，不证明真实平台权限或容器执行。

## 浏览器与平台验证

`tests/html-preflight-browser.mjs` 使用真实 Chromium 和构建后的通用文档宿主，
检查数据渲染、未知 Binding 和渲染异常。
`tests/workbench-browser.mjs` 使用生产远程 bundle 与内存 View Host，
检查保存、筛选、刷新、重开和成功回执的精确版本。

```sh
node tests/html-preflight-browser.mjs /absolute/path/to/platform
node tests/workbench-browser.mjs /absolute/path/to/platform /private/screenshot.png
```

当前 SDK 的 npm semver 范围不能证明新增接口已发布；本地构建验证需要相应平台源码产物。
分批提交审核在临时快照构建和测试，不覆盖运行中的 dist，也不重新部署或重跑 SSO。

真实验收使用 `verify-installed-dashboard.mjs` / `verify-installed-html.mjs`，
传入私有上下文与独立业务 oracle。固定日期的历史模型、SSO 与页面交互结果
保留在历史验收文档中，不应当作本次暂存代码的重新部署证明。

## 持续修改的真实验收

`tests/verify-installed-evolution.mjs` 检查同一 Artifact 的多个精确版本、定义 ID、
样式修改前后 Binding 不变、独立业务 oracle、刷新执行 ID 和声明式查询拒绝路径：

```sh
node tests/verify-installed-evolution.mjs \
  --platform-root /absolute/path/to/platform \
  --context /private/evolution-context.json \
  --output /private/evolution-receipts.json
```

私有上下文提供 `apiUrl`、`orgId`、`assistantId`、Keychain 服务名以及 `cases`。
每个 case 包含 `name`、`artifactId`、`providerId`、按时间排序的 `versions`
（`versionId`，纯样式修改另设 `preserveBindings: true`）和独立 `oracle`。
初始版本可提供修改前捕获的 `manifestSha256`，用于验证历史定义字节对应的 JSON 内容未变。
oracle 指定 `fields`、`numericFields` 与各场景的 `controls`、预期 `rows`。
不要使用被测接口返回的数据来生成预期值，不要提交私有上下文或回执。

接口检查不替代浏览器验收。还需在真实 SSO Workbench 中用一句话生成，选中页面后
用不含 ID 的修改请求取得 `dashboard_open({})` 和 `dashboard_update` 回执，
实际修改来源数据、刷新后检查数值变化和筛选保留，再恢复来源。
最后通过版本菜单查看旧版，重开当前版，并在平台重启后复验持久化结果。
