# 产品与实现说明

## 用户流程与页面原型

目标用户为固件/语音包OTA发布工程师。原流程是从变更记录手写说明、群内审核、Excel归档；应用将输入、AI草案、人工审核、运行记录放在同一工作台。

```text
新建区：机型 / 版本 / 每行一条变更 → 创建草稿
列表区：机型、版本、状态     详情区：
                           draft：编辑机型/版本/变更 → 保存 → 生成
                           ai_running：禁用重复生成
                           ai_failed：失败原因 + 重试
                           ai_done：编辑说明 / 移除误报风险 / 逐项勾选
                                    灰度建议 / 总确认 → 归档
                           confirmed：只读说明、风险、建议、运行历史
```

工作台通过宿主桥接执行动作，服务保存业务对象；生成与重试返回promptText，由assistant.chat.send_message发送给助手。模型先调用relnote_get_draft，随后relnote_save_note写回。工具完成事件触发工作台刷新。

## 关键设计

- 发布单与AI运行记录分表：同一releaseId重试，attempt递增，失败记录不删除。
- expectedRevision拒绝旧版本写入；草稿保存和归档使用带版本与状态的条件更新。
- 草稿未保存时禁止生成；人工审核修改在归档时提交。
- 模型仅提出建议，不具备真实OTA发布接口。
- 文档补充不是回滚能力证明；有风险应提供原变更依据及待验证建议，不把推测写成已验证事实。

## 功能取舍与限制

- 不接真实Git、需求或OTA系统，使用明确标记的合成变更。
- 单助手、单组织演示；未完成跨账号真实权限验收，服务范围测试使用测试替身。
- 风险支持移除和确认，不支持自由新增或修改风险字段。
- 未保存页面修改在刷新或切换记录时丢失，有明确提示。
- 持久化业务闭环已验证，但未做数据库故障下跨表事务一致性、多请求压力或崩溃恢复验收。
- 请求AI与创建运行记录尚非完整事务化并发调度；UI防连点不等于分布式幂等保证。
- 模型不调用工具、网络中断等场景的自动超时恢复尚未覆盖；已验证的失败是工具保存故障注入。
- 分类正例部分通过且有措辞缺陷；真实截图已补，空列表实机证据仍待补齐。不得将一个无风险用例通过解释为全面风险识别可靠。

## 开源复用

工程参考xpert-ai/xpert-plugins的community/apps/sales-ontology：插件注册、中间件、视图提供者、助手模板和桥接组织方式；使用Xpert SDK、NestJS、TypeORM及React提供运行能力。

本插件独立实现OTA发布单/运行实体、三项业务工具、状态流程、审核表单、故障注入、同单重试及对应测试。没有把Sales Ontology的本体业务作为OTA功能交付。

仓库根LICENSE为AGPLv3文本，本插件package.json声明AGPL-3.0；保留上游许可和相关声明。React UMD由已安装的react/react-dom依赖解析，不冒称自行实现；分发依赖时保留各依赖许可。本节不是所有传递依赖的完整许可证审计。

## AI协作记录（供候选人核对后面试讲解）

开发工具为Codex；未留存可核实的开发模型精确版本，不能编造。平台业务助手实测使用deepseek-v4-flash；模板默认模型不同，部署时需在平台选择实际可用模型。

1. 从业务场景收敛范围：人工粘贴变更而非接入Git，把时间放在保存、审核和恢复。
2. React加载报错：将非导出子路径解析改为定位包package.json后拼接UMD文件路径，构建后在平台验证。
3. 重试只有运行记录没有消息：统一生成与重试的client command路径，用故障注入验证按钮自动发送，而非手工补消息冒充成功。
4. 模型把补充回滚说明误当能力缺失：增加事实边界约束，并用新会话相同输入复验；旧会话影响的具体机制未证实。
5. 人工归档：候选人补充演示标记并确认，随后刷新检查持久化；AI没有替代最终审核。

以上是可查过程摘要，不是候选人已经掌握这些知识的声明。面试前应亲自解释工具、revision、失败重试和PR关系。
