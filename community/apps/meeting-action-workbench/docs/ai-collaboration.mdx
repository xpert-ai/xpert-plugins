## 使用的工具和模型

- Codex：阅读需求与仓库约定、检索 SDK 和示例、生成实现草稿、运行测试、检查差异、辅助本地部署与验收。
- DeepSeek `deepseek-v4-flash`：在 Xpert Assistant 中执行真实会议提取和行动项语义风险巡检。

Codex 参与开发过程，DeepSeek 参与应用运行过程。两者的权限与数据边界不同，均不直接拥有业务确认权。

## 人工负责的决策

开发者确认了目标用户、四天范围、中文界面、业务状态机、数据表、规则与 Agent 的职责拆分，以及“Agent 只写风险草案”的权限边界。AI 建议需要与当前 Xpert 源码、Plugin SDK 类型和真实平台行为核对后才进入实现。

模型擅长从自然语言中识别含糊承诺和潜在冲突，但不适合计算日期、判断缺字段或修改正式执行状态。因此逾期、临期、缺负责人和缺截止日期使用确定性规则；用户确认和风险处置保留在 Workbench。

## 协作过程中的关键问题

1. 本地模型提供商已经安装但主模型列表为空。通过检查平台提供商作用域和模型配置，区分租户级 Copilot 与组织级 Assistant 配置，并完成真实请求验证。
2. PostgreSQL 更新语句使用了不兼容的别名，导致真实人工确认失败。定位到服务层 SQL 后修复，并增加回归测试。
3. Remote View 曾只判断 HTTP 成功，没有判断业务响应中的 `success: false`。桥接层改为同时验证两层结果，防止界面误报保存成功。
4. Assistant 升级必须保留原 ID、会话和绑定。最终使用模板同步原地升级，没有删除后重建；模板已升级到 v4，发布版本保持 v1。

## 结果验证方法

每个 AI 生成的实现都通过至少一种独立证据验证：TypeScript 检查、Node 测试、真实构建工件 E2E、`verify:dist`、插件生命周期、本地 Xpert API/UI、PostgreSQL 状态或真实 DeepSeek 工具调用。测试失败时优先定位契约或状态问题，不通过缩小断言掩盖缺陷。

## 数据与安全

开发和测试只使用合成或脱敏会议文本。模型密钥在 Xpert 本机配置中录入，不进入对话、源码、截图、文档或日志。向 DeepSeek 发送巡检上下文前取得了明确授权；Agent 工具仍受租户、组织、Schema、幂等和 revision 约束。

## 开源复用

工程结构、Plugin SDK、共享 shadcn UI 和 Xpert 平台能力来自 `xpert-ai/xpert-plugins` 与 `xpert-ai/xpert`，遵循其许可证和接口约定。会议业务实体、状态机、Agent 工具、Assistant 模板、Remote View 与测试是本应用新增实现。没有复制第三方业务源码，也没有使用机器专用的私有依赖。
