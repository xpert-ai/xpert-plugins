# 演示脚本

## 一分钟产品介绍

客服团队收到的售后描述通常口径不一，主管需要逐条判断类别、紧急程度和回复方式。本应用先保存原始工单，再让 Xpert Assistant 生成结构化分析，最后由人工确认回复。AI 缩短阅读和草拟时间，但不替代业务授权。

## 主流程

演示数据：

- 客户：王女士
- 主题：同一订单被扣款两次
- 描述：订单 20261111001 昨晚支付后显示成功，但银行卡出现两笔 299 元扣款，希望核查并退回重复扣款。

操作：

1. 在 Workbench 创建工单，展示状态为 `pending_ai`。
2. 刷新页面，证明原始工单已经持久化。
3. 点击“让 AI 分析”，切到对话界面展示 Assistant 调用读取和保存工具。
4. 回到 Workbench，展示 `awaiting_review`、类别、优先级、摘要、证据、置信度和回复草稿。
5. 强调草稿没有承诺退款已经完成，只说明将核查并反馈。
6. 点击批准，刷新页面，展示 `approved` 状态仍然存在。

## 失败与重试

1. 创建第二条工单并完成 AI 分析。
2. 点击“模拟失败”，展示持久化的超时原因和尝试次数。
3. 刷新页面，证明失败不是前端临时状态。
4. 点击“重试”，状态回到 `pending_ai`。
5. 再次让 Assistant 分析，确认不会生成重复终态记录。

## 面试说明重点

- 为什么选择单一小闭环，而没有加入多智能体和复杂权限。
- Agent 工具只保存结构化判断，不接受租户、组织等可由服务端恢复的字段。
- 为什么外部承诺必须经过人工确认。
- 如何用状态机避免重复批准和无效重试。
- 当前已验证与未验证内容的边界。
