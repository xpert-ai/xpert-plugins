# 驱动电机制造全流程

在 XpertAI 的「订单协调助手」中，新建一张 12 台 EM-160 的样例订单。销售助手读取合同，工程负责人批准差异并冻结 BOM，计划负责人决定是否接受提前三天交货。交付后，按一台报修电机的序列号追溯实装件、试验与签收记录，并让下一单采用批准的经验。

## 客户现场入口

进入「驱动电机制造演示」工作空间，打开「订单协调助手」的「电机订单总览」，选择「新建样例演练」。进入「订单流程与审批」，按业务阶段选择节点 Tab，核对当前岗位的工作单、上游凭证、审批意见与交接去向。选「分批交付」可以看到 8 台和 4 台的两次签收。工程知识负责人批准发布后，从原单创建下一单，依次打开销售和工程节点，核对总成 IP67 及新增的密封圈定位复核要求。

| 入口 | 节点如何执行 | 证据与限制 |
| --- | --- | --- |
| 新建样例演练 | 工作台运行固定角色样例。五次审批必须由当前订单创建人提交并填写依据 | 不依赖模型生成。页面标明模拟角色执行，保存实际审批账号。可从新单回看经验来源 |
| 新建智能体流水线订单 | 启动项目流水线后，由宿主派发至七个独立的已发布 Assistant。人通过项目人工节点决定放行或退回 | 需要套件发布、有效的主模型和工具调用、宿主队列工作进程已加载本插件。实际执行和会话回执可在工作台查看 |
| Agent Evolution | 首单 R1 对应独立的组织内候选变更，使用六条标注样本评估，人工批准后产生 R2 发布回执 | R2 随后续订单冻结。新建独立订单仍从 R1 开始，便于重复宣讲 |

工厂数据来自插件样例。PLM、ERP、MES、QMS、WMS 和售后回执均标明来源。切换到客户数据时，按系统建立物料与订单行映射、只读查询、授权写回和结果对账。首版中四种审批岗位由一个演示账号依次扮演，上线时需按客户岗位和用户组绑定多人审批。

## 开发与安装

在 community 工作区安装依赖后，从本应用目录运行以下命令。

```sh
corepack pnpm run typecheck
corepack pnpm test
corepack pnpm run build
node ../../../plugin-dev-harness/dist/index.js --workspace . --plugin @xpert-ai/plugin-ev-motor-lifecycle
```

通过 Xpert 的本地插件部署工具按 tenant 级安装本包，并按部署回执在对应 API 与队列工作进程激活插件。切换到要演示的组织，在应用市场找到「驱动电机制造全流程」，初始化应用，选择主模型，发布协调助手和七个角色助手。套件部署也支持宿主的 init-assistant-suite.mjs 及 blueprints/assistant-suite-v1.json。项目启动时按模板键解析发布实例。
