# 验证记录

本文按四层记录验证：单测与构建、harness 生命周期、界面、平台业务流程。每项都写了操作、预期和实际结果。构建通过不等于加载成功，加载成功也不等于用户操作成功，所以每一层分开写。没有验证过的部分集中列在最后。

第 3、4 层的截图和数字都来自 2026-11-16 在空库上从头走的一遍：重新安装插件，从模板创建助手，载入演示请求，然后逐项操作。数据库里的任务记录和截图一一对应。

## 第 1 层：单测、类型检查、构建

在 `community/apps/expedite-shortage` 目录下执行（2026-11-14 重跑）。

| 命令 | 预期 | 实际 |
|---|---|---|
| `pnpm typecheck` | 服务端和界面两套 tsconfig 都没有类型错误 | 通过 |
| `pnpm test`（vitest） | 全部用例通过 | 5 个文件、42 个用例全部通过：缺料计算 11、元数据一致性 3、视图与模板 8、工具契约 4、Service 状态机 16 |
| `pnpm build` | 界面打包、tsc 编译、复制资源，最后 `verify:dist` 校验 | 通过；`app.js` 278838 字节；`Remote assets are current.`、`Dist assets verified (3).` |
| 提交时的 pre-commit 钩子 | 实体表名检查、依赖冻结校验 | 每次提交都通过 |

单测覆盖的要点：

- 缺料计算：两层 BOM 展开，同一物料合并；只把目标日前到货的在途算进可用量；三条演示请求得到预期结论（SO-1024 缺 2 项，SO-1031 关键料提前期不够，SO-1040 不缺料）。
- 状态机：合法迁移成功；非法迁移被拒，比如草稿直接确认；还有未决定的缺料时不能确认；确认后不能再改。
- 幂等：连续两次开始分析只产生一个活动任务；同一任务同一物料保存两次只留一条；旧任务的写入被拒（`JOB_NOT_ACTIVE`）；重复确认返回 `ALREADY_DECIDED`。
- 超时和放弃：注入时钟，2 分 59 秒时任务仍在运行，3 分 01 秒读取时判为 `ANALYSIS_TIMEOUT`；放弃本次分析得到 `ANALYSIS_ABANDONED`，已经超时的任务仍记为超时。
- 演示故障：开关打开时，第 1 个任务报 `INVENTORY_UNAVAILABLE`，第 2 个任务正常。
- 工具契约：每个工具用最自然的合法输入能一次通过；多余字段、非法 uuid、超长说明、空数组都被拒，并且错误信息可读；返回值里不含 tenantId 等内部字段。
- 元数据和视图清单：`meta` 与 `package.json` 一致；表名都以 `plugin_expedite_shortage_` 开头；界面用到的动作都在清单里。

## 验证中发现并修复的问题

| 现象 | 原因 | 处理 |
|---|---|---|
| 第一次真实分析 SO-1024，在提交总结论之前报“已达到递归次数 40 限制”，任务停在运行中 | 平台按执行图节点计算递归次数。每一轮“模型 → 工具”还要经过上下文压缩和待办两个中间件，7 轮工具调用超过了 40 步 | 模板的 `recursionLimit` 改为 100，并加单测检查下限（`500bf7a3`）。测试时在“助手设置”里把已创建助手的上限改成了 150，留出余量 |
| 往还在运行的会话里发分析指令时，指令会被排队 | 宿主的 `assistant.chat.send_message` 遇到运行中的会话会排队 | 每次分析都新开一个会话（`newThread`，`ea4dae20`） |
| 智能体中途停下后，任务一直处于运行中，只能等 3 分钟 | 没有手动结束任务的入口 | 新增视图动作 `abandon_analysis`（`dd25742e`） |
| 暗色主题下“已确认”徽标看不清；确认后看不出每条选了什么 | shadcn `secondary` 的底色和背景太接近；只读状态只是把按钮变灰 | 改用有边框和文字颜色的徽标；只读状态显示“已采纳/已驳回 + 备注”（`2e3e7d9b`） |

## 已知问题（未修复）

- **“工作台正在切换会话”提示不会自动消失**：点重试或 AI 分析时会新开会话，宿主在切换视图上下文的那一刻会拒绝工作台的请求。界面会等 0.8 秒自动重发一次；如果仍被拒，顶部显示“工作台正在切换会话，请稍后点‘刷新’”。在 `19`～`22` 截图里可以看到：之后的数据其实已经正常加载，但这条提示要等用户点“刷新”或下一次操作才会消失。改法是数据加载成功后清掉这条提示，这次没来得及做。

## 未验证的部分

- **列表为空时的引导语**：11-16 进入工作台后先点了“载入演示请求”，没有截到“还没有提前交货请求……”这句引导语。这句文案在 i18n 文件里，并有单测检查 i18n 键齐全，但没有截图证据。
- **多用户隔离**：只用一个账号测试过。代码按 tenant 和 organization 过滤，但没有用第二个用户或第二个组织实际验证过。
- **工作台刷新的触发方式**：分析完成后工作台会刷新，但没有区分是宿主的工具完成事件触发的，还是界面每 5 秒轮询触发的。读平台源码时只在 ClawXpert 会话页看到发布工具完成事件的代码，所以界面保留了轮询作为兜底。
- **其他系统和环境**：只在 Windows 11 + WSL2 Ubuntu 的 source-hybrid 模式下测过，没有测原生 Linux、macOS，也没有测 Docker 全量部署。
- **其他模型**：只用 DeepSeek 跑过。换其他模型时，工具调用顺序和递归上限是否够用，没有验证。
- **真实数据源**：库存、BOM、在途都是模拟数据，没有接任何真实的 ERP 或 MES。
- **浏览器自动化**：界面测试都是手工操作，没有写端到端脚本。
