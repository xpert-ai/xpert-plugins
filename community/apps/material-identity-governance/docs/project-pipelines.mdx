## 执行职责

物料主数据治理使用 `executionAuthority: platform`。在案例工作台点击“启动项目流水线”后，平台负责节点派发、并行与汇合、技术重试、取消、人工等待、轮次及执行记录。插件不再维护任务队列、轮询监督、后台续跑或投影同步日志。

业务流程：采集 → 图纸解析 → 标准化 → 身份比对 → 冲突审计与隔离建议 → 影响评估 → 治理方案 → 人工审批 → 发布。领域服务继续校验组织、案例、角色、当前修订和审批权限。Assistant 必须调用业务 finalizer 提交结果；仅模型执行成功不能使业务节点完成。

## 人工审批

工作台和资料卡的审批操作提交到平台当前人工门禁。平台保存决定及真实操作者，后续服务节点再将该决定幂等地写入业务记录。批准后继续执行，拒绝后停止本轮；Agent 不能代替人审批。审批期间案例修订或输入版本变化时，过期决定不能执行。

## 状态、重试和历史

平台是执行状态的唯一来源。业务页按需读取对应实例和轮次，显示实际失败、取消与执行句柄；插件只保存业务验收与不可变输出证据。重试、取消和历史轮次从项目流水线操作。

同一输入的技术重试保留轮次并产生新尝试。只有来源版本改变才启动新轮次；状态、工件及审批变更不作为新输入。旧轮次由平台保留，不把旧尝试重新归入当前节点。此应用当前的演示来源不可编辑，因此不会凭空制造下一轮输入；来源接入扩展需提供真正的新版本。

## 工作台与执行跳转

“项目流水线”入口在当前 Assistant 内打开案例对应 Project 的项目任务 Remote View，并选中流水线页签；无需进入平台 Project 管理页。平台执行记录跳转使用真实的 conversation / thread / execution。流水线的业务入口由宿主按保存的实例与业务对象重新鉴权解析，不接受 iframe 自选 URL 或 View。工作台及其子视图保留实例、轮次和节点参数以便返回；切换案例清除旧轮次，启动操作定位返回的新实例。历史页面进入的是当前业务事实。

## 本地验证与发布前提

本次新功能依赖配套 Xpert 宿主及 SDK 的 `ProjectEnsureResult.assistantBindings` 明确角色绑定结果。插件不以数组顺序或 Assistant 名称猜测执行者，也不保留旧 Provider 执行路径。发布时先发布对应 SDK 并更新两应用依赖锁定，再发布应用；当前本地构建使用该宿主的 SDK 产物。

新的 `pipeline_acceptance` 表记录原生流水线业务验收；本地旧执行表和案例数据保留，不由新代码读取为当前执行。外部系统仍为明确标记的仿真 / Mock，不代表生产设备或真实 MDM / ERP 已写入。

自动化检查覆盖原生配置、业务 finalizer、批准与拒绝、幂等、取消、作用域和不可变证据。真实 PostgreSQL 测试使用独立 schema，运行方式为设置 `PIPELINE_TEST_ENV_FILE=/absolute/path/to/test.env` 后执行 `pnpm test`。数据库测试与真实平台执行验收应分开记录。

插件不再注册独立的多部门治理流水线 View。管理监控进入业务工作台，证据与治理审批仍在插件内完成；启动或打开流水线使用项目任务的原生流水线。
