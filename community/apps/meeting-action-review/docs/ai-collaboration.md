# AI 协作与人工决策

本插件通过用户与 Codex 逐步讨论完成需求和开发设计，随后由 Codex 实现。使用的具体底层模型标识未从运行环境确认，不据此编造模型版本。

用户明确决定：不保存输入草稿、不逐行确认、分析期间允许看历史、移除后只撤销最近一次、确认后只读、不做派发。工作台参考智能维保的列表/详情布局，避免聊天旁再放三栏。

接受的技术方案：一个主 Agent、两个业务工具、服务端后台分析、两张业务表、原文片段引用、人工确认单独授权。评审后补齐列表轮询、响应未知恢复、字段统一、不可访问记录提示、启用步骤、预算与测试故障注入。

对 AI 建议的修正包括：按当前源码采用 tenant 级插件；不把 interrupted 当作失败；不假定 migrations 目录会自动执行；不把平台任务结束当作业务结果成功。实现中通过真实 PostgreSQL 验证事务与并发约束，通过构建页面测试发现并修复确认弹窗遮挡核实按钮的问题。

测试使用模拟模型/宿主的部分明确标识。随后通过正常登录，在用户的实际 Xpert 上完成了原生安装、模板发布、真实模型提取和浏览器主流程。联调发现并修复了包入口 default 导出、宿主默认分页参数、HTTP 下 UUID 生成，以及默认 View 缓存导致刷新读到旧数据的问题；这些问题没有被本地 mock 测试完全覆盖。

最终用真实页面完成新建、提取、增删改、依据定位、保存、刷新、直接确认最新修改和只读恢复，并通过授权 API 检查持久化结果。失败重试采用本助手临时输出预算限制制造无有效提交的失败，恢复预算后在同一会议上重试成功，没有修改全局模型提供器。


## 三段代表性协作

1. **选题与范围。** 用户要求针对面试完整交付，否定过于复杂或价值不明确的方向，最终选择行动项核对。逐步确认不逐行确认、不自动派发、确认后只读。收获是以可演示的业务闭环约束 AI 产出的功能范围。
2. **布局与真实接入。** 用户指出平台已有左侧聊天，插件再做三栏会拥挤，因此参考智能维保的列表/详情布局。真实部署又暴露 default 导出、HTTP UUID 和 View 缓存问题，分别用运行时加载、真实页面及持久化断言定位；本地模拟通过不能代替安装联调。
3. **会话同步边界。** 先核对公开会话导航、上下文事件和原生停止行为。用户决定只修改插件，放弃立即清空左侧和宿主级保护，保留“提交后同步、历史同步、插件内未保存保护”。实现后用 8 项 UI、11 项数据库测试和真实双栏切换核验；保存失败被弹窗遮挡的问题通过测试发现并修复。

工具为 Codex，配合 Xpert 开发技能、TypeScript、Vitest、Node test、Playwright 和 plugin-dev-harness。实际业务 AI 使用平台已配置的 deepseek/deepseek-v4-pro；这与开发助手底层模型不是同一个概念。用户完成了需求决策及手工验证，AI 执行实现和测试；不提交完整私有聊天记录，也不将自动化生成解释为免于人工理解代码。
