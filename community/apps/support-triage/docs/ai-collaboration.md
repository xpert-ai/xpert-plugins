# AI 协作记录

本次使用 Codex 开发工具，由 GPT-6 系列代理协作完成需求拆分、源码核对、实现和验证。候选人提出按公司任务书完成应用，并明确确认“客服工单分流与回复审核台”选题、本地部署路线和兼容 OpenAI 的模型 API 来源。以下记录区分候选人选择与工具执行，不把代理完成的实现描述成候选人独立编写。

## 需求与范围

先完整读取任务书，提炼最低门槛：一个用户、一条业务流程、可操作界面、一次真实 AI 处理、保存恢复、失败重试及 PR。Codex 提议客服工单场景，候选人确认后开展实现。选择人工审核闭环，暂不扩展自动外发或多智能体。

## 源码与并行实现

先获取 Xpert 与插件仓库 main 的固定 SHA，读取官方技能及实际 SDK 类型。后端和前端围绕共享 TypeScript DTO 并行实现；环境检查单独进行。参考现有应用的注册、上下文、视图、模板和宿主命令模式，重新实现工单领域行为。

## 调试过程

GitHub 直连遇到连接重置，Codex 使用官方 API 和源码归档读取，再通过本机已运行的代理恢复 Git 克隆。没有把归档初始化伪装成上游 Git 历史；最终平台与插件基线可由 Git 验证。

环境检查发现当前机器未安装 WSL/Docker，并发现官方 source-hybrid 脚本依赖 Unix 工具。将平台部署安排在 WSL2，插件代码和测试先在 Windows 独立完成。真实平台和真实模型验收以实际结果为准，不能由本地模拟测试替代。
