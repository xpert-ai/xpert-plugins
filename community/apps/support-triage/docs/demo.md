# 面试演示与讲解

## 五分钟演示路线

1. **30 秒说明问题**：面向小型 SaaS 团队客服，减少重复整理，同时保留人工审核。
2. **录入工单**：客户代号“演示客户 A”，标题“重复扣费且无法下载发票”；使用下方合成原文。
3. **真实 AI 分析**：点击分析，展示 Xpert 助手调用工具后，工作台出现摘要、分类、证据、待补信息和回复草稿。确认这是配置的模型实际执行结果。
4. **人工审核**：检查证据，修改回复措辞，点击确认并保存。解释模型没有确认权限。
5. **刷新恢复**：刷新 Xpert 页面并重新打开工单，核对最终回复、状态和确认时间。
6. **失败重试**：新建另一条工单，在测试环境制造模型连接失败；展示失败状态，恢复配置后重试，确认工单数量不增加、旧任务不能覆盖新结果。

合成输入：

> 我们是演示客户 A。昨天升级团队版时页面一直转圈，我又点了一次支付，今天看到两笔相同金额的扣款。后台仍显示基础版，发票页提示“订单处理中”，下载按钮不可用。请帮忙确认是否重复扣费，以及何时能使用团队版。我们明天上午要给团队演示，还没有把订单号发给你们。

预期检查点：不能编造订单号或退款处理结果；应指出需要核对支付记录及订单信息；草稿不能承诺未经批准的退款到账时间。分类、优先级存在判断空间，最终由客服确认。

## 三分钟技术讲解

前端是 Xpert Workbench Remote View，通过宿主桥接读取工单和执行动作。服务端使用 NestJS 插件、TypeORM 持久化和受限 Agent 工具；Assistant 模板预置提示词和能力绑定。

点击分析先创建服务端任务，再通过宿主允许的 `assistant.chat.send_message` 命令交给当前助手。模型使用读取工单、提交分析或报告失败工具。工具结果进入数据库，工作台通过事件和刷新读取同一份业务状态。

关键设计是三种标识各司其职：业务工单 ID 定位记录，attemptId 区分每次 AI 尝试，revision 防止陈旧页面覆盖新数据。确认操作只开放给人工界面。

## 常见追问

**为什么不是普通聊天框？** 用户操作的是有状态的工单；建议和最终回复分别保存，有表单、列表、审核、恢复和重试。

**为什么不让 AI 自动发送？** 当前产品价值是减少整理与起草负担，外发会引入新的账号接入、误发和业务承诺问题，超出最小闭环。

**AI 引用了真实原文，是否就可靠？** 不是。引用存在不代表推断正确；还需要人工检查，后续可增加针对业务规则的评估集。

**重复点击或超时会怎样？** 请求标识和状态约束防止重复业务写入，attemptId 拒绝旧结果，revision 检测冲突，超时可进入恢复流程。

**为什么按用户隔离？** 本版本面向单客服，不做跨成员共享。身份范围来自宿主，减少额外权限模型；团队协作需另行定义角色和可见性。

**哪些测试不能替代真实平台验收？** SQL.js 测试不等于生产数据库验收；harness 的模拟宿主不证明登录权限和模型可用；界面模拟不证明真实 AI。应分别报告。

**最值得继续改进什么？** 优先补真实场景评估和人工修改反馈，再考虑团队分派或客服系统接入。
