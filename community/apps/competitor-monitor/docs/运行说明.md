# 运行说明

本文件说明实际实现、依赖配置、构建安装与使用方式。核心调用链见 [核心代码导读](核心代码导读.md)。

## 业务界面与接口实现

`src/remote/index.html` 是宿主 iframe 中的工作台，包含商品、轮次、证据、建议审核和数据清理。通过宿主 `requestData` 查询数据、`executeAction` 调用动作、`invokeClientCommand` 发起助手消息；不直接持有 API 密钥。`src/lib/view.provider.ts` 注册视图与动作，使用宿主上下文中的租户、组织调用服务。

## 业务逻辑、数据处理与智能体

| 文件 | 实现 |
| --- | --- |
| `src/lib/service.ts` | Mock 采集、历史快照比较、幂等键、失败次数、同轮恢复、建议保存及审核版本校验 |
| `src/lib/entities.ts` | 商品、轮次、快照、变化和建议；每条数据包含租户与组织范围 |
| `src/lib/deletion.ts` | 选择与范围校验、关联数量、数据摘要确认、事务级删除及回滚 |
| `src/lib/middleware.ts` | 五个 Agent 工具、参数约束与模型失败记录 |
| `src/lib/templates.ts`、助手 YAML | 模板注册、助手节点与中间件连线 |
| `src/index.ts`、`plugin.ts` | 插件元数据、配置 schema 和 Nest 模块装配 |

工具为 `monitor_get_round_changes`、`monitor_record_change`、`monitor_create_advice`、`monitor_report_analysis_issue`、`monitor_finish_analysis`。建议以操作标识及变化类别防重复；人工审核按 revision 更新，过期版本不能覆盖新结果。分析在途标记由数据库保存；未完成分析会阻止删除。

## 依赖配置与复用来源

运行依赖采用平台提供的 NestJS、TypeORM、Xpert Plugin SDK／Contracts、LangChain 和 Zod。SDK 放在 peerDependencies，避免插件内再携带独立 SDK 实例。开发测试使用 TypeScript、tsx、Node test runner 和 SQL.js，具体版本见 `../package.json` 与 `../../../pnpm-lock.yaml`。

复用平台的模块注册、View Provider、宿主桥接、中间件工具和助手模板契约；NestJS/TypeORM 提供注入与数据库操作，LangChain/Zod 提供工具定义与输入校验。界面目前为原生 HTML/CSS/JS，未使用共享 shadcn 组件，不将其描述为已完成最新 UI 规范迁移。

插件配置 schema 当前是严格空对象 `{}`，不需要额外业务配置文件。模型与模型凭证在 Xpert 平台中配置；本地部署账号凭证不属于插件配置。新增可空列 `analysisStartedAt` 需要宿主正常完成实体 schema 同步，不能仅凭编译通过认定目标数据库已升级。

## 构建、安装与启动

以下路径变量均为示例，请替换为自己的检出目录和测试租户；凭证仅在本地配置。

```bash
export XPERT_HOST_DIR="$HOME/xpert-dev/xpert"
export XPERT_PLUGIN_REPO="$HOME/xpert-dev/xpert-plugins"
export XPERT_API_URL="http://localhost:3000"
export XPERT_TENANT_ID="<测试租户 UUID>"
```

分别按仓库说明准备依赖：

```bash
cd "$XPERT_HOST_DIR"
corepack pnpm install --frozen-lockfile

cd "$XPERT_PLUGIN_REPO/community"
corepack pnpm install --frozen-lockfile
corepack pnpm --filter @community/apps-competitor-monitor build
corepack pnpm --filter @community/apps-competitor-monitor test
corepack pnpm --filter @community/apps-competitor-monitor verify:dist
```

部署脚本须在 API 已运行时使用。认证采用已配置的 macOS 钥匙串，或宿主脚本支持的本地进程环境变量 `XPERT_USERNAME` / `XPERT_PASSWORD`；不在 README、截图或仓库中填写真实凭证。

```bash
cd "$XPERT_HOST_DIR"
corepack pnpm plugin:deploy:local \
  --plugin-dir "$XPERT_PLUGIN_REPO/community/apps/competitor-monitor" \
  --force-install \
  --scope tenant \
  --tenant-id "$XPERT_TENANT_ID" \
  --api-url "$XPERT_API_URL"
```

出现 `installed and staged successfully` 后，在原 API 终端停止旧进程再执行：

```bash
cd "$XPERT_HOST_DIR"
corepack pnpm start:api
```

前端按宿主运行说明启动，并访问 4200 平台。不要同时启动两个 API 进程。部署后的模板创建与助手发布仍需独立完成；本项目不需要 npm 发布。


### 首次配置 macOS 钥匙串

在本地终端替换用户名占位值；第二条命令交互输入密码，不把密码粘贴到 README。

```bash
security add-generic-password -a "$USER" -s xpert-local-plugin-username -U -w "<Xpert 登录用户名>"
security add-generic-password -a "<Xpert 登录用户名>" -s xpert-local-plugin-password -U -w
```

非 macOS 环境按宿主部署脚本支持的本地认证方式配置。账号必须具有目标租户的插件安装权限。数据库、缓存及前端启动仍按所选宿主版本 README 配置，不把一个猜测的前端脚本当作通用命令。

## 使用步骤

1. 安装后重启 API，打开 4200 平台并确认插件已加载。
2. 选择竞品分析助手模板，选择工作空间和已配置模型，安装并发布。
3. 核对助手与竞品监控中间件连线及五个工具；打开工作台。
4. 添加 `6543210` 无线蓝牙耳机，首次建基线，第二次采集产生三类变化。
5. 点击“交给 AI 分析”，等待建议保存，人工采纳或驳回。
6. 刷新并重新选择原轮次验证保存；再次分析不应重置审核状态。
7. 在异常测试区填写 `6543210` 触发超时，清空故障输入后使用失败轮次的“重试”。暂停后先恢复原轮次再重试。
8. 如需清理，使用底部数据管理，核对关联数量后输入“删除”确认。

可重复 Mock 场景见 [README 商品清单](../README.md#mock-采集规则)。必要测试、命令和实际结果见 [测试报告](测试报告.md)。截图与六步证据见 [README](../README.md#六步操作与截图验收)。
