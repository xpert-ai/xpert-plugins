1. 产品与运行范围

旺旺竞品监控用于监控商品价格、标题和促销变化，由服务端计算确定性 diff，Assistant 读取证据并保存建议，运营人员采纳或驳回。

本手册以本地 Xpert 插件为准。数据采集为 Mock，不访问淘宝；平台中的模型调用与业务保存是真实运行。独立双击演示版使用浏览器存储及模拟分析，不能作为平台验收证据。

平台入口：http://localhost:4200/；API：http://localhost:3000。

2. 核心操作流程

  1. 进入已绑定竞品监控中间件的 Assistant，打开“竞品监控”工作台。
  2. 输入商品 ID 和标题，点击“添加监控”。确认商品为 监控中；“暂停监控 / 恢复监控”按钮会切换状态，不是开始采集按钮。
  3. 点击“执行采集”。新商品首次只建立基线，不产生变化。
  4. 再次点击“执行采集”，查看价格、标题或促销变化。
  5. 点击“交给 AI 分析”，或目标轮次的“分析此轮次”。分析已有轮次不会重新采集。
  6. 核对建议及证据，点击“采纳”或“驳回”。
  7. 刷新后确认记录与审核状态保留，再分析同一轮验证不重复创建、不重置审核。
人工采纳仅代表审核通过。不会自动修改淘宝商品、价格或促销。销量、流量、我方价格优势等推断没有当前 Mock 数据支持，应标记为待验证假设。

4. 超时、同轮重试、暂停与恢复

一次超时 → 成功重试

  1. 确认 6543212 为 监控中。
  2. 在“模拟超时商品 ID（本次生效）”填写 6543212，点击顶部“执行采集”。
  3. 预期轮次为 采集失败，并展示“模拟数据源超时：6543212”。
  4. 保持故障输入为空，点击该失败轮次的“重试”。
  5. 预期同一 roundId 恢复为 采集成功，不新增轮次。

连续三次失败 → 暂停 → 恢复

  1. 填写 6543212，点击“执行采集”，产生第一次失败。
  2. 重新填写 6543212，点击原轮次“重试”，产生第二次失败。
  3. 再次填写 6543212，点击原轮次“重试”，产生第三次失败。
  4. 确认轮次和目标商品均为 已暂停，轮次提供“恢复采集”。
  5. 清空故障输入，点击轮次的“恢复采集”，商品恢复为 监控中。
  6. 点击同一轮次的“重试”，确认 采集成功；刷新核对状态保留。
故障输入每次操作后自动清空。连续失败测试必须重新填写。三次失败是首次采集失败加两次重试失败；重试时不要点击顶部“执行采集”，否则会创建新轮次。恢复应使用轮次的“恢复采集”，而非仅切换商品状态。

其他手动暂停商品应保持暂停。模型失败属于分析阶段异常，不等同于采集超时；应保留已有证据，并检查工具返回后重新分析原轮次。

8. 本地构建、部署与重启

仅测试业务逻辑不需要部署；要在 localhost:4200 使用修改后的插件，需让 API 加载新产物。本地部署不等于公网发布，无需 npm 发布。

cd /Users/jared/xpert-dev/xpert-plugins/community
nvm use 24
corepack pnpm --filter @community/apps-competitor-monitor build
corepack pnpm --filter @community/apps-competitor-monitor typecheck
corepack pnpm --filter @community/apps-competitor-monitor test
corepack pnpm --filter @community/apps-competitor-monitor verify:dist

保持 API 运行。先在本地安全配置登录凭据，并设置 XPERT_TENANT_ID；不要将密码或 Token 写入手册、提交仓库或发送到聊天。

cd /Users/jared/xpert-dev/xpert
corepack pnpm plugin:deploy:local \
  --plugin-dir /Users/jared/xpert-dev/xpert-plugins/community/apps/competitor-monitor \
  --force-install \
  --scope tenant \
  --tenant-id "$XPERT_TENANT_ID" \
  --api-url http://localhost:3000

--force-install 明确使用本次指定源码目录；默认 refresh 可能使用之前保存的路径。收到 staged / restart required 后，在 API 终端停止并重新执行 corepack pnpm start:api；若原先使用 corepack pnpm start 启动前后端，仍用该命令重启。最后刷新页面。

如果 fetch 采集失败，先启动 API 并检查 curl -i http://localhost:3000/api/health。如果未发现凭据或 tenant-id 为空，先补本地配置；反复重启不能解决认证问题。

数据管理：单条、批量删除与清空

展开工作台底部“数据管理 · 删除与清空”，选择监控商品、采集记录、变化记录或运营建议。点击一条记录的“删除”，或勾选多条后点击“删除已选记录”。“全选当前列表”只选中已加载记录；“清空当前组织全部数据”覆盖全部历史数据。

服务端先显示实际删除数量（包含关联数据），输入“DELETE”后确认永久删除，也可取消。删除商品会同时删除其快照、变化和建议，保留历史轮次；删除轮次会删除其快照、变化和建议；删除变化会删除对应建议。单独删除建议后，再分析可能重新生成。

仅操作宿主上下文中的当前组织，缺少组织时拒绝执行。采集或分析中禁止删除；确认后数据发生变化时，需要重新确认。所有删除处于同一事务，失败时回滚。中断分析需重新分析完成或上报失败后再清理。

本次已通过 SQL.js 数据隔离、关联删除、事务回滚及运行中拦截测试，并在模拟预览验证单条删除、取消、批量删除和一键清空。已取得真实平台数据管理确认界面截图；尚无真实删除完成证据。当前并发保护面向单 API 进程；多实例部署需要数据库级统一业务锁。

10. 权限测试与交付清单

最小六步示例不要求多用户测试；附录二完整验收要求验证适用的权限与数据范围。可以暂缓，但应明确标注“未验证”，不能标记全量验收通过。

  1. 准备两个普通应用账号 A/B，各自仅属于组织 A/B；APP_USER 仍需目标 Assistant 的使用权限。
  2. A 使用固定清单商品 ID 创建仅组织 A 的采集结果，B 不应看到这些数据。

  4. 邀请未收邮件时，检查自定义 SMTP 或环境 MAIL_* 参数；创建邀请记录不等于成功发送邮件。
