# 合同智能体检 — 需求与验收

## 1. 目标用户

| 角色 | 画像 | 核心诉求 |
| --- | --- | --- |
| 老板 / 创始人 | 10–100 人公司负责人 | 签合同前知道风险在哪 |
| 销售负责人 | 客户模板五花八门 | 快速判断客户模板能不能用 |
| 行政 / 商务 | 负责走合同流程 | 把风险整理清楚给老板看 |

## 2. 原有工作方式与痛点

- 现状：老板自己通读合同 → 看不懂就跳过或微信问人 → 出事才发现条款不利 → 偶尔请律师（500–2000 元/份），低频黑盒。
- 痛点：无专业能力、审查慢靠记忆、风险不可见不可追溯、成本高不可复用。

## 3. 业务流程

```
新建体检(录入合同) → 开始体检 → AI 四环节(抽取→审查→改写→摘要)
   → 查看风险与改写建议 → 逐条确认(接受/忽略/自定义) → 保存报告 → 历史记录恢复
```

状态机：

```
draft → processing → needs_review → completed
                    ↘ failed → (retry 单环节) → processing
```

## 4. 关键页面

1. **录入页**：合同名称、类型、正文；正文过短/为空时阻断并提示。
2. **报告页**：总体评分、按等级排序的风险清单、每条改写建议、逐条确认按钮、保存报告。
3. **历史记录页**：列表 + 评分 + 状态（含"体检失败 → 重试"入口）。

## 5. AI 的作用

| 环节 | Agent/工具 | 产出 |
| --- | --- | --- |
| 抽取 | `contract_save_extraction` | 要素 JSON |
| 审查 | `contract_save_risk_items` | 风险清单（等级/条款/问题/依据） |
| 改写 | `contract_save_suggestions` | 可替换条款表述 |
| 摘要 | `contract_save_summary` | 评分 + 一页式摘要 |
| 异常 | `contract_report_failure` | 失败环节与原因 |

## 6. 功能取舍

**本期完成**：单合同体检闭环、逐条确认、持久化保存与恢复、失败重试（幂等）、输入校验与空状态。

**按需延后**：多合同对比、模板库、电子签集成、多组织复杂权限、多智能体治理看板。

## 7. 验收标准

| 场景 | 操作与通过标准 | 实现层 |
| --- | --- | --- |
| 完整流程 | 录入 → AI 处理 → 查看 → 确认 → 保存，界面/状态/结果一致 | 数据与动作链路已实现；界面渲染待平台验证 |
| 保存与恢复 | 刷新或重进应用能恢复原记录与结果 | 已实现（TypeORM 持久化 + reviewId 查询） |
| 输入与空状态 | 缺必填项/无数据时有清晰提示 | 已实现（单元测试覆盖） |
| 失败与重试 | 模拟模型失败 → 可理解原因 → 重试不重复产生结果 | 已实现（单元测试覆盖幂等） |
| 权限与数据范围 | 多组织隔离，无权限不能读他人数据 | 已实现（单元测试覆盖隔离） |

## 8. 已知限制

- 仅中文合同、单文档；无行业细分风险知识库。
- 改写建议为草案，需人工或律师确认。
- 工作台远程组件界面需在平台侧验证渲染。
