# 产品说明 · 简历初筛工作台

> 依据：功能 spec v2.4（`docs/spec/resume-screen-spec.md`）与 UI 设计蓝图 v4.3（本目录 `ui-design.md`）。本文件只写已实现的事实。

## 1. 目标用户

招聘专员 / HRBP / 用人经理——每天要处理一批简历、对照某个岗位 JD 做第一轮去粗取精的人。

## 2. 原工作方式与痛点

- 逐份打开简历（Word/PDF），人眼扫一遍，对照 JD 手工记笔记；
- 横向对比靠 Excel 或聊天记录，每个人手里的标准不一致；
- 同一批简历反复看、重复劳动，高分候选容易被埋没，信息缺口靠经验补。

## 3. 业务流程（JD → 提交 → AI → 处置）

```
① 建岗位：工作台「新建岗位」Dialog 录入岗位名称 + JD 正文（可存多条，头部 Select 切换当前岗位）
② 提交简历：底部录入区多选上传 .docx / .pdf → 逐文件走 transport:'file' 字节通道 →
   服务端校验 + 文本解析 + 落库候选人（status=parsing，记 sourceFileName，dedupeKey 幂等）
③ AI 处理：落库即自动入队 managed-queue，同进程 worker（逻辑并发 3）逐份组装「JD+单份文本」
   prompt 直调 deepseek 模型，结构化抽取（姓名/年限/学历/最近公司/技能/摘要）+ 0–100 匹配分
   + 理由 + 命中点 + 风险点，回填后 status=pending_review；列表以 30s 心跳呈现进度
④ 人工处置：右详情查看抽取字段与评分理由 → 推进 / 待定 / 淘汰 / 撤回为待审；
   抽取错的字段点「编辑」人工修正（乐观锁防并发覆盖）；处置成功后详情自动滑向下一条待审
⑤ 保存与恢复：全部结果落 Postgres（plugin_resume_screen_* 表），刷新或重进应用仍在
```

失败与重试贯穿其中：单条失败标 `failed` + 可读原因，「重试」= 服务端重新入队，**同一条记录不重建**。

## 4. 关键页面原型

布局/交互/视觉以蓝图 v4.3 为唯一依据，此处只给索引（均在 `ui-design.md`）：

- 方案 A：双栏 master-detail（左 320px 列表 + 右详情常驻）+ 顶部岗位/统计条 + 底部可折叠录入区；宿主容器 <720px 时右详情降级为 Sheet 抽屉 —— §2 / §3 / §4
- 候选人六态徽标（解析中 / 待审 / 推进 / 待定 / 淘汰 / 失败，色板 §8）—— §3.4 / §6.2
- 交互状态机（上传队列、失败重试、解析超时提示、乐观锁冲突恢复）—— §6
- 视觉基线：全量对齐 crm-workbench token + smart-maintenance 徽标模式，组件只用 `@xpert-ai/plugin-shadcn-ui`，图标只用 remixicon —— §1 / §5 / §9

运行入口：工作台是助手**对话工作区的固定视图 tab**（注册在 `agent.workbench.fixed` 槽）；`main` 槽仅供 studio 编辑器消费。iframe 内不持有任何 token / tenantId / organizationId，身份由服务端从宿主上下文解析。

## 5. AI 的作用与边界

- **作用**：抽取结构化字段、按当前 JD 打 0–100 匹配分、给出可核对的理由与命中/风险点——替代人工逐份阅读初筛。
- **边界**：AI 只做抽取评分给理由，**不替人做录用决策**。推进/待定/淘汰/撤回/编辑字段等不可逆或裁量动作不在模型工具面，只由人在工作台点击；评分阈值仅作界面提示，绝不触发自动推进。
- 展开见 `ai-collaboration.md`。

## 6. 功能取舍

**本期做**：岗位录入与切换、.docx/.pdf 批量上传、AI 抽取评分、列表筛选/搜索/排序 + 详情、人工处置与字段修正、落库恢复、单条失败重试（幂等）、分层测试（jest + 构建检查 + harness）。

**本期不做（取舍与理由）**：

| 不做什么 | 理由 |
| --- | --- |
| 图片 / 扫描件 PDF / .doc 旧格式解析 | 需引入 OCR；解析失败引导转存 Word/文本层 PDF 重传 |
| 简历去重（同名不同人） | 语义去重成本高，只做精确文本 `dedupeKey` 幂等 |
| 面试安排 / 邮件 / ATS 对接 | 超出初筛环节，且涉及外部系统凭证 |
| 多用户协作与角色权限细分 | 演示与落地以 tenant/organization 隔离为限 |
| 面试评价 / offer 流程 | 后续环节，另立插件 |
| i18n 完整化 | 中文优先，英文保留最小集 |
| 上传队列台账服务端持久化 | 台账为前端内存态（刷新丢失，`sourceFileName` 可溯）；不为此重开已冻结的真机复验后端链路 |
| 粘贴文本录入口 | v3 决策彻底移除，上传为唯一录入口；对话内贴文本仍走旁路 |
