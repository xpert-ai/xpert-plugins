## 配置

| 配置项 | 值 | 默认值 | 说明 |
| --- | --- | --- | --- |
| `mode` | `simulation`、`external` | `simulation` | 执行适配模式 |
| `debug` | boolean | `false` | 启用脱敏的插件与 Remote View 调试日志 |

## 可观测性

Agent middleware 中的每个写工具通过 Xpert `ON_TOOL_MESSAGE` 发送运行、成功和失败状态。消息只包含工具名、Case 标识、修订和变更摘要；租户、组织、令牌和密钥会被过滤。

原生 MCP 直接调用装饰器注册的共享业务方法，不经过 Agent middleware 的 `wrapToolCall`，因此不承诺发送上述 Agent 进度事件。业务写入、`operationId` 幂等、修订冲突和审计均由共享服务层保证；MCP Publication 还保留宿主协议审计。

## 常见错误

| 错误码 | 原因 | 处理方式 |
| --- | --- | --- |
| `factory_revision_conflict` | Case 已被其他 Agent 或用户更新 | 重新读取 Case，使用最新修订重新评估 |
| `factory_operation_payload_conflict` | 相同 operationId 被用于不同载荷 | 生成新的 operationId；只对完全相同的重试复用旧值 |
| `factory_case_project_not_ready` | Case Project 尚未就绪 | 由原创建者重试 Project 同步，确认角色 Assistant 已发布且绑定无歧义 |
| `factory_case_project_retry_forbidden` | 非 Case 创建者尝试重试 Project | 由创建者重试，或先按组织治理流程处理所有权 |
| `factory_plan_not_approved` | 试图执行未审批方案 | 在 Workbench 审批当前修订的方案 B |
| `factory_external_adapters_unconfigured` | 外部模式没有生产系统适配器 | 配置真实适配器，或明确切换回仿真环境 |
| `factory_execution_incomplete` | 执行确认不完整 | 检查失败动作并转人工干预，不得伪造确认 |

## 项目流水线恢复与取消

任务由平台原生项目流水线派发与监督。失败重试、取消、超时和历史轮次都在项目流水线页处理；插件不维护第二套 Queue 或续跑 Worker。重试生成新的平台执行尝试，历史尝试保持可查。平台状态未知时不推断业务已完成。

排查时关联 Case、流水线实例、轮次、节点、operation 和实际 Agent execution。业务 finalizer 只有匹配平台准备的执行身份与输入版本才会接受结果；模型任务完成不能代替业务成果。

## 人工审批与恢复

Profile 和业务 Workbench 的审批都提交到同一个平台人工关口。批准后平台调度审批落账、受控执行和恢复验证；拒绝后进入人工处理。权限撤销、方案变化或外部适配器缺失时先处理原因，再通过项目流水线重试，不能沿用过期审批。

模拟模式只生成模拟确认。外部模式缺少真实适配器时明确失败，不自动降级。

## 数据与发布

新执行接收记录使用 `plugin_factory_ops_pipeline_acceptance`，保留原业务数据和历史记录。上线前备份并检查新增列与表；本次接入不要求清空既有 Case、Project 或用户数据。宿主 SDK 与插件需协调发布，见[项目流水线](/product/features/project-pipelines)。

多个本地 checkout 共用 Redis 时，为各 API 配置不同的 `MANAGED_QUEUE_PREFIX`，避免其他版本的 Worker 消费当前任务。生产副本使用同一前缀。
