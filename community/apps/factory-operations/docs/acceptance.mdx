## 功能验收

- M-07 事件显示 8.7 mm/s 振动、86.4°C 温度、3 张工单、126 件产品和 2 个风险订单。
- 异常研判完成后，四个专业 Agent 可以并行完成且不会覆盖彼此工件。
- 方案 A 延期 210 分钟；方案 B 增加 1,800 元且不延期；方案 C 显示不可接受风险。
- 未审批时执行必须失败；Agent 无审批或执行工具。
- 审批记录包含用户身份、理由、时间和修订。
- 仿真执行恰好生成 12 个明确的模拟确认。
- 恢复验证包含 IoT、QMS、MES 三类证据，并将 Case 关闭为 `recovered`。
- Remote View 在宿主主题切换、工具完成事件和刷新后保持一致。
- 泳道和 Factory Case 任务工作区显示平台 Assistant 绑定返回的真实头像，并统一为圆角方形；模板 Emoji 使用平台可解析的标准 `id/unified`，插件不得通过私有 ID 映射伪造头像。选择角色后整条泳道具有选中样式，Escape 可清除。
- 顶部任务上下文合并为单行；状态、下一项受控动作、恢复进度与主操作常显，次要 Case 元数据通过可聚焦的 shadcn `HoverCard` 展示。
- `factory-case-workspace` 在 `agent.workbench.fixed` 插槽可解析，任务导航保留 `selectionId`、`caseId` 与 `nodeKey`，并可返回同一 Case 的流水线。
- 新建两个 Factory Case 得到两个不同、非空且唯一的 Xpert Project；Project owner 均等于对应 Case 创建者。
- 每个 Case Project 恰好连接当前 Orchestrator 与八个已发布角色 Assistant；模板全部为 `project-required`，管理 Assistant 除外。
- Case 切换先保存 Workbench 选择，再切换 `assistant.project`；ChatKit 与 Workbench 的运行 Project 等于 `workspaceProjectId`。
- 单角色和四角色并行 Assistant Task 的文件范围均为 `catalog=projects`、`scopeId=workspaceProjectId`，不同 Case 的文件互不可见。
- Project `failed` 时仅原创建者可重试；Project 未 `ready` 时不能启动 Assistant Task。
- 重复 operation 不重复排队；revision 冲突不启动任务；排队和已启动任务分别通过 Queue 和 Assistant Task 取消。
- 平台任务成功但未调用业务 finalizer 时不推进 Case；执行记录仍可恢复并保留 Project、task、conversation、thread、execution 与 executor 元数据。
- 插件不包含 `@xpert-ai/plugin-shadcn-ui` 或 `@xpert-ai/shadcn-ui` 跨项目链接；shadcn 组件由当前仓库 CLI 安装，图标来自本地 `lucide-react`。
- 插件详情 Dialog 无需 manifest `toolsets` 条目即可发现 `factory_ops` 与 `factory_ops_insights` 两个运行时 Provider；前者恰好包含 7 个幂等且不可逆的写 Tool，后者恰好包含 5 个安全只读 Tool，合计 12 个且名称不重复。
- `factory_cases_search` 只在调用时组织作用域内按 Case 编号或设备编号查询，分页上限为 50，返回结果不包含完整证据、时间线或内部实体字段。
- 两个自动管理的 MCP Publication 均完成 `initialize` 与 `tools/list`；只读洞察 Publication 还完成 `factory_operations_dashboard_get` 的 `tools/call`，调用结果包含紧凑文本和结构化看板 DTO，并生成协议审计记录。
- MCP Tool 列表不包含方案审批、驳回、执行、演示事件创建或批量演示分析；这些能力继续受现有用户治理边界控制。
- 源 YAML 与构建产物完全一致；插件包不包含 TypeScript 源码或用户数据。

## Assistant Profile 与后台续跑（0.5.0）

- 侧栏展开、折叠和聊天页头使用共享资料卡；原导航保持可用，资料入口不同时显示 Tooltip。
- 350 ms 打开、300 ms 关闭延迟；跨间隙、iframe 焦点、触屏点击、键盘、Escape 焦点恢复、视口边缘、窄屏和深浅色均验收。
- 基本资料、tabs 固定，内容独立滚动；扩展失败局部重试；已访问 tab 缓存 iframe，隐藏时暂停轮询，切回不立刻重复查询；切换 Assistant 或关闭时丢弃旧响应并释放缓存。
- “待处理”只包含待审批、阻塞或失败的续跑，以及尚未被成功重试覆盖的执行失败；已被 `supersededByRecordId` 标记为替代的历史失败不得继续占用待处理列表。详情明确显示处理方式与权限要求，按钮、弹窗、标签和间距采用紧凑规格。
- Feature 移除后不能读取或执行该 View；未声明 action 被宿主拒绝。
- 同角色实例互不混淆；发布版本参与记录可识别；跨租户、跨组织、无 Project 权限不可读取或通过 selection 绕过。
- owner / manager 可以审批，editor / member 与 Agent 工具不能审批；原 Workbench 入口使用同一规则。
- 取消不产生动作，拒绝有原因；旧版本失败；重复请求保持相同 operation ID 和内容。
- 审批及续跑意图同事务写入；入队失败、服务重建、检查点重放、权限撤销和外部模式阻塞均覆盖。
- 真实验收使用独立模拟案件：批准后关闭卡片，核对后台验证 Assistant Task、业务 finalizer、最终状态和审计。平台 Task 成功但没有 finalizer 不得标记恢复。
- 只从唯一 requester 历史回填协调者，歧义记录保留待修复；续跑使用案件协调者而非当前 Profile 的专业 Assistant。

可选真实 PostgreSQL 集成测试（使用独立测试库，测试自行创建并释放独立 schema）：

```bash
FACTORY_PROFILE_TEST_ENV_FILE=/absolute/path/to/test.env corepack pnpm exec vitest run src/lib/factory-profile.postgres.spec.ts
```

`test.env` 使用 `DB_HOST`、`DB_PORT`、`DB_NAME`、`DB_USER`、`DB_PASS`。测试中的平台 Assistant Task 边界是替身；此结果不能替代真实 Task 验收。Profile 的浏览器测试使用 UI fixture，覆盖 opaque-origin iframe、确认/取消、失败重试、中英文、窄屏和关闭后停止轮询。

### 本地验证记录（2026-09-03）

- 0.5.0 已通过平台本地刷新流程安装，API 重启后运行时状态为 `loaded`。
- 蓝图验证、后端与 Remote View typecheck、31 项单元/既有集成测试、8 项独立 PostgreSQL 测试、5 项浏览器测试、构建及生成资源一致性检查通过；生命周期 harness 可加载并正常关闭插件。
- 在真实平台中新建独立模拟案件，由实际协调与专业 Assistant Tasks 形成方案；人在资料卡批准后立即关闭卡片，后台继续执行 12 项模拟确认并派发真实验证 Assistant Task，最终 Case 为 `recovered`、修订 10、续跑记录为 `completed`。
- 审计依次记录人类批准并续跑、方案执行及 Agent 恢复验证；验证记录包含平台 Task、会话、线程、执行和协调者/执行者标识。
- 故障注入的队列恢复、服务重建、权限撤销和外部模式阻塞使用独立数据库测试；不会据此宣称完成生产系统操作。

当前版本依赖配套平台的 Profile contracts 与 Project access runtime capability。对外发布插件前，应先发布包含这些能力的 SDK/contracts，并更新插件的最低兼容版本。
