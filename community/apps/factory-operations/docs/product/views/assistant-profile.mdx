---
title: 'Assistant 资料卡'
description: '查看实例负责的 Factory Case，并审批后后台续跑'
---

在侧栏 Assistant 入口悬停或点击资料按钮，打开资料卡。顶部固定显示 Assistant 资料，下方“基本信息”“最近案件”“待处理”在同一卡片内切换。聊天页头也提供入口。

## 案件归属与查看权限

“最近案件”按更新时间倒序展示每页 10 条 Factory Case，包含设备、严重度、进展、最近变化和下一步。点击案件进入卡内详情，查看方案、证据和执行情况。

案件归属取 Case Project 明确分配与执行记录 requester / executor 的并集，包含同一 Assistant 的发布版本；同名或同角色的另一实例不会自动获得案件。后端先应用租户、组织、Project 可读权限和实例归属，再分页与统计。

“待处理”包含待审批、续跑阻塞或失败，以及仍未结束且有失败执行记录的案件。Project 可读成员可以查看；只有 owner / manager 可以审批。Agent 工具和 editor / member 不具备人类审批权。

## 批准并继续

1. 在待审批 Factory Case 中点击“批准并继续”。
2. 核对当前方案、Case 修订、方案修订、执行范围以及模拟或外部模式。
3. 填写意见并确认。拒绝必须填写原因，取消不产生动作。
4. 审批成功后，后台执行已批准方案并通过案件协调 Assistant 派发恢复验证 Task。
5. 只有匹配的业务 finalizer 确认恢复、证据和执行记录均已保存，案件才成为 `recovered`。

审批和续跑意图在同一事务中持久化。关闭资料卡、刷新页面和 API 重启不会丢失已批准工作；队列暂时不可用时，后台补偿调度。重复提交使用相同 operation ID 和内容，不重复执行。

现有 Workbench 的“批准方案”仍只审批；“批准并继续”是新增组合动作。两种审批入口共享 owner / manager 校验。

## 停止与重试

续跑每一步都检查原审批人权限、审批版本、案件状态和协调者绑定。遇到新人工关口、权限撤销、方案变化、绑定缺失或业务失败时停止，并在资料卡显示原因。基础设施错误有限重试；人工重试保留已完成步骤。

历史协调者只从明确、唯一的 requester 记录回填。无法确定时显示绑定待修复，不能把当前查看的专业 Assistant 当作协调者。

模拟模式只产生明确标记的模拟确认。外部适配器未配置时显示阻塞，不生成生产执行成功结果。

## 加载行为

插件 Feature 为 `factory-assistant-profile`，共享于现有工厂角色 middleware。两个 manifest 使用 `agent.profile.tabs`。tab 首次选中时加载；已访问的 iframe 在资料卡内缓存。隐藏 tab 接收 `viewActive: false` 后暂停轮询，切回先展示缓存并从下一个周期继续刷新。关闭资料卡或切换 Assistant 时释放全部 iframe、请求、订阅和轮询。

确认弹窗及提交期间保持资料卡打开，禁止切换 tab。Escape 先关闭弹窗；关闭资料卡后恢复入口焦点。
