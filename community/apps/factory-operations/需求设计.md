# 工厂生产异常自主处置与恢复

产品名称可以叫：

> **XpertAI Factory Autopilot｜工厂智能运营与异常恢复中心**

它从工单已经下达到车间之后开始，围绕设备、质量、排产、人员、备件、仓储和交付异常，展示多智能体如何共同让工厂恢复运行。

工信部2025年度中小企业人工智能典型应用场景将生产管控、质量检测、设备维护、采购供应列为重点，并明确提出利用AI动态优化生产计划、基于传感器进行预测性维护、通过视觉质检发现缺陷，形成具备自我调节能力的智能运营体系。([ZJTX Platform][1])

# 一、最适合演示的具体行业

建议使用：

## 汽车零部件、轴承、齿轮或精密机械加工车间

不要选择过于特殊的工厂，可以虚构一个“精密传动零部件工厂”，包含：

* 车削产线
* 磨削产线
* 热处理产线
* 装配产线
* 质量检测中心
* 备件仓库
* 成品仓库

这个行业非常适合演示，是因为设备、工序、工单、质量、维修和交期之间的关系很直观：

```text
设备发生异常
    ↓
哪些工单受到影响
    ↓
哪些在制品可能存在质量风险
    ↓
是否需要停机
    ↓
能不能换到其他设备生产
    ↓
有没有维修人员和备件
    ↓
订单是否会延期
    ↓
如何恢复生产
```

工信部发布的轴承、齿轮和传动部件制造业实践样本已经把“AI排产调度模型与动态生产调整”作为高阶数字化能力；其他行业实践样本也强调综合设备OEE、质量合格率和进度，实现排产、质量和设备管理协同。([ZJTX Platform][2])

# 二、核心演示剧情

## 关键设备故障引发的生产交付危机

这是一个非常适合在大屏上展示的故事。

### 初始状态

虚构工厂正在运行三条产线：

| 产线 | 状态    | 当前任务     |
| -- | ----- | -------- |
| A线 | 高负荷运行 | 加工一批紧急订单 |
| B线 | 运行中   | 普通订单     |
| C线 | 待机维护  | 可作为备用产能  |

某一时刻，A线的关键磨床出现异常：

* 主轴振动持续上升；
* 轴承温度异常；
* 加工尺寸开始接近质量控制边界；
* 该设备上还有三个紧急工单；
* 其中一个订单要求当天完成；
* 已经加工的部分产品可能存在质量风险。

中央数字工厂中的设备由绿色变为橙色，并产生红色脉冲。

大屏立即出现：

```text
严重生产异常

设备：磨削中心 M-07
异常：主轴振动趋势异常
影响工单：3个
可能受影响产品：126件
预计交付风险：2个订单
```

# 三、多智能体如何展开工作

这个场景的关键不是让10个智能体依次执行，而是让多个专业智能体**并行分析、相互提出约束、形成恢复方案并执行**。

```text
设备异常事件
       │
       ▼
异常事件研判 Agent
       │
       ├─────────────┬─────────────┬─────────────┐
       ▼             ▼             ▼             ▼
设备诊断 Agent   质量影响 Agent   订单影响 Agent   备件资源 Agent
       │             │             │             │
       └─────────────┴──────┬──────┴─────────────┘
                            ▼
                    恢复方案规划 Agent
                            │
          ┌─────────────────┼─────────────────┐
          ▼                 ▼                 ▼
    动态排产 Agent      维修执行 Agent      仓储物流 Agent
          │                 │                 │
          └─────────────────┼─────────────────┘
                            ▼
                    运营决策 Agent
                            │
                      人工审批闸门
                            │
                            ▼
                MES / CMMS / WMS / APS
                            │
                            ▼
                  恢复验证与复盘 Agent
```

# 四、建议设置的智能体角色

| 智能体        | 主要职责                   | 使用的数据和工具          |
| ---------- | ---------------------- | ----------------- |
| 异常研判 Agent | 判断异常真实性、严重程度和影响范围      | IoT、设备规则、告警记录     |
| 设备诊断 Agent | 分析故障原因、估算剩余可运行时间       | 设备手册、维修记录、故障知识库   |
| 质量影响 Agent | 判断哪些批次和在制品需要隔离或复检      | QMS、SPC、检测数据、工艺参数 |
| 订单影响 Agent | 计算异常对工单、订单和交期的影响       | MES、ERP、订单优先级     |
| 动态排产 Agent | 在设备、人员、工装和交期约束下重新排产    | APS、MES、优化求解器     |
| 维修 Agent   | 生成维修方案、派发维修工单、匹配维修人员   | CMMS、人员技能、维修SOP   |
| 备件 Agent   | 检查备件库存、替代件和供应商交期       | WMS、ERP、供应商数据     |
| 物流调度 Agent | 调度AGV、在制品、工装和备件运输      | WMS、AGV或物流模拟系统    |
| 运营决策 Agent | 比较不同恢复方案，平衡质量、交期、成本和风险 | 各智能体分析结果          |
| 恢复验证 Agent | 检查设备、质量和产线是否真正恢复       | IoT、MES、QMS       |

# 五、真正体现多智能体的“冲突协商”

如果所有智能体永远给出一致答案，就无法体现多智能体价值。

演示中应该故意制造专业目标之间的冲突。

例如：

### 设备诊断 Agent

> 建议立即停止M-07，预计维修2小时，继续运行可能扩大设备损伤。

### 质量 Agent

> 建议隔离最近90分钟生产的126件产品，并执行追加检测。

### 生产计划 Agent

> 如果单纯停机，订单SO-260831-07将延期3.5小时。

### 动态排产 Agent

> 可以将两道工序切换到B线，但需要更换夹具，准备时间45分钟。

### 备件 Agent

> 所需主轴轴承本地库存1件，备件仓库可在18分钟内送达。

### 成本 Agent

> 切换到B线增加约1800元换线和加班成本，但可避免订单延期。

随后由运营决策 Agent 给出三种方案：

| 方案 | 处理方式              |      交期 |      成本 | 风险          |
| -- | ----------------- | ------: | ------: | ----------- |
| A  | 停机维修，原地等待         | 延迟3.5小时 |      最低 | 交付风险高       |
| B  | 停机维修，同时把紧急工单切换至B线 |     不延期 | 增加1800元 | 推荐          |
| C  | 继续运行至订单完成后再维修     |     不延期 |      较低 | 设备与质量风险不可接受 |

系统推荐方案B，并说明原因：

> 在保障设备安全和产品质量的前提下，方案B可以避免客户订单延期。虽然增加换线成本，但综合损失最低。

老板看到的不是“AI回答了一个问题”，而是：

> **多个专业智能体围绕一个工厂事件完成诊断、协商、决策和执行。**

# 六、系统需要真正执行什么

只输出一份分析报告还不够。演示必须继续向下执行。

运营负责人点击“批准方案B”后，系统自动完成：

```text
1. MES暂停设备M-07当前工单
2. CMMS创建紧急维修工单
3. 指派具备对应技能的维修工程师
4. WMS锁定并出库主轴轴承
5. 调度AGV将备件送到A线
6. APS重新计算生产排程
7. MES将两个紧急工单迁移至B线
8. 创建夹具更换和首件确认任务
9. QMS隔离可能受影响的126件产品
10. 创建追加检测任务
11. 更新订单预计完工时间
12. 持续监控维修和生产恢复进度
```

这才是多智能体流水线相对于传统问答机器人的核心区别：

| 普通AI助手      | 多智能体生产运营系统       |
| ----------- | ---------------- |
| 告诉用户设备可能有问题 | 自动调查设备异常         |
| 给出一段处理建议    | 多部门并行评估影响        |
| 生成维修方案      | 创建并派发维修任务        |
| 提醒可能延期      | 自动重新排产           |
| 需要人工逐个操作系统  | 调用MES、WMS、CMMS执行 |
| 回答结束后任务结束   | 持续监控直到生产恢复       |

工信部面向工业中小企业的管理指南也将智能化调度、全过程生产监控、质量精准追溯、应急响应、供应商风险管理以及仓储配送协同列为相互关联的提升方向。把这些原本分散的能力组织成一个事件驱动的多智能体流水线，是本方案的核心产品化思路。([ZJTX Platform][3])

# 九、建议准备四套异常剧本

## 剧本一：设备故障

关键设备出现异常，系统完成诊断、停机、维修、备件配送和重新排产。

重点展示：

> 多智能体并行分析和自主恢复。

## 剧本二：质量漂移

检测数据连续偏离目标值，但尚未达到不合格界限。

系统自动：

* 判断趋势异常；
* 追溯相关设备、人员、材料和工艺参数；
* 暂停可疑批次；
* 调整工艺；
* 创建首件复检；
* 恢复生产。

重点展示：

> 从“事后发现不良”转向“提前干预”。

## 剧本三：关键物料临时短缺

物料配送没有按时到达，当前工单将在30分钟后停线。

系统自动：

* 检查其他仓库库存；
* 寻找可替代批次；
* 计算转运时间；
* 调整工单顺序；
* 向供应商确认到货时间；
* 保护高优先级订单。

重点展示：

> 仓储、采购、计划和生产协同。

## 剧本四：紧急订单插单

销售突然要求插入一个高优先级订单。

系统自动：

* 分析所有设备和订单负荷；
* 识别可能被影响的订单；
* 生成多种排产方案；
* 计算加班、换线和延期成本；
* 由负责人批准后执行。

重点展示：

> 多目标约束下的智能决策。

# 十、技术实现时的关键原则

## 异常检测不要全部交给大模型

合理分工应该是：

```text
时序算法 / 规则引擎
负责检测设备和质量异常

优化求解器
负责约束排产和资源优化

LLM智能体
负责理解事件、调查证据、协调角色、
解释方案、调用工具和推动流程
```

动态排产可以使用：

* OR-Tools CP-SAT
* 遗传算法
* 约束规划
* 企业已有APS

LLM不应该凭自然语言直接“算出最优排产”。

## 不要直接控制PLC

第一版应让智能体操作：

* MES工单
* CMMS维修单
* WMS出库任务
* QMS隔离任务
* APS排产方案
* 人工审批任务

涉及设备启动、停机或安全联锁时，应由PLC、MES规则或授权人员控制。

## 必须保留证据链

每个智能体结论都应带有：

```text
使用了什么数据
引用了什么规则
调用了什么工具
为什么给出该建议
还有哪些不确定性
谁批准了最终操作
实际执行结果是什么
```
