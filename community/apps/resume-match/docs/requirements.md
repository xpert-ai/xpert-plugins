# 产品与验收说明

## 用户任务

招聘负责人需要对照岗位要求阅读候选人材料，整理有来源的匹配依据、信息缺口与待核实问题，并留存自己的复核结论。当前假设是一份岗位配一份简历；处理频率、耗时与收益需后续实际测量。

AI 生成的分数和文字均为辅助草稿。应用不自动执行录用或淘汰，不发送通知，不连接外部招聘系统。人工可以调整结论后保存。

## 交互与数据

新建界面包含岗位说明、简历和基本信息，提交前检查必填项与长度。记录创建时保存输入快照。等待界面显示当前记录并允许重新分析；结果界面显示四个维度、原文材料、依据与待核实项，人工确认窗口收集结论。历史列表支持重新进入原记录。

`waiting_ai → review → confirmed` 是成功路径；工具可以把未完成分析标记为 `failed`。重新分析只增加同一记录的 attempt 与 revision。服务端使用修订、状态和轮次条件更新，拒绝过时写入和对已确认结果的模型覆盖。

Assistant 负责自由文本理解，业务工具负责受权限约束的读写。综合分数按已声明权重确定性计算；它不是经过统计校准的录用概率。最终判断由人完成。

## 验收

1. 在 Xpert 工作台创建记录，真实 Assistant 读取材料并保存结构化草稿。
2. 修改并确认人工结论，刷新及重新进入后恢复同一记录。
3. 空输入有提示，尚无记录时可以继续创建。
4. 触发一次可解释失败，在原记录重试；旧轮次不能覆盖新轮次。
5. 无法通过其他租户、组织或用户上下文读取或修改记录。

预览 fixture 仅验证交互，不代替上述平台验收。单元测试使用 repository spy；harness 默认模拟数据库与运行上下文，也不能证明真实持久化通过。

## 复用范围

保留原有 resume-match 实体、工作台、Assistant 和构建结构，参考 `smart-maintenance` 与 `procurement-quote-comparison` 的服务、工具与视图分工。复用来源遵循原项目及依赖声明的许可；本插件声明 AGPL-3.0。

本次改动聚焦修订保护、重复写入语义、严格输入校验、可执行测试和 CommonJS 加载兼容，后续验证结果以验证文档为准。

## 范围取舍

先完成一份材料的完整闭环。暂不做 OCR、批量处理、多智能体、统计看板、外部系统与复杂角色管理。基础宿主数据隔离仍然保留。先验证真实平台接入，再投入界面样式完善。
