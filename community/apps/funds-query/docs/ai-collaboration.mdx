## 工具与分工

本项目使用 Codex 辅助开发，候选人确认所选模型为 GPT-6.1 Sol。候选人提出业务目标、选择实现方案、操作实际平台并反馈验收结果。Codex 阅读仓库接口、实现 Python/Vue/TypeScript、补充测试和整理交付。

应用运行时使用 Xpert 中配置的业务模型。该配置与开发工具模型分别管理，具体运行模型以测试平台设置为准。

## 代表性协作过程

### 1 从资金追踪收敛到交易问数

候选人最初考虑多层资金转手追踪，随后提出让 AI 根据标准数据回答业务问题，例如“张三在上个月一共收了多少钱”。需求最终收敛为标准 Excel、自然语言查询、精确统计和证据核对的 MVP。

该决定缩小了数据归因规则的范围，同时使 AI 在理解意图、账户确认和连续追问中有明确作用。Codex 据此实现受限工具与持久化结果。

### 2 明确技术分工

候选人要求 Python + Vue，并接受少量 TypeScript 用于 Xpert 原生插件注册、权限上下文、工具和工作台桥接。实现保留平台的真实执行身份，Python 负责金额和数据保存，Vue 负责业务交互。

### 3 根据实际故障修正上下文处理

用户验收发现，追问会出现等待超时和未确认送达。排查对比了插件已保存问题与平台实际消息、执行记录，定位到原生会话恢复阶段。

修复采用先确认会话就绪、再准备问题和发送的顺序，增加目标线程校验，并通过独立读取上下文处理导航回执丢失。对应测试覆盖回执丢失、超时草稿保留和历史响应乱序。

### 4 根据用户反馈调整交付方式

候选人指出命令部署对用户不友好。Codex 核对平台的压缩包上传入口，将交付拆分为上传安装包和开发源码包，并随包提供固定版本纯 Python 依赖、自动解释器检查和图形配置项。

页面重启在源码模式下需要本地启动器配合。一次“任意正常退出后自动重启”的尝试被自动审批拒绝，之后改为仅接受平台通过私有进程通道发出的明确重启通知。相应回归区分正常退出、用户停止和平台重启。

## 验证方式

开发中分开使用 Python 规则测试、原生接口及安装包测试、浏览器夹具测试、生命周期检查和真实 Xpert 验收。候选人多次操作安装、导入和问数，并反馈实际错误和成功结果。

夹具测试用于重复执行条件继承、错误恢复和时序场景。真实模型调用及用户验收用于核对实际使用流程，相关结果分别记录在验证文档中。

## 面试交流准备

候选人应结合上述实际过程说明自己的产品判断、接受或调整 AI 建议的理由，以及如何通过独立预期金额和原始交易行检查 AI 结果。具体使用体验和个人收获由候选人按真实经历口头说明。
