## 产品与范围

产品是「拍照受理」，面向设施服务台的受理人。主流程：拍照建单 → 助手调用视觉模型给出建议类别 → 受理人确认或改正 → 保存。质量环节：在已确认的受理单上对比当前提示词与新提示词，由人决定是否采用；采用后的提示词用于之后的识别。

包为 `@community/apps-photo-intake`，版本 `0.4.0`，tenant 级插件，数据命名空间 `photo_intake`。首版固定一个默认模型，不接 RAG、向量库、LLM 裁判或自动发布，不派单。

## 接下来按顺序处理

- [ ] **P1：区分提供商限流。** 平台验收中逐项连续调用触发了 HTTP 429，现在和其他错误一样记为“模型调用失败”。可以在共享契约里增加限流这一失败类别，界面提示稍后重试；是否在验收运行里加间隔或退避需要先确认。
- [ ] **P2：长边超过 1280 的真实照片。** 平台上用的是代码绘制的小图，压缩分支在模拟宿主测试里覆盖；用一张大照片在平台上确认预览、保存尺寸和刷新恢复。
- [ ] **P2：少量真实照片。** 由用户确认照片来源和类别后做一次验收，记录输出与费用口径。示意图上的命中不能当作真实照片准确率。
- [ ] **P3：准备 PR。** 审查相对插件 main 基线的差异、依赖变更和材料里的敏感信息；`package.json` 的改动在 Windows 上会让 pre-commit 的依赖检查因找不到 `pnpm` 而失败，需在能运行该检查的环境提交，不要跳过钩子。PR 目标 `xpert-ai/xpert-plugins:main`，描述附产品说明、验证结果、两个基线 SHA 和实际测试的版本。
