# 五分钟演示提纲

目标：说明设施服务台的受理人如何用一张照片建单、让助手给出类别建议、自己确认，以及改提示词之前怎样在已确认的受理单上先验一遍。

## 演示前

- 确认本地 Xpert 已启动、插件 0.4.0 已加载、助手已从模板更新并发布；步骤见 [README](../README.md)。
- 当前组织的默认主模型需要支持图片输入。
- 准备两三张自己拍的、没有敏感信息的照片，其中一张问题明确（例如滴水的水龙头），一张看不出问题。
- 现场每识别一张受理单是一次图片模型调用；一次验收是“样本数 × 2”次，另有助手编排调用。

## 展示顺序

| 时间 | 操作 | 需要讲清楚的内容 |
|---|---|---|
| 0:00–0:40 | 打开“受理”，上传照片、写一句描述、保存 | 用户是受理人，要给每张照片定类别。保存不调用模型；描述不会发给模型。 |
| 0:40–1:40 | 在打开的受理单里点“让助手识别”，切到对话看工具调用，再回到受理单 | 助手调用一次 `photo_intake_analyze_case`，服务端把照片交给视觉模型。助手看不到照片，也没有确认类别的工具。受理单上显示建议、理由、模型和提示词来源。 |
| 1:40–2:20 | 改一下类别或保持建议，点“确认类别” | 类别由人定。确认后定稿；列表里能看到助手建议和确认类别是否一致。 |
| 2:20–3:00 | 展示一张识别失败的受理单，点“重新识别” | 失败原因被保存，不会编一个类别出来。可以重试，也可以不等模型直接确认。 |
| 3:00–4:10 | 到“新建验收”，A 是当前提示词，B 填候选，勾选已确认的受理单，运行并查看对比 | 样本只能是人确认过的受理单，参考答案就是确认的类别。打开样本看原始输出和尝试历史。 |
| 4:10–4:40 | 保存结论，回到“受理”看当前提示词来源 | 采用 A 或 B 后，之后的识别使用该版；打平或都不采用则不变。不部署、不换模型。 |
| 4:40–5:00 | 刷新页面；展示画布上的助手模板与中间件 | 受理单、建议、确认和验收都从数据库恢复。 |

不要预先承诺哪一版提示词会胜出；现场结果是什么就讲什么。

## 三个可解释的取舍

- **为什么类别必须由人确认？** 类别决定后续找谁处理，错了有成本。模型的建议附带理由和来源供人判断，助手没有代为确认的工具。
- **为什么验收样本只用已确认的受理单？** 这样参考答案来自受理人的实际判断，不需要另外维护一套标注；也让日常受理自然积累出回归样本。
- **为什么首版不接 RAG、不让模型给自己打分？** 分类只需要照片和类别定义，没有要检索的外部知识；类别可以按确认结果确定性比对，采用与否留给人。

## 如实说明的边界

0.4.0 的受理流程在真实平台上的验证记录见 README“验证结果”；没有记录的项目按“未验证”说明。已确认的受理单不能撤销。示意图或少量照片上的结果不能说明真实照片的准确率。模型的实际费用没有取得，只有提供商返回的 token 用量。
