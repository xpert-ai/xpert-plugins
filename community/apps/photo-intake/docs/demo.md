# 五分钟演示提纲

目标：说明维护图片分类助手的人如何依据固定样本、原始输出和人工复核，决定是否采用一次提示词修改。设施问题分类只是具体测试任务。

## 演示前

- 确认本地 Xpert 已启动、插件 0.3.0 已加载、助手模板已发布；构建和安装步骤见 [README](../README.md)。
- 先使用已保存的真实运行记录演示查看与恢复，不需要重新调用模型。记录仅存在于执行验收的本地数据库；其他环境需按 README 自行创建，截图不会导入数据。
- 若现场运行新验收，准备一张自己确认标签的照片，选择默认 A/B，预期两次图片模型调用，另有助手编排调用。先确认该环境页面上传可用。

## 展示顺序

| 时间 | 操作 | 需要讲清楚的内容 |
|---|---|---|
| 0:00–0:40 | 展示样本库、新建验收入口 | 目标用户是维护分类助手的开发者或测试人员。原先逐张试图并手工抄表；现在固定图片、标签、提示词和模型配置，保存一次可复查的验收。 |
| 0:40–1:40 | 在验收记录打开“平台验收 2026-11-14 · 几何图负样本”，查看固定配置和对比表 | 这是一张合成负样本的真实模型运行，两版均为 `unclear`。它证明流程可运行，不能证明哪版在真实照片上更好。 |
| 1:40–2:30 | 点击样本名称，查看图片、原始输出、用量和测试评审 | 被测模型只看本版提示词、类别定义、输出约束和图片。人工参考标签不进入模型请求；服务端按标签评分，人工评审不改写该分数。 |
| 2:30–3:10 | 刷新并重新进入验收记录 | 结果、原始输出、评审和采用决定保存在数据库。此次已有决定标为自动化验收，不冒充业务专家评审。 |
| 3:10–4:10 | 打开“异常流程验收 · 损坏图片与重试（非效果比较）”并查看样本详情 | 故意损坏的图片导致两版各失败两次，历史没有被覆盖；不能采纳仍有失败项的版本。展示的是已经发生的失败与重试，不重新点击或声称已恢复成功。 |
| 4:10–5:00 | 展示助手画布、中间件和对话中的工具记录 | 助手逐项组织模型运行并解释结果；人通过工作台确认标签、安排重试和记录采用决定。保存决定不会自动上线提示词。 |

已定稿记录不能继续修改。需要现场演示创建、运行和保存新的评审时，新建一次验收，等待真实结果后再判断；不要预先承诺某版胜出。

## 三个可解释的取舍

- **为什么首版不接 RAG？** 当前问题是比较固定图片分类任务上的两版提示词，没有需要检索的外部知识来源。类别定义直接随快照保存。
- **为什么不让模型给自己打分？** 类别可按人工参考标签确定性评分；证据质量和最终采用理由留给人复核，避免把另一个模型的偏好当作标准答案。
- **为什么只比较一个模型？** 首版固定默认模型，先控制提示词这一变量；跨模型比较与自动发布留作后续需求。

## 如实说明的剩余边界

实际 Xpert/IAB 页面选文件与压缩尚未完成验收，本次平台样本经真实 View API 上传；模拟宿主浏览器已验证文件选择事件、解码缩放和保存尺寸。真实照片准确率、提供商故障恢复后的成功重试尚未验证。模型实际美元费用未取得，已记录返回的 token 用量。
