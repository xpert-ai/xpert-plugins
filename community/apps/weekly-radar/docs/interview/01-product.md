# 01 · 产品说明（周报风险雷达）

## 1. 一句话

把这周真实发生的事情沉淀为可追踪条目，用**可复算的规则**扫出未闭环状态，生成一份数字不会漂移的周报。

## 2. 用户 / 痛点 / 原方式 vs 新方式

| 项 | 内容 |
|---|---|
| 用户 | 带团队的管理者、项目负责人、需要每周向上汇报的人 |
| 痛点 | 周报里最难写的不是"干了什么"，而是"上周哪些没闭环、哪些结论还没人确认、哪些结论其实已失败不可信"；这些信息人不会主动写，风险总在最后一刻才被问出来 |
| 原方式 | 翻聊天记录 + 凭记忆拼周报；风险靠临场回想；上周说过的事下周没人再提 |
| 新方式 | 随手沉淀条目（带状态 + 证据指针）→ 规则扫出未闭环 → 服务端重算周报数字与风险行 |

## 3. 核心主张：模型只写叙述，规则负责判定

| 环节 | 由谁做 | 为什么 |
|---|---|---|
| 从用户的话里抽取条目事实 | 宿主助手模型 | 生成式判断，规则做不到 |
| 判定什么算风险、几级 | **服务端规则引擎**（纯函数） | 可复算、可审计、可背责 |
| 周报中的数字与风险行 | **服务端重算** | 模型不能编造或改写数字，避免周报与事实漂移 |
| 周报叙述（要点 / 下周动作） | 宿主助手模型 | 措辞是语言活，交给模型 |

## 4. 范围与取舍

**做**：条目沉淀、5 条风险规则、周报组装与人工确认归档、工作台三区视图。

**不做（刻意）**：会议转写（官方 Meetings）、通用看板（官方 Live Dashboard）、文档美化（官方 Office）、IM 接入、OKR、协作评论、绩效、外部系统同步。

**取舍理由**：仓库里已有 40+ 个"喂材料 → AI 抽取 → 人工确认"的工作台（824 个 PR 全量统计），再做一个抽取型工作台没有增量；本插件只保留"未闭环状态"这一个纵切面，并把判定权从模型收回到规则。

## 5. 完成标准（对齐最低范围）

1. 明确用户（带团队的管理者）
2. 一条核心流程（沉淀 → 扫描 → 生成 → 确认归档）
3. 可操作界面（工作台三区）
4. 真实 AI 处理（助手抽取条目与撰写叙述）
5. 保存与恢复（条目与周报落库，刷新可回看）
6. 失败重试且不产生重复（`operationId` 唯一索引 + 绝对值更新）
