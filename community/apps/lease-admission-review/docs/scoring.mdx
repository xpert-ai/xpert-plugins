规则版本：`admission-three-indicators-v1`。统一基准日与管理层范围是本插件功能验证约定，不表示覆盖全部业务政策。

| 指标 | 输入区间 | 得分 |
| --- | --- | --- |
| 管理层近一年离职次数 | 0 / 1–2 / ≥3 | 2 / 1 / 0 |
| 股票质押比例 | ≤40% / (40%,50%] / (50%,60%] / (60%,70%] / >70% | 5 / 4 / 3 / 1 / 0 |
| 资产负债率 | 同上五档 | 8 / 6 / 4 / 2 / 0 |

资产负债率严格大于80%命中单条负面规则；80%未命中。有效资产负债率可独立显示该结果；数据无效则为“数据不足”。输出仅为选定指标试算，不能作为完整评级或准入审批。

## 人工核验约定

- 统计窗口为基准日前一年同日之后至基准日（含）；闰日按上一年二月末处理。例如2024-02-29对应(2023-02-28,2024-02-29]。
- 覆盖董事长、CEO、总经理、副总经理、财务总监。人工确认次数及材料覆盖范围；未提及不等于零。
- 两比例报告日都必须与基准日一致。质押口径固定为控股股东及一致行动人的质押数占其持股数，不能把模糊“公司质押比例”直接采用。
- 只接受明确披露的百分比。值含`%`或单位为`%`、`百分比`、`percent`；最多四位小数，按一万分之一个百分点的整数比较，不先四舍五入。质押范围0–100%，资产负债率可超过100%。不做分子分母计算。
- 人工输入与各指标原文引用关联。服务端验证引用是原文子串；人工勾选确认引用支持所填日期、次数与口径。子串匹配不能自动证明语义正确。

## 草稿、试算与确认

`save_draft`允许尚未完成的输入，增加版本号及事件，保留AI候选不变。`preview_score`只返回服务端计算结果；修改任一表单输入后旧试算失效。`confirm`重新完整验证并计算，在事务中保存人工值、草稿、规则版本、逐项依据、总分、负面规则和事件，拒绝客户端分数。

修改AI字段须填写原因；修改已保存且可完整试算的人工输入，也须在最终确认时填写原因。事件快照保存旧值，不能通过再次保存草稿绕过该要求。首次填写人工评分口径不自动视为对AI字段的修改。

缺失、冲突、不适用、日期或口径不符时仅保存草稿，无完整总分，不允许确认。缺少依据时新建包含补充资料的案例，本轮不编辑原文、不补录外部依据、不覆盖历史确认。旧确认显示“历史核验记录，未评分”，不自动重算。

刷新与重新进入从宿主数据库恢复人工草稿，AI候选独立保留。后台通知不覆盖未保存编辑；未保存内容在整页刷新后会丢失，应先保存草稿。所有访问绑定宿主租户、组织、用户及助手。

## 合成样例

统一基准日2025-12-31，统计窗口(2024-12-31,2025-12-31]。

正常材料：星河设备管理层包括董事长、CEO、总经理、副总经理、财务总监，窗口内全部上述职位合计离职0次，资料覆盖全部职位与期间。2025-12-31控股股东及一致行动人的质押数占其持股数为40%；同日披露资产负债率为40%。预期2+5+8=15，负面规则未命中。人工误填离职1次时为14；核对原文改回0并说明原因后为15。

缺失材料：仅披露同日资产负债率50%，未披露管理层和质押情况。预期无完整总分，负面规则未命中，允许保存草稿。

负面规则材料：正常材料中的资产负债率改为80.0001%。预期2+5+0=7，单条负面规则命中。80%同样得7分，但不命中负面规则。

## 从0.1升级

案例表增加可空JSONB `reviewDraft`、`assessment`，事件表复用原快照列，无新表。已有安装在加载0.2前，于具有宿主DB环境的API容器内运行：

```sh
node /path/to/plugin/scripts/upgrade-scoring.cjs
```

脚本只执行`ADD COLUMN IF NOT EXISTS`，可重复运行，不开启全局同步、不清库。首次安装沿用宿主实体注册建表路径；升级失败不要加载新版本，先检查数据库权限及表存在性。回退代码时保留新增可空列及已有快照，不能删除业务数据。
