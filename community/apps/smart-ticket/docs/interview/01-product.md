# 产品说明与范围

整理日期：2026-11-10  
项目名称：智能客诉工单工作台（Smart Ticket Agentic App）  
插件包名：`@community/apps-smart-ticket`  
当前版本：`0.1.0`

---

## 一、 目标用户、原有痛点与核心价值

### 1. 目标用户
* **一线客服人员**：每天处理大量客户咨询与投诉，需要快速提炼核心诉求并拟定专业安抚答复。
* **客服组长 / 售后技术支持专员**：需要针对高优先级（P0/P1）客诉进行人工复核、分类调整与工单归档流转。
* **产品与运营团队**：根据已归档客诉的分类与严重度，回溯产品缺陷与高频用户建议。

### 2. 原有工作方式与痛点
* **客诉文本冗长混乱**：客户在情绪激动时往往夹杂大量情绪化发泄词汇，核心问题（如账单扣款失败、系统崩溃）分散在各处，客服人工阅读提取耗时。
* **话术规范度与情绪安抚不足**：新手客服面对愤怒客户容易措辞不当，缺少标准化、有同理心的安抚模版。
* **工具脱节与信息孤岛**：传统纯聊天 Bot 仅能答复，无法直接将对话中的客诉结构化为工单；而传统工单系统又缺乏 AI 实时提取与人机协同审核（Human-in-the-loop）的流转界面。
* **网络或外部服务异常导致丢单**：大模型调用偶尔因网络抖动超时，若无重试机制，已输入的客诉内容容易直接丢失。

### 3. 核心改善与产品价值
智能客诉工单工作台为 Xpert 平台提供了一个**从输入、AI 分析、工作台核对修改到确认归档持久化**的完整业务闭环：
1. **自动提炼意图与情绪**：一键识别客诉类别（账单、技术、安全、建议等）、紧急度（P0-P3）及客户情绪极性。
2. **生成高同理心回复草稿**：AI 自动拟定专业、严谨且符合服务标准的建议答复。
3. **可交互的双栏工作台**：在独立的 Remote Component 视图中提供工单列表、详情编辑卡片，支持客服直接在工作台中微调回复内容。
4. **一键确认并持久化落库**：核对无误后点击“确认归档”，数据保存至插件数据库，页面刷新或重新进入应用均可完整恢复。
5. **健壮的异常与重试闭环**：内置输入长度校验与超时模拟机制，遇到故障提供一键重试且不产生重复脏数据。

## 二、 完整业务流程

```text
[ 用户 / 客服输入 ]
       │
       ▼ (1. 粘贴客户原始反馈，点击“AI智能分析”)
[ SmartTicketService / Tool: ticket_analyze_and_draft ]
       │
       ├─► 校验内容长度 (若 <10 字符，拦截并提示 CONTENT_TOO_SHORT)
       ├─► 模拟异常排查 (若触发超时，展示异常并保留输入，支持一键重试)
       ├─► 智能算法提炼意图、情绪极性、P0-P3紧急度、问题摘要与回复草稿
       │
       ▼ (2. 自动生成待审核工单草稿，状态: pending_review)
[ 交互式工作台 (Remote Component Workbench) ]
       │
       ├─► 左栏：工单卡片列表（分类标签、优先级徽章、状态过滤器）
       ├─► 右栏：工单详情检查器（标题/分类/优先级/情绪指示器）
       │
       ▼ (3. 客服人工核验与微调回复建议 - Human-in-the-loop)
[ 客服在工作台中微调措辞，点击“确认归档保存” ]
       │
       ▼ (4. Action: confirm_ticket / Tool: ticket_confirm_and_save)
[ 数据库持久化落库 (TypeORM plugin_smart_ticket_record) ]
       │
       ├─► 状态流转: pending_review ──► confirmed
       ├─► 递增 revision 版本号，记录更新时间
       │
       ▼ (5. 数据恢复与协同扩展)
[ 页面刷新 / 重新进入工作台：历史工单完整恢复；可点击“引用至聊天”继续深入讨论 ]
```

## 三、 功能取舍与设计思考

| 模块 / 能力 | 当前设计与实现状态 | 取舍原因与设计决策 |
| :--- | :--- | :--- |
| **客诉分类与情绪判定** | 已实现：精准提取 5 大业务分类与 P0-P3 四级优先级 | 优先满足最核心的分类与分流诉求，不堆砌复杂的自研 NLP 模型，保证轻量且可靠 |
| **专业安抚回复拟定** | 已实现：按分类与情绪动态生成标准化安抚方案 | 给予客服现成的高质量回复初稿，大幅降低客服沟通成本 |
| **交互式工作台** | 已实现：基于 React 的 iframe 隔离架构双栏工作台 | 相比单纯的聊天框，独立工作台视图能清晰呈现工单全貌与编辑控件 |
| **人工审核与确认** | 已实现：支持编辑标题、分类、优先级及回复内容后归档 | 严格遵循 Human-in-the-loop 原则，避免 AI 幻觉导致直接向客户发送不当回复 |
| **结果保存与恢复** | 已实现：基于 TypeORM 多租户隔离持久化存储 | 刷新或重登后数据不丢失，满足实际业务系统持久化要求 |
| **失败与重试机制** | 已实现：提供超时模拟按钮与一键重试能力 | 演示真实生产环境下网络异常后的容灾恢复路径，重试幂等不产生脏数据 |
| **外部三方 CRM 系统直连** | 暂未包含（作为后续扩展） | 题目建议 2–6 小时聚焦小闭环，避免因三方鉴权与网络不可控因素阻塞主流程 |
| **复杂多角色多智能体流水线** | 暂未包含（按需选用） | 单一专精智能体配合中间件与工作台已完整闭环，无需引入额外复杂度 |
