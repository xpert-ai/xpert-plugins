## 发布流程

平台数字专家也可直接添加 **SAIC Doris 中间件**，无需经过本节的外部发布流程。中间件与 MCP 共用工具名称、输入契约和业务逻辑，连接分别配置。

1. 安装配套的 MySQL/Doris 数据源插件和 SAIC Doris 工具插件。
2. 初始化插件的原生 MCP 资源，或使用已有 Publication。需要新增独立连接时，可通过下述宿主原有接口创建租户／组织范围的 SAIC 工具集，并执行能力发现。
3. 在 **MCP 管理** 选中服务，在 **配置连接** 页签编辑当前服务已绑定的连接，选择平台数据源或手填连接后保存。新建的 Publication 需要先在能力页绑定该来源的 24 个工具及 schema 资源；保持原工具名。
4. 通过平台为该 Publication 配置凭据和访问范围，复制平台显示的 Streamable HTTP 地址。
5. 在 WorkBuddy 或其他支持 Streamable HTTP 的 MCP 客户端中填入该地址和平台提供的认证方式，执行 `ping` 和 `schema://saic/config-tables` 验证数据库连接及现有表。

插件不创建外部监听端口，不自建 MCP 服务，不生成访问密钥。多个数据源需要独立入口时，创建多个工具集及对应 Publication；不要通过工具参数传入连接标识。

## 服务内的配置连接页签

支持插件页签的宿主直接渲染 Provider 的 `configSchema`，SAIC 声明页签名为 **配置连接**。打开时回显已有连接，无需重新选择提供程序。数据源下拉、条件显示和密码控件来自同一 schema。密码脱敏显示，保持不变会保留原值；替换内容后保存会更新密码。

保存只更新绑定连接，不重建服务、不改变 MCP 地址和访问密钥。如果其他管理员已修改配置，保存会提示冲突，点击 **重新加载配置** 后再编辑。一个服务绑定多个插件来源时，各来源分别显示页签；同一个连接被多个 Publication 共用时，修改会作用于所有使用它的服务。共享租户服务需切换到所属租户范围编辑连接。

没有配置字段、也没有声明其他扩展视图的插件只显示默认页签。普通工具集目录的卡片可以保留，不需要通过卡片配置。

## 宿主原有连接管理接口

管理员使用有效的平台登录凭据及当前租户／组织请求头调用以下接口。平台登录凭据与外部 MCP 调用密钥不同；不要把数据库密码或登录令牌放入聊天或命令历史。

`POST /api/xpert-toolset/builtin-provider/saic_doris/instance`：

```json
{
  "name": "SAIC Doris connection",
  "workspaceId": null,
  "credentials": {
    "mode": "platform",
    "dataSourceId": "REPLACE_WITH_AUTHORIZED_DATASOURCE_ID"
  }
}
```

手填模式用 [连接配置](/configuration) 中的对象替换 `credentials`。更新现有连接时在请求体加入该连接的 `id`；保留原 ID，不删除连接或 Publication。保存后对返回的工具集 ID 调用 `POST /api/mcp-capability-catalog/toolsets/:toolsetId/discover`，再从 MCP 管理页选择其能力。调用 `ping` 才能确认数据库连接正常。

未支持插件页签的旧宿主使用上述接口配置连接，不提供独立的“配置工具集连接”弹窗。插件详情的启用操作用于初始化原生 MCP 资源，不负责填写连接。旧宿主重新初始化托管工具集可能清空该实例凭据，配置完成后不要将重新初始化作为连接测试；需要时通过上面的接口恢复配置。

## 客户端配置示意

以下是常见 MCP 配置形状。客户端版本可能使用不同字段，以该客户端的 HTTP MCP 配置界面为准：

```json
{
  "mcpServers": {
    "saic-doris": {
      "url": "REPLACE_WITH_PUBLICATION_STREAMABLE_HTTP_URL",
      "headers": { "Authorization": "Bearer REPLACE_WITH_PUBLICATION_CREDENTIAL" }
    }
  }
}
```

凭据必须允许 `tools:list/call` 和 `resources:list/read`。工具默认在鉴权后直接执行，包括写工具；管理员的拒绝或审批策略仍可覆盖插件默认值。写工具明确标记为写入、有副作用、非幂等，客户端应按此处理重试。

## 结果

工具返回兼容原接口的 JSON 文本 `content[0].text`，同时提供同一对象的 `structuredContent`。业务校验失败仍返回普通 `{ "error": "..." }` 对象；配置、权限、连接、取消等执行失败由原生工具执行层转换为 MCP 错误。

资源 URI 保持 `schema://saic/config-tables`，MIME 类型为 `application/json`，文本内容是六张允许表的结构数组。资源与工具使用相同工具集连接和权限上下文。

## 接入验收

依次执行 initialize、tools/list、resources/list、resources/read、ping，再用本机隔离数据调用 `upsert_owners`。确认文本 JSON 与结构化结果相同、返回 24 个工具、工具 schema 不含连接密码。另需在真实宿主确认管理员策略覆盖、跨组织拒绝和资源权限；本地协议替身不替代这些验收。
