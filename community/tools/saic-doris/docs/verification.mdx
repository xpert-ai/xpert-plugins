## 安装与构建

在仓库根目录执行。community 工作区通过 packageManager 选择其 pnpm 版本；该工作区已包含配套的 MySQL 插件路径，以便从正式包入口解析依赖。

使用包声明的已发布 SDK `3.21.0` 构建；无需链接宿主 SDK。构建检查还会验证原生资源清单已纳入分发包。见[兼容说明](/compatibility)。

```bash
cd community
pnpm install --filter @xpert-ai/plugin-saic-doris...
pnpm --filter @xpert-ai/plugin-mysql build
pnpm --filter @xpert-ai/plugin-saic-doris build
pnpm --filter @xpert-ai/plugin-mysql typecheck
pnpm --filter @xpert-ai/plugin-saic-doris typecheck
cd ..
node --test xpertai/databases/mysql/tests/*.test.mjs
node --test community/tools/saic-doris/tests/*.test.mjs
```

Python 契约对照测试需要 python3。测试使用从提供的源接口提取的离线 oracle，只保留业务函数、常量和测试替身；没有客户连接信息、真实连接或 MCP 启动代码。

SAIC 的 build 会先构建 MySQL 插件，再从其公开 Doris 入口打包共享实现。宿主共享的 SDK、Nest 和 Zod 保持外置，避免产生重复容器；运行依赖只使用 npm 能解析的版本。`scripts/verify-dist.mjs` 检查打包入口、Doris 工厂和 Nest 注入元数据，防止本地工作区安装回归。

配套发版 changeset 位于 community 工作区，涵盖两个包，确保版本更新时同时更新 workspace 和 peer 依赖。先发布带公开 Doris 工厂的驱动，再发布 SAIC 插件；平台模式需要配套的新驱动。不自动执行 version、publish、Git 提交或 PR 操作。

## 生命周期

按仓库 plugin-dev-harness/README.md 构建 harness 后执行：

```bash
node plugin-dev-harness/dist/index.js --workspace ./xpertai --plugin @xpert-ai/plugin-mysql
node plugin-dev-harness/dist/index.js --workspace ./community --plugin @xpert-ai/plugin-saic-doris
```

harness 验证 dist 包入口、Nest 注入和生命周期。它提供 Runtime Capability 等替身，不证明真实宿主权限或业务数据库可用。

## 文档

```bash
cd community/tools/saic-doris/docs
mint validate
mint broken-links
```

文档使用 mint new 的结构，不需要启动浏览器或开发服务器。

## 本机宿主与浏览器验收

2026-10-16 在用户授权的本机 Xpert 完成两个 0.1.0 本地构建的浏览器安装，以及平台 Doris 数据源连接测试。经用户批准补齐宿主原生初始化、独立连接管理和 MCP 用户权限上下文后，在浏览器分别创建手填和平台连接，绑定到两个独立 Publication，每个暴露 24 个工具和 1 个资源。配置表单保留条件显示、数据源下拉和密码字段。

两个 Publication 分别通过真实 HTTP MCP initialize、24 工具发现、六表 schema 资源读取及全部 24 工具调用，写入仅使用上述隔离库。每次工具结果的 JSON 文本与 structuredContent 一致；相同只读查询在两种连接模式下结果一致。重复主键返回业务错误，凭据表查询、多语句和自由写 SQL 被拒绝。无凭据与使用另一个 Publication 的密钥均返回 HTTP 401。浏览器内置就绪检查均显示 25 项能力已就绪。

平台模式保留现有数据源权限检查：宿主按当前用户加载真实角色权限，未授予额外权限。回归测试覆盖角色权限撤销后下一次调用失去权限；该测试不等于在真实账号上修改权限。宿主数据源授权或连接失效不会自动切换到手填模式。

浏览器将隔离测试 Publication 的 create_task 临时设为“禁止调用”后，MCP 返回工具不可用，查询确认没有写入记录；恢复原来的“直接允许”后，相同请求成功。该结果验证管理员禁止策略可以覆盖插件默认允许策略。
