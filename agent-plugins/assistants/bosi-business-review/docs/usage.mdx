## 管理员准备

1. 在 Xpert 安装并启用 `@xpert-ai/plugin-live-dashboard` 和
   `@xpert-ai/plugin-analytics-data-xpert`。配置正常可用的模型、文件沙箱与
   Data Xpert Integration；密钥只填写到系统连接配置中。
2. 通过标准 Agent Plugins 的 ZIP 或 Git 导入 `bosi-business-review`，检查
   模板/技能诊断，发布资源包以供模板目录使用，再把插件加入目标 AI Workspace。
3. 从 Assistant 模板目录选择需要的 Bosi 岗位模板。11 个模板均为可选项，
   不要一次性为客户创建所有角色。选择模型并完成依赖预检，再创建并发布实例。
4. Data Xpert 中使用“自定义助手”的**绑定已有 Assistant**路径，选择同一个
   AI Workspace 及上一步已发布的实例。平台会核对实例所属空间和发布状态。
   配置业务领域、可用资源和使用人群；语义模型的业务领域需符合资源绑定要求。
5. 配置源系统的只读访问、行级或组织范围授权。必要时为不同部门建立不同
   实例。不要把另一个助手的 ID、分析定义或资源授权复制过来作为绕过方式。

Agent Plugin 模板首先出现在 Xpert 的通用模板目录。当前 Data Xpert 内置
“业务模板”选择器走独立的远程模板过滤逻辑；本套件使用上面的已有实例绑定
路径，不把“自动出现在该选择器”描述为已实现。这里不新增 Project View。

发布 Assistant 是让用户可以使用该实例；这不等于发布它制作的任何看板。

## 用户第一次提问

1. 在 Data Xpert 打开已配置的岗位助手。
2. 在 ChatKit 选择或创建项目。Live Dashboard 与 ChatKit 使用同一个项目，
   当前项目内可以保存多个看板。
3. 点一个简短业务开场提示，或直接提出问题。短标签背后保留完整分析指令。
4. 助手检查授权数据、范围和口径，必要时只追问会改变结论的信息。
5. 需要看板时保存草稿并给出真实成果卡片。用户打开看板，检查筛选、指标、
   明细、币种和数据范围。正式发布仍通过 Live Dashboard 的正常发布流程。

## 同一个角色可以做很多看板

销售经理可以问客户结构、商品贡献、订单趋势，也可在有授权时分析回款。
采购经理可以按供应商、品类、合同或采购组织分析。不存在“一主题一助手”
或“BW 一个助手、OData 一个助手”的强制拆分。

所有用户本次指定的源、公司、期间和交付形式均优先于岗位默认提示。仅请求
分析时，不必制作看板；缺少数据时，也不会自行换用样例数据。

## 三类数据的提问示例

**BW XMLA**：

> 使用已授权的销售语义模型，分析指定销售组织上个已结账月与前月的变化，
> 重点核对销售额、销售成本和客户贡献，制作一个看板草稿。

**SAP OData**：

> 使用当前可访问的采购订单资源，分析这些采购组织的未完成订单；先确认
> 分页是否完整、交付字段是否存在，不要把第一页金额当成全部支出。

**数据库**：

> 使用我指定的订单数据模型，分析本季度各区域的订单变化。确认订单与订单
> 行的粒度、取消状态和币种，展示可验证的趋势与明细。

## 每月经营会议

先明确报告范围、已结账期间、比较期间及币种。助手从实际覆盖的主题中探索
重大变化，并记录来源、计算口径和重要限制。看板修订固定的是定义，实时
绑定仍可能返回更新的数据；如需会议留档，应保存带截止时点的证据和导出，
不能把修订号当成财务数据快照。

默认没有定时任务。只有用户明确要求并指定项目、时区和报告范围后，才另行
配置平台例行任务；不要在安装套件时自动启用。

## 升级

导入新版本包后，在既有 Assistant 的设置中使用“从模板更新”，检查本地
修改冲突、依赖就绪状态并按平台流程发布。不要反复从向导新建同名实例。
升级岗位指令不应改变客户的数据授权、已有项目或看板内容。
